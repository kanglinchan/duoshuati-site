# 移位与旋转：一条指令搞定乘除法，加密算法也在用它

上一课我们解开了负数之谜——补码。这一课回到指令本身，一口气拿下五个位操作指令：`LSL`、`LSR`、`ASR`、`ROR`、`RRX`。

先看一个朴素的需求：想把寄存器里的数乘以 2，怎么办？用 `MUL`？当然可以，但这像为了钉一颗钉子搬出整台冲床。硬件里藏着一条更快的捷径——把整条比特队列往左挪一格，右端空位补 0，数值就自动翻倍了。

### 四条路径，一个分水岭

![四种移位操作总览](../images/chapters/fig-shift-ops.png)

五条指令的区别全在一个问题上：移动之后，空出来的位置填什么？LSL 在右端补 0，LSR 在左端补 0，ASR 在左端补符号位，ROR 干脆不补——让掉出去的比特绕一圈回来。RRX 更特别，它把 CPSR 里的 C 标志也拉进旋转队伍。

移位还有两种写法。一种是独立指令 `lsl r0, r1, #2`；另一种是"嵌入式位移"，顺手挂在别的指令后面：

    mov r1, r0, lsl #2    @ R1 = R0 左移 2 位
    add r2, r3, r4, lsl #1 @ R2 = R3 + (R4 × 2)

第二种是 ARM 的独门绝技：ALU 前面有个桶形移位器（barrel shifter），第二个源操作数进 ALU 之前可以先被移一程，不多花一个时钟周期。

### LSL：移一位就是 ×2

`LSL`（逻辑左移）：所有比特向左移动 n 位，右端空位补 0，左端被挤出去的比特丢弃。

![LSL 逻辑左移](../images/chapters/fig-lsl-multiply.png)

40 变成 80，再变成 160——每左移一位，数值恰好翻倍。二进制里每一位的权重都是右边的 2 倍，整体往左挪一格，等于每个比特都升了一级。左移 n 位就是乘以 2^n。

    mov r0, #40        @ R0 = 40
    lsl r0, r0, #1     @ R0 = 80（40 × 2）
    lsl r0, r0, #2     @ R0 = 320（80 × 4）

> **易错点：** "乘以 2"有个前提——高位没有被移出去。如果左移把一个 1 挤出了最高位，那一位就丢了，结果不再等于乘 2。顺带一提，最后被挤出的那一比特会被送进 C 标志。

在性能敏感的嵌入式代码里，凡是乘以 2 的幂的地方，编译器几乎都会把 `MUL` 换成 `LSL`——移位只要一个周期。

### LSR：移一位就是 ÷2

`LSR`（逻辑右移）是 LSL 的镜像：所有比特向右移动 n 位，左端空位补 0。

    mov r0, #40        @ R0 = 40
    lsr r0, r0, #1     @ R0 = 20（40 ÷ 2）
    lsr r0, r0, #1     @ R0 = 10（20 ÷ 2）

> **注：** 右移做除法是"向下取整"的。41 右移一位得 20，不会四舍五入成 21——被挤出的余数直接丢弃。

### ASR：符号位亲自来填空

本课的重头戏。把上一课的补码请出来：32 位寄存器里的 `-40` 是 `0xFFFFFFD8`。如果对负数用 LSR 右移一位，左端补 0，结果变成一个巨大的正数——负数的身份写在最高位那个 1 里，你补个 0，等于当场把符号擦掉了。

`ASR`（算术右移）就是为这件事生的：右移时左端空位不补 0，而是补符号位——正数补 0，负数补 1。

![LSR 与 ASR 的分水岭](../images/chapters/fig-asr-vs-lsr.png)

    @ R0 = 0xFFFFFFD8（即 -40）
    asr r0, r0, #1     @ R0 = 0xFFFFFFEC（即 -20）
    asr r0, r0, #1     @ R0 = 0xFFFFFFF6（即 -10）

-40 → -20 → -10，一路都是负数，数学上分毫不差。

> **关键性质：无符号用 LSR，有符号用 ASR。** 这还是第五课那句"CPU 不知道类型，类型在你脑子里"的延续——同一串比特，想当有符号数除 2 就得选 ASR；选 LSR，CPU 也不会拦你，它只是默默补 0。

### ROR：比特的轮回

前面三条指令都会"丢比特"。而 `ROR`（循环右移）一个都舍不得丢——掉出右端的比特，会绕回左端重新入队。

![ROR 与 RRX](../images/chapters/fig-ror-rrx.png)

`0101 0001`（81）循环右移一位，最右边的 1 不消失，而是绕到最左边，得到 `1010 1000`（168）。32 位全量旋转时数值会变得面目全非——ROR 不追求数值意义，追求的是比特图案的彻底重排，而且完全可逆：再转 31 位就原样回来。

> **注：** 不丢信息、可逆，这两条性质让循环移位成了加密 / 解密算法的常客。很多加密例程（以及恶意软件的混淆代码）里都能看到成片的 ROR——逆向工程时见到它，基本就是在做比特级的打乱与还原。

### RRX：带上 C 标志的 33 位旋转

`RRX`（扩展循环右移）是最特殊的一个：不接受位移量参数，永远只移一位，而且把 C 标志也拉进环里。旧 C 进入寄存器最高位，bit0 进入新 C——相当于把"进位标志 + 32 位寄存器"拼成一条 33 位的队列整体旋转。

    rrx r0, r0         @ C → R0 最高位；R0 的 bit0 → C

它存在的意义是接力：做 64 位数据的移位时，先用 LSR/ASR 移高 32 位（挤出的比特进 C），再用 RRX 移低 32 位，C 里那一比特就顺着滑进低半部分的最高位——两半数据通过 C 标志无缝衔接。

### 移几位？

位移量有两种给法：

    lsl r0, r1, #5     @ 立即数：左移 5 位
    lsr r0, r1, r2     @ 寄存器：R2 里是几就移几位

立即数写死在指令里，速度快；寄存器版把位移量变成运行时变量——循环里逐位处理数据时非它莫属。

![五条移位指令速查表](../images/chapters/fig-shift-table.png)

### 小结

- LSL：右端补 0，左移 n 位等于乘以 2^n；高位被挤出就丢失
- LSR：左端补 0，无符号除以 2^n，奇数向下取整
- ASR：左端补符号位，有符号数除法的唯一正确选择
- ROR：首尾相接的轮回，不丢信息、完全可逆
- RRX：C 标志参与的 33 位旋转，多字移位的接力棒
- 位移量：立即数或寄存器两种给法，嵌入式位移不多花周期
