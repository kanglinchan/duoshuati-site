# CMP 比较指令：CPU 怎么知道谁大谁小？

想让 CPU 学会做选择（分支），得先解决一个前置问题：它怎么知道两个数谁大谁小、是否相等？答案就是今天的主角 `CMP`——整个分支体系的侦察兵。

### 比较的本质：减一下就知道

想知道 R0 和 R1 谁大？做个减法，看结果的正负零：差是负数说明 R0 小，差是正数说明 R0 大，差是零说明相等。

`cmp r0, r1` 会在 CPU 内部暗中计算 R0 - R1，然后根据差值刷新 CPSR 的标志位。

![CMP 的本质](../images/chapters/fig-cmp-essence.png)

注意它和 `SUB` 的关键区别：不保存结果。`sub r2, r0, r1` 把差值写进 R2；而 `cmp r0, r1` 算完就扔——没有任何寄存器被修改，唯一留下的痕迹是 CPSR 高 4 位标志被刷新。

为什么设计得这么"浪费"？因为做判断时我们根本不关心差值是几，只关心它是正、是负还是零。差值留着反而占寄存器，不如直接丢弃。

### CPSR 高 4 位：CMP 的记分牌

![CPSR 高 4 位](../images/chapters/fig-cpsr-nzcv.png)

- N（Negative，bit 31）：差值为负时置 1——读作"R0 比 R1 小"
- Z（Zero，bit 30）：差值为零时置 1——读作"两数相等"
- C（Carry，bit 29）：减法无需借位时置 1——读作"无符号意义下 R0 ≥ R1"
- V（Overflow，bit 28）：有符号溢出时置 1

> **易错点：** C 标志在减法语境下是反直觉的——C=1 表示"没借位"，C=0 才表示"借了位"。4 - 5 需要借位，所以 C=0；5 - 4 不需要，所以 C=1。

### 三次单步实验

![三次 CMP 实验对照](../images/chapters/fig-cmp-cases.png)

    mov r0, #4
    mov r1, #5
    cmp r0, r1      @ 4 - 5 = -1 → N=1（且借了位，C=0）

    mov r0, #5
    mov r1, #4
    cmp r0, r1      @ 5 - 4 = 1  → 全灭，但无借位 → C=1

    mov r0, #5
    mov r1, #5
    cmp r0, r1      @ 5 - 5 = 0  → Z=1，且无借位 → C=1

三次实验，三种标志组合。CMP 从不直接告诉你"谁大"，但标志位的组合就是答案：N=1 是"小"，Z=1 是"等"，C=1 是无符号的"≥"。

### CMP 与 SUB 的分工

![CMP 与 SUB 的分工](../images/chapters/fig-cmp-vs-sub.png)

`sub` 把差值写回寄存器、默认不动标志；`cmp` 丢弃差值、必然刷新标志。两者底层走同一个减法器，区别只在"结果存不存、标志动不动"。

> **关键性质：要结果用 SUB，要判断用 CMP。** CMP ≡ 扔掉结果的 SUBS。

### 为分支铺路

CMP 自己不做任何决定——它只是把证据留在 CPSR 里。真正拿证据做决定的是条件分支指令：`BEQ`（相等则跳）看 Z 标志，`BLT`（小于则跳）看 N 和 V 的组合……它们全都指望 CMP 提前把标志布置好：

    cmp r0, r1      @ 侦察兵：布置标志
    beq somewhere   @ 决策者：看标志行事

### 小结

- CMP：暗中计算 Rn - Rm，差值丢弃，不写回寄存器
- 必然刷新 CPSR 的 N/Z/C/V 四个标志
- N=1 是"小"，Z=1 是"等"，C=1 是无符号的"≥"
- 反直觉：减法里 C=1 表示"没借位"
- 与 SUB 分工：要结果用 SUB，要判断用 CMP
