# 栈上传参：寄存器不够用怎么办

上一课立了个规矩：参数依次放 r0~r3，返回值放 r0。当时埋了个伏笔——第 5 个、第 6 个参数往哪放？寄存器就这四个，答案只能是一块更大的地方：栈。这一课把例子从两个参数加到六个，看多出来的参数怎么搭"栈"这趟车。

## 一个六参数的函数

C 代码：

```c
int add_numbers(int a, int b, int c, int d, int e, int f) {
    return a + b + c + d + e + f;
}

int main() {
    int sum = add_numbers(1, 2, 3, 4, 5, 6);
}
```

六个参数，r0~r3 装满前四个还多出两个。翻译成 ARM 汇编，多出的 5 和 6 走栈：

## 调用方的三步新动作

比上一课多出的三步全是栈操作：

第一步，开空间。`sub sp, sp, #8` 把栈指针往下挪 8 字节——2 个参数 × 4 字节，正好 8。相当于在栈上"租"两个格子。

第二步，存参数。6 写进 `[sp]`（栈顶），5 写进 `[sp, #4]`。顺序是反的：最后一个参数放最低的地址。

第三步，收空间。`bl` 返回后 `add sp, sp, #8`，租的格子退掉。

> **注：**为什么 8 = 2 × 4？ARM 栈上每个槽位 4 字节，有几个栈上参数就开几乘 4 字节。3 个栈上参数就是 sub sp, sp, #12。

## 栈帧布局：参数住在哪里

![图 2 · 栈帧布局：第 5、6 个参数住在哪里](/assets/images/2026-08-arm-assembly/fig-stack-args-layout.png)

从下往上（地址从低到高）：参数 6 在 `[sp]`，参数 5 在 `[sp, #4]`，最上面是 `push {lr}` 压入的返回地址。被调方用一模一样的偏移取值：`ldr r4, [sp, #4]` 拿到 5，`ldr r4, [sp]` 拿到 6。

为什么逆序存？栈向下生长，最后进栈的参数占据最低地址，即 SP 正对的位置。被调方不用知道参数总数，按固定偏移 [sp]、[sp+4]…… 依次拿就行。双方对同一张布局图心照不宣，这就是调用约定的另一半。

> **易错点：**存和取的偏移必须严格一致。调用方把参数 5 放 `[sp, #4]`，被调方就得用同样的偏移取；写错偏移，取到的是隔壁格子的垃圾值，程序不报错，但结果全错。

## 分配用减，释放用加

开空间为什么做减法？栈向下生长——从高地址往低地址长。SP 减 8，栈顶向低地址推 8 字节，新空间就出来了；用完加 8，空间还掉。

![图 3 · SP 轨迹：开栈 −12，收栈 +12，回到原点](/assets/images/2026-08-arm-assembly/fig-stack-args-sp.png)

盯住轨迹：`push {lr}` 让 SP 减 4，`sub sp, sp, #8` 再减 8，最低点 −12；函数执行期间 SP 不动；返回后 `add sp, sp, #8` 加回 8，`pop {lr}` 再加 4，恰好归零。push 和 pop 也是自动做这种加减，只是不用手写数字。

> **关键性质：借多少还多少。**开 8 字节就必须还 8 字节，push 几个就得 pop 几个。只借不还，SP 回不去，上层函数的栈数据全错位。格子里残留的旧值没人再读，下次开栈自然被覆盖。

## 规则速查

![图 4 · 栈上传参规则速查](/assets/images/2026-08-arm-assembly/fig-stack-args-rules.png)

一句话：寄存器是快车道，栈是后备车厢——前 4 参走快车道，多余的上栈。

## 完整走一遍

1. `mov r0, #1` / `mov r1, #2`——前两个参数进寄存器
2. `push {lr}`——返回地址进栈，SP 减 4
3. `mov r2, #3` / `mov r3, #4`——参数 3、4 装满 r2、r3
4. `sub sp, sp, #8`——栈上开 8 字节，SP 到 −12
5. `str r4, [sp]` / `str r4, [sp, #4]`——参数 6、5 逆序落位
6. `bl add_numbers`——LR 记下返回地址，跳进函数
7. 三个 `add`——r0 = 1 + 2 + 3 + 4 = 10
8. `ldr r4, [sp, #4]` / `ldr r4, [sp]`——从栈取回 5 和 6
9. 两个 `add`——r0 = 10 + 5 + 6 = 21，结果在 r0
10. `bx lr`——按 LR 返回
11. `add sp, sp, #8` / `pop {lr}`——退格子、取回 LR，SP 归零

最终 r0 = 21，栈干干净净。寄存器参数和栈参数无缝衔接，这就是 AAPCS 调用约定的完整形态。

## 小结

- 前 4 个参数放 r0~r3；第 5 个起上栈，由调用方负责摆放
- 调用方三步：sub 开空间 → 逆序 str 存参（最后的参数在 [sp]）→ 返回后 add 收空间
- N = 栈上参数个数 × 4 字节；栈向下生长，分配用减、释放用加
- 被调方用 ldr rX, [sp, #偏移] 取栈上参数，偏移必须与存放时一致
- push 每个寄存器 SP 减 4，pop 每个加 4；借多少还多少，栈保持平衡
