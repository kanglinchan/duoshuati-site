栈上传参：寄存器不够用怎么办

上一课我们立了个规矩：参数依次放 r0~r3，返回值放 r0。当时埋了个伏笔——第 5 个、第 6 个参数往哪放？寄存器就这四个，答案只能是一块更大的地方：栈。这一课就把上一个例子从两个参数加到六个，看看多出来的两个参数怎么搭"栈"这趟车。

1. 目标：翻译一个六参数函数

先看 C 代码：

int add_numbers(int a, int b, int c, int d, int e, int f) {
    return a + b + c + d + e + f;
}

int main() {
    int sum = add_numbers(1, 2, 3, 4, 5, 6);
}

六个参数，r0~r3 装满前四个还多出两个。翻译成 ARM 汇编，多出来的 5 和 6 走栈：

main:
        mov r0, #1          @ 参数 1 → r0
        mov r1, #2          @ 参数 2 → r1
        push {lr}           @ 保存返回地址
        mov r2, #3          @ 参数 3 → r2
        mov r3, #4          @ 参数 4 → r3
        sub sp, sp, #8      @ 栈上开 8 字节（2 个参数 × 4 字节）
        mov r4, #6
        str r4, [sp]        @ 参数 6 → 栈顶 [sp]
        mov r4, #5
        str r4, [sp, #4]    @ 参数 5 → [sp+4]
        bl add_numbers      @ 调用函数
        add sp, sp, #8      @ 用完释放 8 字节
        pop {lr}            @ 恢复 LR

add_numbers:
        add r0, r0, r1      @ 参数 1 + 2
        add r0, r0, r2      @ 累加参数 3
        add r0, r0, r3      @ 累加参数 4
        ldr r4, [sp, #4]    @ 从栈取参数 5
        add r0, r0, r4      @ 累加参数 5
        ldr r4, [sp]        @ 从栈取参数 6
        add r0, r0, r4      @ 累加参数 6
        bx lr               @ 返回，结果在 r0

前 14 句还是上一课的老面孔，真正的新动作只有三处：sub sp, sp, #8 开空间、str 存参数、add sp, sp, #8 收空间。下面逐个拆。

2. 调用方的三步新动作

对照图里看调用方（main），比上一课多出的三步全是栈操作：

第一步，开空间。sub sp, sp, #8 把栈指针往下挪 8 个字节——要传 2 个参数，每个 4 字节，正好 8。这一步相当于在栈上"租"了两个格子。

第二步，存参数。把 6 写进 [sp]（栈顶），把 5 写进 [sp, #4]（栈顶上方 4 字节）。注意顺序是反的：最后一个参数放最低的地址。

第三步，收空间。bl 返回后 add sp, sp, #8 把 SP 加回去，租的格子退掉。

注：为什么 8 = 2 × 4？ARM 栈上每个槽位 4 字节（32 位），有几个栈上参数就开几乘 4 字节。3 个栈上参数就是 sub sp, sp, #12，以此类推。

3. 栈帧布局：参数住在哪里

存完之后，栈上长这样：

从下往上（地址从低到高）依次是：参数 6 在 [sp]，参数 5 在 [sp, #4]，最上面是 push {lr} 压入的返回地址。被调方 add_numbers 进来后，用一模一样的偏移量取值：ldr r4, [sp, #4] 拿到 5，ldr r4, [sp] 拿到 6。

为什么要逆序存？因为栈向下生长，最后一个进栈的参数占据最低地址，也就是 SP 正对的位置。这样约定下来，被调方不需要知道"总共有几个参数"，只要按固定偏移 [sp]、[sp+4]、[sp+8]…… 就能依次拿到第 6、第 5、第 4+n 个参数。双方对同一张布局图心照不宣，这就是调用约定的另一半。

易错点：存和取的偏移必须严格一致。调用方把参数 5 放在 [sp, #4]，被调方就得用 ldr r4, [sp, #4] 取；写错偏移，取到的就是隔壁格子的垃圾值，程序不会报错，但结果全错。

4. 分配用减，释放用加

很多初学者看到 sub sp, sp, #8 会愣一下：开空间为什么是做减法？因为栈是向下生长的——从高地址往低地址长。SP 减 8，等于把栈顶向低地址推 8 个字节，新空间就出来了；用完加 8，栈顶缩回去，空间还掉。

盯住轨迹图：push {lr} 让 SP 减 4（一个寄存器 4 字节），sub sp, sp, #8 再减 8，最低点到 −12；函数执行期间 SP 不动；返回后 add sp, sp, #8 加回 8，pop {lr} 再加 4，恰好归零。push 和 pop 其实也是自动做这种加减，只是不用你手写数字。

关键性质：借多少还多少。开 8 字节就必须还 8 字节，push 了几个就得 pop 几个。只借不还，SP 回不去，上层函数的栈数据就全错位了。至于格子里残留的旧值？没人再读它们，下次开栈自然被覆盖。

5. 完整走一遍

把寄存器传参和栈上传参拧成一股，从头到尾执行一遍：

  • mov r0, #1 / mov r1, #2——前两个参数进寄存器
  • push {lr}——返回地址进栈，SP 减 4
  • mov r2, #3 / mov r3, #4——参数 3、4 装满 r2、r3
  • sub sp, sp, #8——栈上开 8 字节，SP 到 −12
  • str r4, [sp] / str r4, [sp, #4]——参数 6、5 逆序落位
  • bl add_numbers——LR 记下返回地址，跳进函数
  • 三个 add——r0 = 1 + 2 + 3 + 4 = 10
  • ldr r4, [sp, #4] / ldr r4, [sp]——从栈取回 5 和 6
  • 两个 add——r0 = 10 + 5 + 6 = 21，结果按约定在 r0
  • bx lr——按 LR 返回
  • add sp, sp, #8 / pop {lr}——退格子、取回 LR，SP 归零

最终 r0 = 21，栈干干净净。寄存器参数和栈参数在同一次调用里无缝衔接，这就是 AAPCS 调用约定的完整形态。

6. 规则速查

一句话总结：寄存器是"快车道"，栈是"后备车厢"——前 4 参走快车道，多余的上栈。

小结

  • 前 4 个参数放 r0~r3；第 5 个起上栈，由调用方负责摆放
  • 调用方三步：sub sp, sp, #N 开空间 → 逆序 str 存参（最后的参数在 [sp]）→ 返回后 add sp, sp, #N 收空间
  • N = 栈上参数个数 × 4 字节；栈向下生长，分配用减、释放用加
  • 被调方用 ldr rX, [sp, #偏移] 取栈上参数，偏移必须与调用方存放时一致
  • push 每个寄存器 SP 减 4，pop 每个加 4；借多少还多少，栈保持平衡
