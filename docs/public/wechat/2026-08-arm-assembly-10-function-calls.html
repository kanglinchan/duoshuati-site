函数调用：让代码学会复用

顺序、分支、循环——前几课我们把程序三大控制流全部打通了。但还差一块拼图：真实程序动辄几十万行，如果同样的加法逻辑要在十个地方各写一遍，改一处就得改十处。解决方案你在 C 语言里早就用熟了——函数。这一课讲的就是：函数调用在 ARM 汇编层到底发生了什么。

剧透一下，核心只有四个问题：参数怎么递过去？怎么跳过去干活？算完怎么回来？回来时怎么保证寄存器没被弄乱？

1. 目标：翻译一个最小的函数调用

先看 C 代码：

int addNums(int a, int b) {
    return a + b;
}

int main() {
    int result = addNums(1, 2);
}

addNums 收两个参数、返回两者之和。翻译成 ARM 汇编，调用方和被调方各干各的活：

        mov r0, #1          @ 参数 1 → r0
        mov r1, #2          @ 参数 2 → r1
        push {r0, r1}       @ 把 r0、r1 的值存进栈（护现场）
        bl add_nums         @ 调用：跳过去，同时记下返回地址
        mov r2, r0          @ 返回值在 r0，转存到 r2
        pop {r0, r1}        @ 从栈取回原值，恢复 r0、r1

add_nums:
        add r0, r0, r1      @ r0 = 参数1 + 参数2
        bx lr               @ 按记录的返回地址回家

下面把这张总览图拆开，逐个角色讲清楚。

2. 逐行对照：谁负责什么

看右上的汇编列，颜色就是分工：

调用方（main）负责三件事——备参数（mov r0 / mov r1）、发起调用并接住返回值（bl + mov r2, r0）、护现场（push / pop）。被调方（add_nums）只负责干活和回家：add r0, r0, r1 算出结果，bx lr 返回。

注："现场"指的是调用发生前各寄存器里的值。add_nums 会把 r0 改成计算结果，调用方如果还想要 r0 的旧值，就必须在调用前先存起来。

3. 怎么跳过去、怎么回来：BL 与 BX LR

跳过去靠 bl add_nums（Branch with Link）。它一条指令干两件事：先把"下一句指令的地址"写进 LR 寄存器（R14 的别名，Link Register），然后跳到 add_nums 标签处。

回来靠 bx lr（Branch and eXchange）。它把 LR 里存的地址装回程序计数器——CPU 就回到了当初 bl 的下一句，正好是 mov r2, r0。

这个"留地址—回地址"的机制是函数调用的命脉。没有 LR，跳过去就回不来了——就像出门前不记家门地址，干完活只能流浪。

易错点：如果被调方内部又调用了别的函数，第二条 bl 会覆盖 LR，第一个返回地址就丢了。所以函数嵌套时，进来第一件事就是 push {lr} 把 LR 也存进栈，返回前 pop {lr} 取回。本课的例子没有嵌套，暂时不用管。

4. 参数与返回值：调用约定

参数放哪、结果放哪，不是调用方和被调方临时商量出来的，而是体系结构提前定好的规矩，叫调用约定（calling convention）。ARM 的约定可以浓缩成一句话：参数从 r0 开始递，返回值也用 r0 还。

前 4 个参数依次放 r0、r1、r2、r3——第 5 个及更多就压到栈上。返回值放 r0（本课是 32 位整数，一个 r0 装得下）。所以调用方在 bl 之后要从 r0 取结果，例子中用 mov r2, r0 把返回值转存进 r2。

正因为"返回值固定放 r0"，而 r0 同时也是第一个参数寄存器——add_nums 一执行 add r0, r0, r1，参数就被结果顶掉了。这正是下一节要解决的问题。

5. 护现场：PUSH / POP 与栈

调用前 r0=1、r1=2 是调用方（更上层）还在用的值。add_nums 一跑，r0 变成 3——原值没了。怎么办？调用前把怕丢的寄存器存进栈，回来再取回：

push {r0, r1} 把两个寄存器的当前值压进栈，SP（R13，栈指针）自动挪到新栈顶。pop {r0, r1} 按后进先出的顺序把值弹回寄存器，SP 退回原位。

三连拍里盯住 SP 的位置：push 后它指向新栈顶，pop 后复位。栈就是一块"谁都可以临时寄存行李的格子架"，函数调用全靠它保平安。

关键性质：push 和 pop 必须配对。寄存器列表一致、顺序匹配，只 push 不 pop 栈就漏了，只 pop 不 push 取回的是垃圾值。

6. 完整走一遍

把四条线拧成一股，从头到尾执行一遍：

  • mov r0, #1 / mov r1, #2——按调用约定把参数放进 r0、r1
  • push {r0, r1}——r0、r1 的值（1 和 2）存进栈，护住现场
  • bl add_nums——LR 记下返回地址，跳进函数
  • add r0, r0, r1——r0 = 1 + 2 = 3，结果按约定放回 r0
  • bx lr——按 LR 返回，落到 mov r2, r0 这句
  • mov r2, r0——返回值 3 转存进 r2
  • pop {r0, r1}——栈里的 1 和 2 弹回，r0、r1 恢复原样

至此 r2=3（拿到了结果），r0、r1 原封不动（现场无损），SP 复位（栈干净）——一次教科书式的函数调用。

小结

  • 函数调用四件事：传参（r0~r3）、跳转（bl）、返回（bx lr）、护现场（push/pop）
  • bl 一条指令干两件事：LR ← 返回地址，然后跳转；bx lr 按地址回家
  • 调用约定：第 1~4 个参数依次放 r0~r3，更多压栈；返回值放 r0
  • push 把寄存器值存进栈、SP 挪到新栈顶；pop 后进先出地恢复、SP 复位；两者必须配对
  • 嵌套调用会覆盖 LR，函数套函数时要 push {lr} / pop {lr}
