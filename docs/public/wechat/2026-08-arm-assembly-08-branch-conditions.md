# B 指令与条件后缀：让 CPU 学会做选择

上一课的 `CMP` 是侦察兵——减一下、留好证据（标志位），然后退场。这一课，决策者登场：`B` 指令和它的条件后缀家族。有了它们，程序第一次拥有了"岔路"。

### 从直线到岔路

之前所有程序都是"顺序流"：PC 寄存器自顾自地每次 +4，一条接一条往下跑。而分支指令只做一件事——按条件决定 PC 的下一个值。

![顺序流 vs 分支流](../images/chapters/fig-branch-flow.png)

分支需要两个新角色：标签（`cond1:` 这样以冒号结尾的行，只是地址的名字，不产生指令）和跳转（`b cond2`，汇编器会把标签换算成地址差编进指令里）。

### 无条件分支与条件后缀

`B`（Branch）最朴素：不问条件，直接跳。它的真正威力在于后缀——把条件码拼在 B 后面，它就长出了判断力：

- `beq`：相等才跳（看 Z=1）
- `bne`：不等才跳（看 Z=0）
- `blt`：小于才跳（看 N 和 V 的组合）

回忆上一课：`cmp r0, r1` 之后两数相等时 Z=1。于是"相等则跳"的完整拼图就是：

    cmp r0, r1      @ 侦察兵：相等则 Z=1
    beq cond1       @ 决策者：Z=1 才跳去 cond1

这就是 ARM 世界里 if 语句的最小单元。CMP 布置标志，条件分支看标志行事。

### 完整实验：BEQ 不跳，B 兜底

![单步执行轨迹](../images/chapters/fig-beq-demo.png)

    mov r0, #4
    mov r1, #5
    cmp r0, r1      @ 4 ≠ 5，Z=0
    beq cond1       @ Z=0，不跳，继续往下
    b cond2         @ 无条件跳：直接着陆 cond2
cond1:
    mov r2, #1      @ 被跳过，R2 始终是 0
cond2:
    mov r3, #2      @ 跳转着陆点，R3 = 2

调试器里单步走完，R2=0、R3=2——cond1 分支被整个跳过。同一份代码，标志位不同，走的路就不同。

### 顺序穿透：最烂的 if 语句

上面的代码有个暗伤：汇编里没有"块"的概念，标签挡不住顺序执行。假如 R0=R1，BEQ 跳进 cond1 执行完 `mov r2, #1`——然后 PC 继续 +4，顺势滑进 cond2，`mov r3, #2` 也执行了！两个分支都跑一遍，else 形同虚设。

> **易错点：** 高级语言的 if-else 自带"互斥"，汇编里互斥要靠自己用跳转搭出来。忘记加"防穿透"分支，是条件分支新手最经典的 bug。

正确的拼装需要两条"胶水分支"：

![if-else 的正确拼装](../images/chapters/fig-if-else-pattern.png)

    cmp r0, r1
    beq cond1       @ 胶水① 条件跳：相等才去 if 体
    b cond2         @ 胶水② 兜底跳：不等就去 else 体
cond1:
    mov r2, #1      @ if 体
    b end           @ 胶水③ 防穿透：干完就走
cond2:
    mov r3, #2      @ else 体
end:

三条 B 家族指令各司其职：一条管"选谁"，一条管"躲开谁"，一条管"收队"。看懂这个三段式，就看懂了所有 if-else 的汇编骨架。

### 条件后缀大家族

![条件后缀速查表](../images/chapters/fig-cond-suffix.png)

EQ/NE/GT/LT/GE/LE/AL 一整族后缀，全部围绕 CPSR 标志设计。GT/LT 看的是 N 和 V 的组合而不只是 N，是为了正确处理有符号溢出——但不用背规则，记住"后缀语义 = 高级语言的比较符"就够了。

有了这一族后缀，`if (a > b)`、`while (i != 0)`、for 循环……高级语言的所有控制流，都能拆成 CMP + 条件分支的组合。接下来的课程就会把 C 语言的 if 和循环逐个翻译成汇编，看看编译器到底干了什么。

### 小结

- B：无条件改写 PC；标签只是地址的名字
- 条件后缀：BEQ 看 Z=1、BNE 看 Z=0，GT/LT 看 N 与 V 的组合
- 组合拳：CMP 布置标志 + 条件分支看标志行事
- 顺序穿透：if 体末尾必须加 `b end` 防穿透
- AL = 总是跳，即无条件 B 本身
