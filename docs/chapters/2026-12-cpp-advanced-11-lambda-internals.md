# lambda 的实现原理：编译器替你写的函数对象

![lambda 底层：编译器生成匿名类，[] = 构造捕获 = 成员变量，() = operator()，mutable 解 const](/assets/images/cpp-advanced/cpp-advanced-11-lambda-internals.png)

第 39 篇给函数对象立过功，也记过它的短板：**每次使用都要先定义一个类**——为一次 sort 定义的比较类，用完之后类名永远留在代码里。lambda（C++11）把这个痛点一刀解决：语法就地书写，**类型由编译器匿名生成**。

"lambda 是什么"的底层答案一句话：**编译器替你生成的函数对象类 + 一个匿名实例**。`[]`、`()`、`{}` 三段语法各对应类的一个零件。这篇对着语法逐件拆解，把捕获列表的四种写法翻译回成员变量与构造函数——之后 lambda 的一切行为（mutable、悬垂捕获）都能自行推导。

边界：lambda 无捕获时可隐式转函数指针（用于 C 接口回调），一句话带过；泛型 lambda（C++14）、初始化捕获（C++14）不在本篇。

## 1. 三段语法 → 类的三个零件

```cpp
auto f = []() { cout << "hello"; };
f();                          // 调用

// 编译器眼中的等价物：
class TestLambda01            // 匿名类（类型名编译器生成，用户不需要知道）
{
public:
    void operator()() const { cout << "hello"; }   // ① () ② {}
};
TestLambda01 f;               // ③ auto 拿到的就是这个类的实例
```

三段语法的翻译表：

| lambda 语法 | 对应的类零件 |
|---|---|
| `()` | `operator()` 的形参列表 |
| `->返回类型` | `operator()` 的返回值（可省略，编译器推导） |
| `{ 函数体 }` | `operator()` 的函数体 |
| `[捕获列表]` | **构造函数的形参** + 对应的成员变量 |

前三个是"函数怎么调"，第四个（捕获列表）是"函数记得什么"——也是 lambda 与普通函数的全部区别所在。

带参数与返回值的版本同样机械对应：

```cpp
auto f2 = [](int a, int b) -> int { return a + b; };
// 生成：int operator()(int a, int b) const { return a + b; }
```

"几元函数对象"的老概念在这里自动消解：形参几个，operator() 就是几元——**不需要为一元、二元、三元的差异定义不同的类**，lambda 想要几元就写几元。

## 2. 捕获列表：构造函数的形参表

`[]` 空着表示"不捕获任何外部变量"——生成的类构造函数无参、没有成员变量，lambda 体内碰不到任何外部名字。想用外部变量，就得"捕获"，四种写法逐一翻译：

```cpp
int a = 10, b = 20;

[a, b]()        { ... }     // ① 按值捕获指定变量 → 成员 int ma=a, mb=b（拷贝进来）
[=]()           { ... }     // ② 按值捕获全部用到的外部变量
[&]()           { ... }     // ③ 按引用捕获全部用到的外部变量 → 成员是引用（第 07 篇：引用=别名）
[&a, b]()       { ... }     // ④ 混合：a 按引用，b 按值
```

翻译成类就一目了然：**按值捕获 = 构造函数按值收参 + 成员变量保存拷贝**；**按引用捕获 = 成员是引用**（构造时绑定，lambda 体内读写的是原变量本身）。`= 与 &` 的"全部"指 lambda 体内实际用到的那些变量，不必罗列。

## 3. mutable：解开按值捕获的 const 锁

一个经典实验：按值捕获 a、b，lambda 体里交换它们：

```cpp
int a = 10, b = 20;
auto f3 = [a, b]() { int t = a; a = b; b = t; };   // 编译错误！
f3();
// a 仍是 10，b 仍是 20
```

编译错误信息直指本质："无法在非可变 lambda 中修改按值捕获的变量"。翻译回类视角：按值捕获生成了成员 `ma`、`mb`，而编译器生成的 `operator()` 是 **const 方法**（第 13 篇：编译器对只读语义默认加 const）——const 方法里改成员，老规则不允许。

解法是 lambda 的 `mutable` 修饰符：

```cpp
auto f4 = [a, b]() mutable { int t = a; a = b; b = t; };
```

mutable 的作用一句话：**给 lambda 的所有按值捕获成员加 mutable 修饰**——const 方法里也能改了，编译通过。但注意结果：**f4 内部的交换只作用于成员拷贝，外部的 a、b 纹丝不动**（10、20 原样）——按值捕获改的是副本，这与函数按值传参"形参改不影响实参"是同一条规则。

想让外部真的被交换？**按引用捕获**：

```cpp
auto f5 = [&a, &b]() { int t = a; a = b; b = t; };
f5();      // 外部 a=20，b=10——引用成员直接读写原变量
```

按引用捕获不需要 mutable——成员是引用，修改的是"引用所指向的内存"，不是引用本身（第 07 篇的语义在 lambda 里的复现）。

## 4. 回到泛型算法：lambda 的主场

第 40 篇的两个场景，lambda 版全部更干净：

```cpp
sort(v.begin(), v.end(), [](int a, int b) { return a > b; });   // 降序：二元，就地书写

auto it = find_if(v.begin(), v.end(), [](int val) { return val < 65; });
// 一元谓词：不需要 bind1st/bind2nd 的装配推导——想几元就几元

for_each(v.begin(), v.end(), [](int val) {
    if (val % 2 == 0) cout << val << " ";        // 只打印偶数
});
```

绑定器时代的"二元装配成一元"推导在 lambda 下彻底退休：**不拘泥一元二元，问题场景需要几元就写几元**。而函数对象类必须预先定义、类名永驻代码的痛点也消失——lambda 就地生灭，类型匿名，代码里不留痕迹。

最后一个细节：**在成员方法内写 lambda，想访问 this 的成员必须捕获 this**（`[this]` 或 `[=]`）——空捕获 `[]` 下连成员变量都碰不到，因为生成的类与外层对象毫无关系。成员方法内的 lambda 是独立小类，this 是它连接外部对象的唯一桥。

## 小结

- lambda = 编译器生成的匿名函数对象类 + 一个实例；`()`=operator() 形参、`{}`=函数体、`[]`=构造捕获=成员变量
- 捕获翻译表：按值 = 成员拷贝；按引用 = 成员引用；`=`/`&` = 全部实际用到的变量；混合自由组合
- mutable = 给按值捕获成员加 mutable，解开编译器生成的 const 方法之锁；按值捕获的修改只作用于副本——外部不变
- 按引用捕获才真正改外部（引用成员读写原内存），且不需要 mutable
- 泛型算法主场：二元比较、一元谓词就地书写，bind1st/bind2nd 的装配推导退休；几元自由，类型匿名
- 成员方法内访问 this/成员必须捕获 this——lambda 是独立小类，this 是唯一桥

lambda 让"可调用物"唾手可得，function 让它们有处安放。下一篇合龙：C++11 的通用 bind + function 实战线程池——成员方法怎么充当线程函数。
