# 有序关联容器：set 与 map 的红黑树世界

![有序关联容器：set/map 底层红黑树、中序遍历有序输出、map[] 的插入副作用与自定义类型 operator&lt; 要求](/assets/images/cpp-core/cpp-core-37-ordered-containers.png)

把 20 个随机数塞进 `set<int>`，遍历打印——输出居然**从小到大排好了**。没调过任何排序函数，谁干的？

答案是底层那棵**红黑树**：set 的插入是往树上放节点，遍历是对树做**中序遍历**——二叉搜索树的中序遍历天然有序。这就是有序关联容器的全部魔法：set、multiset、map、multimap 四兄弟共用这棵树，增删查 O(log₂n)，取出来天然有序。

这篇讲清四兄弟的分工、map 那个臭名昭著的 `[]` 副作用，以及自定义类型放进有序容器的正确姿势。

边界：红黑树的旋转与着色规则属于数据结构课程，本文把它当"自平衡二叉搜索树"黑盒使用；无序版本（哈希表族）在下篇。

## 1. set：会自动排序的集合

单重集合 `set` 的核心规则两条：**元素唯一**、**取出有序**。

```cpp
set<int> s;
for (int i = 0; i < 20; ++i)
    s.insert(rand() % 100);      // 只给值，不给位置

for (auto it = s.begin(); it != s.end(); ++it)
    cout << *it << " ";          // 从小到大，且重复值只出现一次
```

两个细节都值得咀嚼。**insert 只给值不给位置**——对比 vector 的 `insert(pos, val)` 需要迭代器指定位置，set 的 insert 只要值：红黑树自己知道往哪放（按值比较沿树下行），用户指定位置反而破坏树的有序性。**遍历输出有序**——`begin()` 到 `end()` 的迭代器遍历，本质是对红黑树做中序遍历，输出即升序序列。你排序了，是树替你排的。

`multiset` 是"多重"版：允许重复元素，`insert` 从不检查存在性，给什么存什么；相同值在树中相邻排列。单重与多重的选择就看一句话：**键要不要去重**。

## 2. map：键值对与那个危险的 []

映射表 `map<K, V>` 存的是**键值对**，内部用 `pair<const K, V>` 承载——`first` 是键，`second` 是值。**排序只看键**，值不参与：键是 int，编译器自己会比；键是自定义类型，才轮到第 3 节的规则。

```cpp
map<int, Student> stu;
stu.insert({1000, Student(1000, "张三")});
stu.insert({1020, Student(1020, "李四")});
stu.erase(1020);                     // 按键删
Student s = stu.find(1000)->second;  // find 查询，无副作用

for (auto it = stu.begin(); it != stu.end(); ++it)
    cout << it->first << " " << it->second;   // 按键升序输出
```

重头戏是 `operator[]`——map 最方便也最危险的接口：

```cpp
stu[2000];                            // 返回什么？
```

如果键 2000 存在，返回对应的值，一切正常。**如果不存在，它会插入一个新键值对**：键是 2000，值是 V 的**默认构造对象**——然后返回这个新造对象的引用。这个副作用有两重后果：一是你"只是想查一下"却悄悄污染了容器（size 多了一）；二是它要求 **V 必须有默认构造函数**——第 16 篇 String 类那个"传 nullptr 也开 1 字节"的构造，在 map 的场景里是刚需，没有默认构造直接编译报错。

所以查询的正确姿势是 `find(k)`：找到了返回指向该键值对的迭代器，找不到返回 `end()`——**绝不插入**。[] 只该用在"确认要写入"的语义下：`stu[1000] = newStudent;` 这类赋值场景它才是利器（存在则覆盖，不存在则创建——这正是它副作用换来的便利，用对地方就是好东西）。

## 3. 自定义类型放进有序容器

往 set 里放 Student，编译器报错：不知道两个 Student 怎么比大小。红黑树的每个插入都要沿树做键比较，键怎么比必须由类型自己交代——**提供 `operator<`**：

```cpp
class Student
{
    int id;
    string name;
public:
    bool operator<(const Student& rhs) const     // 必须写 const！
    {
        return id < rhs.id;                      // 按学号排序
    }
};
```

两个要求各有来历。**必须是成员方法或全局函数**（这里是成员版），**必须带 const 后缀**：树内部比较时拿到的键是 const 的（pair 的 first 是 `const K`），调用非常量方法直接编译失败——第 13 篇的"只读方法一律 const"守则在容器场景的强制兑现。

map 的好消息：**排序只看键**，值类型不需要 `operator<`——键是 int 时编译器自己搞定，值随便是什么类型。但值类型仍需**默认构造**（第 2 节 `[]` 副作用的要求）。总结成一张入坑清单：

- 放进 set / 用作 map 的**键**：提供 `operator<`（const 方法）
- 用作 map 的**值**：提供默认构造函数；不必提供 `operator<`

## 4. 与无序家族的对比

set/map 与 unordered_set/unordered_map 的**接口几乎一字不差**——insert、erase、find、迭代器遍历，用法完全一致。区别全部沉淀在底层与输出：

| | 有序族（set/map） | 无序族（unordered_set/map） |
|---|---|---|
| 底层 | 红黑树 | 链式哈希表 |
| 增删查 | O(log₂n) | 接近 O(1) |
| 遍历输出 | **按键升序** | 乱序（哈希桶顺序） |
| 附加能力 | 范围查询（lower_bound/upper_bound） | 无顺序语义 |

选型口诀呼应第 34 篇：**要有序遍历或范围查找 → 有序族；只要快、不关心顺序 → 无序族**。接口一致的好处是切换成本极低——把 `map` 改成 `unordered_map`，业务代码几乎不用动，性能特征却完全换了。

## 小结

- 有序关联容器四兄弟共用红黑树：增删查 O(log₂n)，set/map 单重（键唯一），multiset/multimap 多重（键可重复）
- insert 只给值不给位置——树的有序性由它自己维护；遍历 = 中序遍历 = 升序输出
- map 存 pair（first 键 / second 值），排序只看键；遍历用 `it->first / it->second`
- `map[k]` 有插入副作用：键不存在时插入 k + V 的默认构造对象——查询用 find（无副作用），[] 留给"确认写入"场景；副作用要求 V 必须有默认构造
- 自定义类型入坑清单：做键或进 set 要 `operator<`（const 常成员方法）；做 map 的值只要默认构造
- 与无序族接口几乎一致，切换零成本；区别在底层（红黑树 vs 哈希表）、复杂度（log vs O(1)）、输出（有序 vs 乱序）

红黑树家族归队。下一篇它的孪生兄弟：无序关联容器——链式哈希表怎么把增删查压到 O(1)，哈希冲突怎么办。
