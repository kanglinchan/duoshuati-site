# 对象的内存布局与对齐：sizeof 的完整算法

![结构体对齐规则：最大成员对齐、补位；空类 C 为 0、C++ 为 1 及其对象本质](/assets/images/cpp-core/cpp-core-42-memory-layout.png)

`struct { char a; double b; }` 的 sizeof 是多少？凭直觉是 9，答案是 **16**。三个 char 的结构体是 3，一个 char 的空壳结构体在 C 里是 0、在 C++ 里是 **1**——同样是"空"，两种语言给出了不同答案，理由直指 C++ 对象的本质。

这一篇把 sizeof 的计算规则整理成一套可执行的算法，并借"空类为什么是 1"把对象 = 内存 + 构造这条贯穿全书的线索再拧紧一圈。它是笔试里"给你一个类，问 sizeof"这类题的完整解法。

边界：以 32 位 x86 + 默认对齐为准；`#pragma pack`、跨平台差异、位域不在本文范围（第 10 篇讲过 `cl /d1reportSingleClassLayout` 验证工具，本文结论都能用它复核）。

## 1. 对齐的两条规则

结构体（以及类的对象）的大小不是成员大小的简单相加，编译器按两条规则摆放成员：

**规则一：每个成员的偏移量必须能被 min(自身大小, 对齐系数) 整除**——放不下就在前面补位（padding）。

**规则二：总大小必须是最大成员大小的整数倍**——末尾不够再补。

"对齐系数"由编译器决定（MSVC 默认取最大成员大小），于是实用口诀是：**找最大成员，一切向它看齐**。用两个例子跑一遍算法：

```text
struct Data { char a; double b; };

偏移 0        ：a（1 字节）
偏移 1~7      ：补 7 字节（double 要求偏移是 8 的倍数，0+1=1 不行，垫到 8）
偏移 8~15     ：b（8 字节）
总大小 16     ：16 恰好是最大成员 8 的整数倍 ✓

struct T { char x; char y; char z; };    // 三个 char

三个成员各占偏移 0、1、2；最大成员 1 字节，总大小 3 = 1 的整数倍 ✓
→ sizeof = 3（不是 1，也不是 4）
```

第一个例子里的 7 字节空洞就是"对齐的代价"。为什么编译器要这么浪费？第 10 篇说过一次：对齐让每个成员都落在自身大小的整数倍地址上，CPU 读取不跨缓存行、不拆总线周期——**用空间换访问速度**。内存越来越便宜，随机访问的 penalty 越来越贵，这笔账现代硬件下始终划算。

## 2. 空结构体：C 说 0，C++ 说 1

```c
struct Empty {};     /* C 语言 */
sizeof(struct Empty) = ?    // Windows/MSVC：编译不过！Linux/GCC：0
```

先记一个反直觉的事实：**C 语言里 MSVC 根本不允许定义空结构体变量**（报错）；Linux/GCC 允许，sizeof 是 **0**——"啥也没有，分 0 字节"，逻辑自洽。

同样的"空"翻译成 C++（`.cpp` 里的空类），答案变成 **1**，而且 Windows、Linux 全平台一致。为什么 C++ 不肯给 0？

这就要回到第 11 篇立下的那条定义：**对象 = 开辟内存 + 调用构造函数**。C 里的结构体变量只需要内存——啥也不用存，0 字节说得过去。但 C++ 的对象不一样，它诞生时必须被**构造**，而构造函数（每个成员方法都一样，第 10 篇）编译后带一个 `this` 形参：

```cpp
Empty* p = new Empty();      // 编译器：开内存 → 拿地址调 Empty::Empty(this)
```

构造函数得知道"在哪儿构造"——`this` 必须接到一个**有效的内存地址**。0 字节的对象没有地址可言，构造无从发起，对象就创建不起来。所以 C++ 强制空类至少占 **1 字节**：内存的最小计量单位是字节，1 字节才能有唯一地址，才能有 this，才能有构造。

这个解释在面试里讲出来，直接把"C++ 空类是 1"从一条背诵结论升级成一条因果链：**对象区别于变量的本质是"要被构造"→ 构造需要 this 地址 → 地址需要至少 1 字节内存**。面试官问的从来不是"是多少"，是"为什么"。

顺带把变量与对象的分野钉死：**变量只需要内存，对象 = 内存 + 构造**。这是 C 与 C++ 在"类型实例"这件事上的全部区别，空类大小只是它的一个投影。

## 3. 继承与成员的 sizeof 陷阱

有了对齐算法和空类本质，几个经典陷阱一次排掉。每个都是"脑洞题"，正确答案全部违反直觉：

**空类派生空类，还是 1。**`class A {}; class B : public A {};` sizeof(B) 是 1，**不是 1+1=2**。继承把基类部分"并"进派生类对象——B 继承的 A 部分本身就是空的，加上自己的空，对象里没有任何实际数据，按空类规则仍占 1 字节。"空类加空类等于二"是典型的脑补错误。

**空类加一个 char 成员，是 1，不是 2。**加了成员它就**不再是空类**了——空类规则（那 1 字节的"地址凭证"）失效，一切按普通对齐算法算：一个 char 就是 1。那 1 字节不是"空类税"，是"无成员时保证可构造"的保底，有真成员就轮不到它。

**虚继承空类，变 8（32 位）。**虚继承让对象头部多一个 **vbptr**（第 32 篇），4 字节——对象从 1 变 5，按 4 对齐补到 **8**。虚继承的代价从这一刻开始显形。

**加虚函数，变 4 的倍数。**类里只要有虚函数，对象头部就多一个 **vfptr**（第 29 篇）。空类 + 一个虚函数 = vfptr 4 字节，sizeof = 4。

这四条合起来是一张"sizeof 体检表"：先看有没有虚函数（+vfptr）、有没有虚继承（+vbptr），再按对齐算法摆成员，最后核对总大小对齐——任何类的大小都能这样推导出来。

## 4. sizeof(类) 与 sizeof(对象)：一回事

`sizeof(Test)` 和 `sizeof(Test对象)` 相等吗？相等——而且"类的大小"这个说法本身就是不严格的。

类是**类型**，类型是模具：模具本身不占内存，占内存的是用它造出来的对象（第 10 篇的面包比喻）。所以 sizeof(Test) 的准确含义是"**用 Test 类型定义一个对象，这个对象占多少内存**"——它量的是对象，类只是个名字。笔试里问"类大小"，答案永远是"该类对象的大小"，两个 sizeof 一个意思。

这条澄清还有个实用推论：**静态成员变量不影响 sizeof**（它在数据段，不属于对象，第 13 篇），**成员函数不影响 sizeof**（指令在代码段，全类一份）。sizeof 只数两样东西：非静态成员变量 + 各类指针（vfptr/vbptr）+ 对齐补位。

## 小结

- 对齐算法两条：成员偏移按 min(自身大小, 对齐系数) 整除（不够就补位）；总大小是最大成员的整数倍——口诀"找最大成员，一切向它看齐"
- `char + double` = 16（中间垫 7 字节）；三个 char = 3——空洞是对齐的代价，换 CPU 访问速度
- 空结构体：MSVC 的 C 直接编译不过，GCC 的 C 是 0；C++ 的空类全平台是 **1**
- 空类 = 1 的因果链：对象 = 内存 + 构造 → 构造函数要 this 地址 → 地址需要至少 1 字节——变量只需内存，对象还要被构造
- 陷阱四连：空类派生空类仍是 1（不是 2）；空类加 char 成员是 1（不再是空类）；虚继承空类 8（+vbptr）；空类加虚函数 4（+vfptr）
- sizeof(类) = sizeof(对象)——类是模具不占内存；静态成员与成员函数都不计入，sizeof 只数成员变量、指针、补位
