# 单例模式：一个类只许一个对象，还要线程安全

![单例：饿汉/懒汉、双重检查锁、volatile、静态局部变量版；多线程面试四五十分钟的名题](/assets/images/cpp-advanced/cpp-advanced-16-singleton.png)

单例模式（Singleton）是创建型模式里最简单的，却也是面经里聊得最久的——有读者反馈"一面被单例模式问了四五十分钟"。原因很简单：它自己不复杂，但它与多线程结合后能拆出**懒汉/饿汉、双重检查、volatile、静态局部变量**一整条链，每一环都是前几篇的知识点。

需求一句话：**一个类不管创建多少次对象，永远只能得到该类型一个实例**。日志模块就是典型——所有功能模块都往同一个日志对象里写，日志系统必须是全局唯一的。

边界：单例的删除时机（程序结束时的析构顺序）与跨 DLL 问题不在本篇；Meyers 单例（静态局部变量版）是本篇压轴。

## 1. 先禁掉"第二个对象"：构造私有化

单例的实现地基是访问限定符（第 13 篇）：**把构造函数放进 private**——外部再也 new 不出对象；再提供一个 static 的 `getInstance()` 返回唯一实例。保证"只有一个"的所有写法，都是围绕"getInstance 里那一次构造发生在何时、由谁保证"展开的。

## 2. 饿汉：程序启动就构造，天然线程安全

**饿汉模式**——"饿"，急着吃：实例在**程序启动阶段**（main 之前）就构造好（第 11 篇：全局对象在数据段、main 前构造）：

```cpp
class Singleton
{
private:
    static Singleton instance;      // 类内声明
    Singleton() {}
public:
    static Singleton* getInstance() { return &instance; }
};
Singleton Singleton::instance;      // 类外定义：启动即构造
```

线程安全**自动成立**：对象构造发生在 main 之前的单线程初始化阶段，多线程开始时实例早已就位，不存在竞争。代价是不管用不用都占内存、都在启动时构造（如果构造很重，启动就被拖慢）。

## 3. 懒汉：延迟构造，竞争来了

**懒汉模式**——"懒"，用的时候才构造：实例的诞生延迟到**第一次调用 getInstance** 时。启动快、不用不占，但构造动作落入多线程辖区——"new 对象"是多条指令的复合动作（第 11 篇：开内存 + 调构造），不是原子操作，竞争条件（第 14 篇）随之而来：两个线程同时第一次调用 getInstance，双双判断"实例为空"、双双 new——**第二个实例诞生，单例被打破**。

## 4. 修复演进：锁的粒度与双重检查

**第一版：整个函数加锁。**getInstance 全程 lock/unlock——线程安全成立，但**锁粒度太大**：实例构造好之后，单线程/无竞争场景下每次调用也要加锁解锁，纯浪费。

**第二版：锁缩小 + 双重检查。**把锁挪到"判断为空才构造"的分支里，分支外不再加锁；同时**锁内再判断一次**（第 14 篇的老朋友——判断在锁外，判断与操作间有缝隙）：

```cpp
Singleton* getInstance()
{
    if (instance == nullptr)              // 第一重：无竞争路径零锁开销
    {
        lock_guard<mutex> lock(mtx);
        if (instance == nullptr)          // 第二重：拿到锁再复核
            instance = new Singleton();
    }
    return instance;
}
```

线程 A 进来拿锁构造中；线程 B 过了第一重判断、阻塞在锁上；A 构造完释放锁，B 拿到锁——**锁内第二重发现 instance 已非空，直接放弃**，不再 new。既保住了多线程安全，又让无竞争路径零锁开销。

**还差一块：volatile。**instance 是数据段的共享变量，而 CPU 为提速会把共享内存拷贝进线程缓存——线程 B 看到的可能是缓存里的旧值（还是 nullptr），双重检查形同虚设。给指针加 `volatile`（修饰指针变量本身，不是指向的对象）：**强制所有线程读内存原始值，禁止缓存**——某线程写入后其他线程立即可见。

## 5. 压轴：静态局部变量版——编译器替你加锁

还有更精简的写法，连 mutex 都不用：

```cpp
Singleton* getInstance()
{
    static Singleton instance;     // 函数静态局部变量（第 14 篇：首次执行到才构造）
    return &instance;
}
```

三重保障全是语言机制。**其一**：静态局部变量在数据段，**第一次执行到才构造**——天然懒汉。**其二**：C++11 保证**静态局部变量的初始化是线程安全的**——编译器在初始化指令周围自动加锁解锁（Linux 下 gdb disassemble 该函数可证），并发首次调用只有一个线程执行构造，其余等待。**其三**：静态局部变量只初始化一次，语言层面封死"第二个实例"。

这就是 **Meyers 单例**——最精简的线程安全懒汉：零手写锁、零 volatile、三行代码。面试的完整答卷因此成形：**饿汉（启动构造，天然安全）→ 懒汉裸写（竞争条件）→ 锁 + 双重检查 + volatile（手工修复）→ 静态局部变量版（语言机制修复）**——四步演进，每步都是前面篇章的知识点会师。

## 小结

- 单例地基：构造函数 private + static getInstance——所有写法围绕"那次构造何时发生"展开
- 饿汉：启动即构造（main 前），天然线程安全，代价是启动即占资源
- 懒汉：延迟到首次 getInstance——"new 对象"非原子，两线程同判空则单例被打破
- 修复演进：全程加锁（粒度太大）→ 锁缩进分支 + 双重检查（锁内复核）→ volatile 禁线程缓存（写入立即可见）
- Meyers 单例：函数静态局部变量——首次执行到才构造（懒）+ C++11 初始化线程安全（编译器自动加锁，gdb 可证）+ 只初始化一次——最精简正确版
- 面试四步答卷：饿汉 → 懒汉裸写 → 双重检查 + volatile → Meyers——每步对应一篇旧知识
