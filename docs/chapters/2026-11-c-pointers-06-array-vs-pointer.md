# 数组与指针：长得像，其实是两种东西

第 2 课我们学了一个规则："表达式中，数组名会自动转成指向首元素的指针。" 这一课要把它讲透，因为**数组和指针的纠缠不清，是 C 指针一半困惑的根源。**

先亮结论，免得你带着悬念读到一半走神：

> **数组和指针是两种完全不同的东西。它们只是在"表达式"这一个特定场合表现得像。**

搞清楚"什么时候像、什么时候不像"，C 指针最难的一关就过去了。

### 1. 先分清两个面孔：变量是"值"还是"地址"？

在拆解数组之前，先补一个基础概念：**左值（lvalue）**。

```c
int x;
x = 5;        /* 这里的 x 是"一块存储空间"——左值 */
int y = x;    /* 这里的 x 是"里面存的值 5"——右值 */
```

同一个 `x`，在赋值号左边时表示"那块空间"，在右边时表示"里面的值"。**能表示"一块存储空间"的表达式叫左值**，只能取它的值的叫右值。

这个概念有什么用？它能一句话解释为什么 `5 = x` 报错（5 不是一块空间），也为下面理解"数组不能赋值"埋下伏笔。

### 2. 核心规则：表达式中，数组自动转成指针

第 2 课学过：`int a[5]; int *p = a;` 里，`a` 被自动转成了 `&a[0]`。现在把这个规则说得更准确：

**只要数组出现在"表达式"中（被使用、被运算、被传参），它就会被转换成"指向首元素的指针"。**

这个转换做了两件事：

1. 把"数组"这个类型的**最后一环**换成"指针"。`int[5]` 变成 `int*`；`int[3][5]` 变成 `int(*)[5]`（指向"5 个 int 的数组"的指针）。
2. **元素个数被丢掉了。** 转换后的指针只剩下"首元素在哪"，不知道后面跟了几个。所以函数收到数组参数后不知道长度——根源就在这。

注意这个转换**不产生任何机器码**，纯粹是编译器换了副"眼镜"看同一个东西。

### 3. 三个例外：这些情况下数组不转换

上面说的是"表达式中"。有三种情况，数组**不会**转成指针：

**① `sizeof(a)`**——得到的是整个数组的总大小，不是指针大小。

```c
int a[5];
sizeof(a);      /* 20（5 × 4 字节），不是 8 */
sizeof(a[0]);   /* 4（一个 int） */
/* 所以求元素个数用：sizeof(a) / sizeof(a[0]) */
```

**② `&a`**——得到的是"指向整个数组的指针"，类型是 `int(*)[5]`，不是 `int*`。

```c
int a[5];
int (*p)[5] = &a;   /* 指向"5个int的数组"的指针 */
p + 1;              /* 前进 20 字节（跳过整个数组） */
```

**③ 用字符串字面量初始化数组时**——`char s[] = "abc"` 里的 `"abc"` 不转成指针，而是被当成 `{'a','b','c','\0'}` 的初始化列表。

记住这三条例外，"数组什么时候不是指针"就有数了。

### 4. 声明中：数组和指针是两码事

重头戏来了。刚才说"数组在表达式中会变成指针"，很多人就误以为"数组和指针差不多"。看声明就知道它们多不一样：

```c
int a[5];     /* 真的分配了 5×4=20 字节的连续内存 */
int *p;       /* 只分配了 8 字节（一个指针的大小），指向未知 */
```

**声明一个数组，是真的在内存里开辟了 N 个元素的空间；声明一个指针，只是给了一个"指向别处"的格子，本身不装数据。**

由此产生一个高发错误：

```c
/* file1.c */
int a[100];        /* 定义：分配 400 字节 */

/* file2.c */
extern int *a;     /* 错！把数组当成指针声明 */
```

file1 里 a 是占 400 字节的数组，file2 却声明它是个 8 字节的指针。链接器通常不吭声就把它们凑一块儿，运行时 file2 拿着 a 的前 8 字节内容当成地址去访问——程序直接崩。**定义和声明的类型必须一致。**

### 5. `a[i]` 和 `p[i]`：同一个写法，两种本质

现在能把 `[]` 彻底看清了。下面两种写法长得一模一样：

```c
int a[5] = {10, 20, 30, 40, 50};
int *p = a;

a[2];   /* 30 */
p[2];   /* 30，居然也行！ */
```

但它们的底层路径不同：

- `a[2]`：a 转成 `&a[0]`，再 `*(&a[0] + 2)`，取到 a 的第 3 个元素。
- `p[2]`：p 本身就是指针，`*(p + 2)`，从 p 指的位置往后数 2 个。

殊途同归，因为 `a` 一参与运算就变成了和 `p` 一样的东西。这就是为什么 `p[i]` 也能用下标——**`[]` 从来不是数组的专利，它是"指针 + 偏移"的语法糖。**

二维数组 `a[i][j]` 也是这个套路，只是套了两层：

```c
int a[3][5];
a[i][j]  ≡  *( *(a + i) + j )
```

第一层 `a` 转成 `int(*)[5]`，`a + i` 跳整行（20 字节）；解引用后变成 `int*`，`+ j` 再跳 4 字节。两个 `[]` 各触发一次"数组→指针"转换，一次按行跳、一次按元素跳。

### 6. `char s[] = "abc"` vs `char *p = "abc"`：一个能改，一个会崩

把前面的知识合起来，就能看懂一个超经典的坑：

```c
char s[] = "abc";
s[0] = 'X';        /* ✓ 没问题，s 变成 "Xbc" */

char *p = "abc";
p[0] = 'X';        /* ✗ 运行时崩溃（段错误） */
```

同样是 `"abc"`，为什么一个能改一个崩？

- `char s[] = "abc"`：这是数组初始化（例外③）。编译器在**栈上**给 s 分配 4 字节，把 `'a','b','c','\0'` **复制**进去。s 是可写的局部数组。
- `char *p = "abc"`：p 只是个指针，指向的是字符串字面量本身——那东西存在**只读区**（第 3 课讲过）。往只读区写数据，操作系统直接毙掉程序。

![char str[] 是栈上的可写拷贝，char *p 指向只读区原件](/assets/images/c-pointers/cptr-06-string-vs-array.png)

一句话：**要修改字符串，用数组；只读，用指针。**

### 7. 一张表终结所有混乱

把数组和指针的区别浓缩成一张表，收藏好：

| | 数组 `int a[5]` | 指针 `int *p` |
|---|---|---|
| 声明时分配 | 20 字节（5×4） | 8 字节 |
| `sizeof` | 20 | 8 |
| `&a` 的类型 | `int(*)[5]` | `int**` |
| 能否被赋值 `a = …` | 不能（转出来的是右值） | 能 |
| `a[i]` / `p[i]` | 转成指针后偏移 | 本身就是指针，直接偏移 |
| 存的是 | 5 个 int 的数据 | 一个地址 |

再记一句话收尾：**数组是"一块数据"，指针是"一个地址"。** 表达式让它们看起来能互换，但那只是编译器施的障眼法。

### 小结

- 左值表示"一块空间"，右值只表示"一个值"；数组转出的指针是右值，所以数组不能被赋值
- 数组在表达式中转成指针，但 `sizeof`、`&`、字符串初始化数组是三个例外
- 声明层面数组和指针完全不同：数组开辟空间，指针只存地址；`extern` 声明时张冠李戴会直接崩
- `a[i]` 和 `p[i]` 殊途同归，因为 `[]` 就是"指针 + 偏移"的语法糖
- `char s[] = "abc"` 可改，`char *p = "abc"` 指向只读区不能改
