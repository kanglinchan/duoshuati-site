# 迭代器：一套 begin/end 通吃所有容器

![迭代器 = 面向对象的指针：遍历差异封装在 ++ 重载里；begin 到 end 左闭右开](/assets/images/cpp-core/cpp-core-23-iterators.png)

手写的 vector 已经能存能删了（第 20 篇），但你遍历它只能用下标——这依赖"底层是数组"的内部知识。`string` 更麻烦：想遍历字符，连底层成员叫什么都不知道（私有）。**外部代码不该知道容器的内部结构**，那遍历怎么办？

答案是迭代器（iterator）：容器暴露一套**统一的接口**——`begin()` 给你指向首元素的"东西"，`end()` 给你指向末尾后继的"东西"，对它 `++` 前进、对它 `*` 取值、用 `!=` 判断走完。所有容器的这套用法一字不差，而"怎么从当前元素走到下一个"的内部差异，全部封装在各自的 `++` 重载里。

这篇亲手给 string 和 vector 各写一个迭代器——四个成员函数，写完你对 `for(auto it = v.begin(); it != v.end(); ++it)` 这行代码的理解会从"背下来的咒语"变成"我写的每一块零件都认识"。

边界：本文实现的是最常用的正向迭代器；反向迭代器、const_iterator 的完整体系、以及迭代器失效是下一篇的主题。

## 1. 迭代器的契约：三个符号加一对端点

迭代器不是容器，是**遍历协议**。协议只有几条，先背下来：

```cpp
for (auto it = c.begin(); it != c.end(); ++it)
    cout << *it;
```

- `c.begin()`：返回指向**首元素**的迭代器；
- `c.end()`：返回指向**最后一个元素后继位置**的迭代器——注意不是最后一个元素，是它再往后一格（第 20 篇 vector 的 `last` 指针，同一个口径）；
- `++it`：从当前元素走到下一个；
- `*it`：访问当前元素；
- `it != c.end()`：还没走完。

`[begin, end)` 左闭右开。空容器的 `begin() == end()`，循环体一次都不进——这个口径让"空容器"不需要任何特判，协议自洽。

**为什么所有容器能用同一套写法？**因为容器底层千差万别——数组、链表、红黑树、哈希表——但"从当前元素到下一个元素"这个动作每种容器自己知道。数组是 `+1`，链表是 `p = p->next`，树是走向后继……这些差异**全部封装在各自迭代器的 `++` 运算符重载里**。用户只管 `++it`，底层怎么走不关他的事。这就是"迭代器可以**透明地**遍历容器"的准确含义。

## 2. 给 string 写一个：四件套

迭代器的身份是**容器的嵌套类**——每种容器底层结构不同、迭代器实现必然不同，做成嵌套类型顺理成章（嵌套类还能访问外层类的私有成员）。string 底层是 `char` 数组，所以它的迭代器本质是一根 `char*` 的封装：

```cpp
class String
{
    char* _pstr;
public:
    class iterator
    {
    public:
        iterator(char* p = nullptr) : _p(p) {}              // ① 构造：接一根指针

        bool operator!=(const iterator& it) const           // ② 不等：底层指针的比较
        {   return _p != it._p;   }

        iterator& operator++()                              // ③ 前置++：底层指针 +1
        {   ++_p;   return *this;   }

        char& operator*()                                   // ④ 解引用：访问当前字符
        {   return *_p;   }

    private:
        char* _p;
    };

    iterator begin() { return iterator(_pstr); }            // 容器的方法，返回迭代器
    iterator end()   { return iterator(_pstr + strlen(_pstr)); }
};
```

四件套逐件看。**构造**接一根指针——迭代器"指向某元素"的实质就是它内部的指针指向数组某格。**`!=`** 比较的是两根底层指针——两个迭代器相等当且仅当它们内部指针指向同一处。**前置 `++`** 让指针走一格——string 是数组，走一格就是 `+1`；若底层是链表，这里写的就是 `p = p->next`，而调用方代码不变。**解引用**返回 `char&` 而不是 `char`——返回引用意味着既能读也能写（`*it = 'x'` 合法），和原生指针的语义对齐。

`begin`/`end` 是**容器**的方法（不是迭代器的）：`begin` 用首元素地址构造迭代器；`end` 用 `_pstr + strlen`——正好是 `'\0'` 的位置，"最后一个字符的后继"，协议要求的那个格子。

一个习惯问题顺手定下：迭代器的 `++` **只用前置**。后置 `++` 要先拷贝一份旧值返回（第 25 篇细讲它的代价），多产生一个临时对象；遍历循环从来不用返回值，前置版零开销。STL 风格代码写 `++it` 而不写 `it++`，理由在此。

## 3. 给 vector 写：同一套模板换个成员类型

vector 底层也是数组，迭代器与 string 几乎逐行相同，只是 `char*` 换成 `T*`：

```cpp
template<typename T>
class vector
{
    T* first;  T* last;  T* end_;
public:
    class iterator
    {
        T* _p;
    public:
        iterator(T* p = nullptr) : _p(p) {}
        bool operator!=(const iterator& it) const { return _p != it._p; }
        iterator& operator++() { ++_p; return *this; }
        T& operator*() { return *_p; }
    };

    iterator begin() { return iterator(first); }
    iterator end()   { return iterator(last); }      // last 正是"有效元素后继"
};
```

`end()` 直接复用第 20 篇的 `last`——那个"最后有效元素的后继位置"的指针，当初看着只是 `size()` 的计算原料，现在显出真正身份：它就是 `end()` 迭代器。第 20 篇埋的左闭右开的种子在这里发芽。

要一个"只读版"迭代器也简单：解引用返回 `const T&`、`++`/`!=` 照旧——这就是 `const_iterator`，允许遍历 `const vector` 而不让人改元素。机制同源，只是 const 修饰的位置不同（第 13 篇的 this 三态在这里是解引用返回值的三态）。

## 4. vector 的三种遍历，谁才是通用的

vector 是数组，下标遍历又快又直白：

```cpp
for (int i = 0; i < vec.size(); ++i)
    cout << vec[i];               // 随机访问 O(1)
```

前提是给 vector 重载了 `[]`（`return first[index];` 加上下标越界检查）。三种遍历各就各位：

| 方式 | vector | 链表/红黑树/哈希 | 通用性 |
|---|---|---|---|
| 下标 `[]` | ✓ O(1) | ✗（内存不连续，无意义） | 仅顺序数组类容器 |
| 迭代器 | ✓ | ✓ | **所有容器** |
| range-for | ✓ | ✓ | 所有容器（见下） |

链表遍历用 `[]` 毫无意义——它的第 5 个元素不在"首地址 + 5×sizeof"处。**只有迭代器对所有容器通用**，这也是迭代器存在的全部理由。

## 5. range-for 与泛型算法：契约的兑现

C++11 的范围 for 更短：

```cpp
for (auto val : vec)
    cout << val;
```

它是糖不是魔法——底层展开就是 `begin()/end()/++/*`。验证方法很直接：把容器的 `begin`/`end` 方法注释掉，range-for 立刻编译报错"未找到可用的 begin 函数"。**range-for 的合法前提是容器满足迭代器契约**；`auto` 则替你写完那个冗长的嵌套类型名 `vector<int>::iterator`（第 17 篇模板的又一处红利）。

最后一层关系是 STL 的骨架：**泛型算法**（`sort`、`find`、`reverse` 这些全局函数）之所以能服务所有容器，正因为它们的参数**接收的是迭代器区间**——`sort(v.begin(), v.end())`。算法不认识 vector 也不认识 list，它只认识"一对能 `++`、能 `*`、能 `!=` 的东西"。迭代器是容器和算法之间的**胶水层**：容器提供遍历能力，算法消费遍历能力，两边解耦。

## 小结

- 迭代器契约：`begin()` 首元素、`end()` 末尾后继（左闭右开）、`++` 前进、`*` 取值、`!=` 判终；空容器 `begin() == end()` 自然跳过循环
- "透明遍历"的实质：各容器从当前元素到下一元素的差异，全部封装在自己的 `++` 重载里
- 迭代器是容器的嵌套类，本质是对底层遍历变量（数组是指针，链表是节点指针）的封装；经典四件套：构造、`!=`、前置 `++`、解引用（返回引用以支持写）
- 遍历习惯用前置 `++`：后置版多产生临时对象
- 下标遍历只对数组类容器有意义（O(1) 随机访问）；迭代器是唯一对所有容器通用的遍历方式
- range-for 底层就是 `begin/end/++/*`；泛型算法参数收迭代器区间——迭代器是容器与算法之间的胶水
