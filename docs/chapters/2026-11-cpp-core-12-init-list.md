# 构造函数的初始化列表：成员变量的出生时刻

![初始化列表在函数体之前执行：类类型成员是初始化，函数体内是先默认构造再赋值；顺序由声明决定](/assets/images/cpp-core/cpp-core-12-init-list.png)

两段几乎一样的构造函数，一段把初始化写在冒号后面，一段写在花括号里。对 `int` 成员，两者生成的汇编一模一样；把成员换成类类型，一个编译通过，一个报"没有合适的默认构造函数可用"。

再配一道笔试题：初始化列表里明明先写了 `mb(data)` 再写 `ma(mb)`，结果 `mb` 是 10，`ma` 却是个垃圾值。这两件事是同一个答案的两面——**初始化列表发生在函数体之前，初始化顺序由成员声明顺序决定，与列表书写顺序无关**。

这篇文章把这条时间线讲透：为什么成员对象"必须"用初始化列表、初始化和赋值对类类型差在哪、以及那道经典的顺序陷阱题。

边界：本文承接上一篇的构造函数基础；拷贝构造与赋值运算符重载属于深拷贝篇；`char` 数组名这类需要调用函数的初始化，列表里放不下，文中会说明。

## 1. 从一个编译错误说起

例. 商品类要加"生产日期"。日期不写成商品的三个 `int` 属性，因为年月日还会用在过期日期、人的生日、入学日期上——单独抽象成日期类，再让商品持有它的对象：

```cpp
class CDate
{
    int m_year; int m_month; int m_day;
public:
    CDate(int y, int m, int d)      // 只有这一个构造函数
    {
        m_year = y; m_month = m; m_day = d;
    }
};

class CGoods
{
    char m_name[20];
    double m_price;
    int m_amount;
    CDate m_date;                   // 成员对象：组合关系（a part of）
public:
    CGoods(const char* name, double price, int amount, int y, int m, int d)
    {
        strcpy(m_name, name);
        m_price = price;
        m_amount = amount;
        // m_date 怎么构造？函数体里写 m_date = CDate(y,m,d) 也不行——见下文
    }
};
```

解. 编译器在 `CGoods` 的构造函数上报错：**CDate 没有合适的默认构造函数可用**。

要读懂这个错误，先看两个铺垫。第一，商品和日期是**组合关系**——日期是商品信息的一部分，代码上的体现就是日期对象作为商品的成员变量，习惯叫**成员对象**。（与"继承是 is a"相对，这条线在继承篇收束。）

第二，上一篇说过：对象的诞生 = 开辟内存 + 调用构造函数，两步缺一不可。这条规则对成员对象同样生效——`CGoods` 的对象开辟内存时，`m_date` 那 12 字节也就位了，它作为对象**同样需要构造**。

而 `CGoods` 的代码里没有任何一处指定过 `m_date` 的构造方式。C++ 的规则是：没指定构造方式，就用**默认构造**。可 `CDate` 自己写了带参构造，编译器就不再生成默认构造（上一篇讲过：一旦自定义构造函数，默认构造消失）。于是链条断在中间——商品要构造，商品构造之前要先构造它的日期，日期却没构造可用。

错误信息里那句"函数体里也没指定"暗示了关键时间线：**成员对象的构造发生在当前类构造函数体执行之前**。等你能在花括号里写代码时，`m_date` 早就过了它的构造时机——函数体里能做的只有赋值，而赋值的前提是先有一个已构造的对象。

## 2. 初始化列表：把初始化提到函数体之前

语法是在构造函数参数表后加冒号，跟一串"成员(初值)"：

```cpp
CGoods(const char* name, double price, int amount, int y, int m, int d)
    : m_date(y, m, d)               // 指定成员对象的构造方式
    , m_price(price)
    , m_amount(amount)
{
    strcpy(m_name, name);           // char 数组只能留在函数体
}
```

冒号后这一串叫**构造函数的初始化列表**。它逐个指定成员变量的初始化方式：`m_date(y, m, d)` 直说"用这三个参数调用 CDate 的构造函数"——成员对象的构造方式从此有了着落，编译错误解除。

注意 `m_name` 没在列表里：`char` 数组的初始化要调用 `strcpy`，初始化列表里只能写"直接初始化"这种简单形式，调不了函数，所以名称的拷贝留在函数体里做。

## 3. 列表里写和函数体里写，差在哪

对内置类型，真没差。`int m_amount;` 写在列表里和写 `m_amount = amount;` 在函数体里，断点进反汇编，指令一字不差——都是"先有内存，再写值"。

对类类型，两条路彻底分岔：

```cpp
// 写在初始化列表：m_date(y, m, d)
// 语义：定义 m_date 的同时直接调用 CDate(y,m,d) —— 一步到位的初始化

// 写在函数体：m_date = CDate(y, m, d);
// 语义：先默认构造 m_date（无参），再调用赋值运算符把临时对象拷给它 —— 两步
```

函数体版本要求 `CDate` 有默认构造——它没有，所以编译失败；就算有，也白做了两步构造。这就是第 1 节那个报错的全貌：**成员对象的初始化只有初始化列表这一条路**。

标准库和开源代码把能进列表的成员全部写进列表，理由也在此：列表是初始化，函数体是赋值，类类型的赋值隐藏着"构造 + 拷贝 + 析构临时对象"的额外开销。养成习惯——**能进列表的都进列表**，实在进不去的（`strcpy` 这类）才留在函数体。

## 4. 笔试题：顺序由声明决定，不是书写顺序

例. 先自己写答案：

```cpp
class Test
{
    int ma;
    int mb;
public:
    Test(int data = 10) : mb(data), ma(mb) {}
    void show() { /* 打印 ma、mb */ }
};

Test t;
t.show();        // 输出什么？
```

列表里 `mb(data)` 写在前面，直觉会说"先 mb=10，再 ma=mb=10"，输出 `10 10`。上机跑一遍：`mb` 是 10，`ma` 是 **-858993460**。

解. 规则是：**成员变量的初始化顺序由它们在类中的声明顺序决定**，与初始化列表的书写顺序无关。

`ma` 声明在前，就先初始化 `ma`。此刻轮到 `ma(mb)`——拿 `mb` 给 `ma` 初始化，可 `mb` 还没轮到初始化，值是分配内存后留下的随机值。在 Windows 的 Debug 版里，栈上内存被填成 `0xCC`（第 01 篇讲过这道警戒线），按 `int` 读出来正是 `-858993460`。之后才轮到 `mb(data)`，`mb` 拿到 10。

所以输出是 `ma = -858993460`（Linux/GCC 下则是当时的栈残留值）、`mb = 10`。反过来把声明改成 `mb` 在前，同一个列表立刻输出两个 10——变的不是代码，是声明顺序。

这道题的组合拳还有一记变体：把 `ma(mb)` 换成列表里没出现 `ma`。没出现在列表里的成员走默认初始化，内置类型就是"不初始化"——垃圾值原样保留。两条结论合起来：

> 列表书写顺序是给人看的，声明顺序才是编译器执行的。**让列表的书写顺序与声明顺序保持一致**，这类坑从源头上就不存在。

## 小结

- 成员对象让类之间形成组合关系（a part of）；它作为对象，同样适用"开内存 + 调构造"两步
- 成员对象的构造发生在外层构造函数体**之前**；没指定构造方式就找默认构造，找不到就报错
- 初始化列表在函数体之前执行，逐个指定成员的初始化方式；`char` 数组这类要调函数的留在函数体
- 内置类型两者汇编相同；类类型本质不同——列表是初始化，函数体是"默认构造 + 赋值"
- 初始化顺序由声明顺序决定，与列表书写顺序无关；列表顺序请与声明顺序对齐

初始化的地基铺完。下一篇盘点成员方法的全家福：常对象、常成员函数、静态成员、静态方法——它们和 `this` 指针的爱恨情仇。
