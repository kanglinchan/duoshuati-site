# 指针运算与数组：a[i] 底层就是指针

![指针 + 1 前进「所指类型的长度」](/assets/images/c-pointers/cptr-02-pointer-arith.png)

上一课我们知道了指针就是存地址的变量。这一课要揭开一个可能会颠覆你认知的事实：

**你在 C 里写的每一次 `a[i]`，底层都是指针运算。数组下标只是个"语法糖"。**

这不是修辞，是字面意义。学完这一课，你会明白为什么 `a[i]` 和 `*(a+i)` 可以互换、为什么数组传给函数时长度会"丢"、以及为什么 `scanf("%s", buf)` 不用加 `&`。

### 1. 数组：一排连续的房间

先看数组在内存里的样子。

```c
int a[5];
for (int i = 0; i < 5; i++) a[i] = i;

for (int i = 0; i < 5; i++)
    printf("&a[%d] = %p\n", i, (void*)&a[i]);
```

输出大概是：

```text
&a[0] = 0x7fff04819160
&a[1] = 0x7fff04819164
&a[2] = 0x7fff04819168
&a[3] = 0x7fff0481916c
&a[4] = 0x7fff04819170
```

注意看地址：相邻元素正好差 4——一个 int 的字节数。**数组元素在内存里是紧挨着连续排列的**，中间没有缝隙。

![数组在内存中连续分布，相邻地址差 4 字节](/assets/images/c-pointers/cptr-02-array-memory.png)

这个"连续"是数组一切特性的根基。正因为连续，"第 i 个元素在哪"才有确定答案。

### 2. 指针 + 1，到底走多远？

现在做个实验：对指针加 1，看它变了多少。

```c
int hoge;
int *p = &hoge;

printf("%p\n", (void*)p);        /* 比如 0x7fffc7d60af4 */
p++;
printf("%p\n", (void*)p);        /* 0x7fffc7d60af8 —— 加了 4！ */
printf("%p\n", (void*)(p + 3));  /* 0x7fffc7d60b04 —— 又加了 12 */
```

直觉上，地址加 1 应该是 +1 字节。可这里 `p++` 实际加了 4，`p + 3` 加了 12。

规律是：**对指针加 n，地址实际前进「所指类型的长度 × n」字节。** p 指向 int，int 长 4 字节，所以 +1 走 4 字节、+3 走 12 字节。如果 p 指向 char，+1 就只走 1 字节。

为什么这样设计？想一想就通了：指针运算服务的对象是数组。"下一个元素"才是有意义的操作，至于它在内存里偏移几个字节，让编译器根据类型去算——你只管用 `p + 1` 表达"下一个"。

> **注意：** 这也意味着指针和整数不是一回事。把指针当整数乱加是危险的：加多加少由类型决定，类型错了整个就偏了。

### 3. 本课核心：数组名就是指向首元素的指针

重头戏来了。看这段代码：

```c
int a[5] = {10, 20, 30, 40, 50};
int *p = a;          /* 注意：没有 &！直接赋值 */
```

没有 `&`，编译居然不报错，而且 p 真的能用了：

```c
printf("%d\n", *p);      /* 10 */
printf("%d\n", *(p+2));  /* 30 */
```

奥秘是一条铁律，请务必记住：

> **在表达式里，数组名会被自动当成"指向它第一个元素的指针"。**

所以 `int *p = a;` 等价于 `int *p = &a[0];`。编译器看到单独的 `a` 出现在表达式中，就默默把它换成了首元素的地址。

这条规则有一个重要例外（先留个印象，第 6 课细讲）：`sizeof a` 里的 `a` 不转换——所以 `sizeof(a)` 得到的是整个数组的大小，不是指针的大小。

### 4. `a[i]` 就是 `*(a + i)` 的语法糖

把第 2、3 节拼起来，一个惊人的等价关系浮出水面。

`a[i]` 发生了什么？a 先被转成"指向 a[0] 的指针"，然后……这不就是 `*(a + i)` 吗？加 i 个元素（前进 i×4 字节），再解引用。

```c
int a[5] = {10, 20, 30, 40, 50};

printf("%d\n", a[2]);      /* 30 */
printf("%d\n", *(a + 2));  /* 30 —— 一模一样 */
```

**`a[i]` 和 `*(a + i)` 在 C 里是完全等价的两种写法**，编译器看到前者就直接翻译成后者。下标运算符 `[]` 存在的唯一理由，是让代码好读——它就是块糖。

甚至，因为加法满足交换律，`a[i]` 还能写成 `i[a]`（`*(i + a)`），编译也认。当然，正经代码里千万别这么写，这只是用来证明"[] 和数组没有半点特殊关系"的。

### 5. 数组传参的真相：传的是指针

现在回答一个所有学 C 的人都会撞上的问题：数组怎么传给函数？

答案有点反直觉：**C 语言根本传不了数组本身，你传的永远只是"指向首元素的指针"。**

```c
void print_array(int arr[], int size)   /* 形参写的是数组的样子…… */
{
    for (int i = 0; i < size; i++)
        printf("%d ", arr[i]);          /* ……也能用下标访问 */
}

int main(void)
{
    int a[5] = {1, 2, 3, 4, 5};
    print_array(a, 5);      /* a 在表达式中 → 转成 &a[0] 传过去 */
    return 0;
}
```

调用时 `a` 被转成指针传进去。所以形参 `int arr[]` 实际上是个指针——`int arr[]`、`int *arr`、`int arr[5]` 三种写法完全等价，那个 5 写了也白写。

由此引出两个推论：

**推论一：函数不知道数组有多长。** 它手里只有一个光秃秃的地址，所以必须额外传个 `size` 参数。这也是为什么 `printf("%s", str)` 不用传长度——字符串靠结尾的 `'\0'` 自己标记边界。

**推论二：函数里 `sizeof(arr)` 得到的是指针大小（8 字节），不是数组大小。** 想算数组长度，只能在数组定义的地方算：`sizeof(a) / sizeof(a[0])`。

顺带解开第 1 课留的扣子：`scanf("%s", buf)` 为什么不用 `&`？因为 buf 是数组，在表达式里已经自动变成指针了；而 `scanf("%d", &n)` 里 n 是普通变量，得手动 `&` 取地址。

### 6. 为什么要有指针运算这种怪东西

读到这你可能会嘀咕：既然 `a[i]` 又好用又好懂，干嘛还要 `*(a+i)` 这种写法？

两个历史原因：

**一是继承。** C 的前身 B 语言里指针就是整数，+1 走一格（那时一格就是一个 word）。C 把它改造成"按类型走"，但语法留了下来。

**二是当年的性能。** 上古编译器优化能力弱，循环里反复写 `a[i]` 会反复算 `a + i×4`；而 `*p++` 每次只加一次。所以 K&R 那本圣经里说"指针版更快"。

但注意，这是**时代的眼泪**。现代编译器（GCC、Clang）对这种循环的优化早已炉火纯青，两种写法生成的机器码几乎一模一样，性能差距是零。

所以今天的实践原则很简单：**新代码用下标 `a[i]` 写，好读；读别人的老代码时，认得 `*(p+i)` 就行。** 别为了显得"很 C"去写 `*++p`，那是给自己和后来人挖坑。

### 小结

- 数组元素在内存中连续排列，相邻地址差 `sizeof(元素类型)`
- 指针 + n，地址前进 `sizeof(所指类型) × n` 字节——指针运算为数组而生
- **表达式中的数组名 = 指向首元素的指针**（sizeof 除外）
- `a[i]` ≡ `*(a + i)`，下标 `[]` 只是语法糖
- 数组传参传的是指针，函数不知道长度，得额外传 size
- `scanf("%s", buf)` 不加 `&`，因为 buf 已经是指针了
- 现代写法：用下标，别炫指针运算
