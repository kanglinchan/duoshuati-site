# 无序关联容器：哈希表的 O(1) 世界

![无序关联容器：链式哈希表、unordered_set/map 与 set/map 接口一致、海量数据查重去重实战](/assets/images/cpp-core/cpp-core-38-unordered-containers.png)

上一章的红黑树家族做到了"有序 + O(log n)"。但很多场景里用户更贪心：**不关心顺序，只要够快**。无序关联容器（unordered_*）为此而生——底层**链式哈希表**，增删查**接近 O(1)**。

最有意思的是它的接口：与 set/map **几乎一字不差**（insert/erase/find/迭代器遍历），连类名都只是在前面加了 `unordered_` 前缀。这意味着两件事：学习成本近零（会 set 就会它），切换成本近零（改个类名，性能特征完全切换）。

这篇讲清哈希族的规则、与红黑树族的差异，最后用"海量数据查重/去重"两个实战题展示它真正的主场。

边界：哈希函数与冲突解决的底层实现属于数据结构课程，本文把它当"哈希桶 + 链地址法"黑盒使用；unordered 容器的负载因子调节（rehash）只点到为止。

## 1. 哈希族四兄弟与它们的"快"

命名规则一句话：**有序族加 `unordered_` 前缀**。四兄弟对号入座：

| | 键唯一（单重） | 键可重复（多重） |
|---|---|---|
| 只存键（集合） | `unordered_set` | `unordered_multiset` |
| 存键值对（映射表） | `unordered_map` | `unordered_multimap` |

单重与多重的区别在**插入时是否检查存在性**：单重 set 存 50 个随机数（范围 1~100），重复值不落库，`size()` 可能只有 18；多重 set 照单全收，`size()` 就是 50，`count(15)` 能数出 2。其余操作完全一样。

**快**的来源是哈希：元素落在哪个桶由哈希函数决定，定位一步到位，不用像红黑树那样沿树比较下行。代价同样是哈希给的：**桶内无序，遍历输出乱序**，且没有"范围查询"的语义基础——`lower_bound`/`upper_bound` 在这里不存在。

## 2. 接口零迁移：从 set 切换过来

因为接口与有序族一致，语法要点只需补两条。

**insert 不给位置**（与 set 相同，原因同样）：元素落在哪个桶由哈希函数说了算，vector 那种"迭代器指定位置插入"在这里没有意义——`insert` 只收值（或键值对）。

**map 的键值对打包**：`unordered_map<K, V>` 的 insert 收的是 `pair<K, V>`，两种写法：

```cpp
unordered_map<int, string> m;
m.insert(make_pair(1000, "张三"));        // 显式打包
m.insert({ 1010, "李四" });               // C++11：大括号初始化 pair（更常用）
```

`pair` 用 struct 定义（默认 public），成员 `first` 是键、`second` 是值；遍历时 `it->first` / `it->second`，与有序 map 完全相同。查重语义也相同：单重 map 对重复键的第二次 insert 静默失败（size 不变），multimap 照存。

`operator[]` 的插入副作用**原样继承**（上一篇刚讲过）：键不存在时插入 `k + V()` 并返回引用。这个"坑"在下一节的实战里会摇身变成"利器"。

## 3. 实战一：海量数据查重并统计次数

题目：10 万个整数（范围 1~1 万）中，找出**重复的数字**并统计每个重复了几次。

思路先想清楚再动手：数字是"键"，出现次数是"值"——这正是一张 `unordered_map<int, int>`。扫描数组，每个数查一下哈希表：没见过就插入（次数记 1），见过就给次数 +1。最后遍历表，`second > 1` 的就是重复数字。

先看"笨"写法（find + 分支），它把逻辑摊开了：

```cpp
unordered_map<int, int> m;
for (int v : arr)
{
    auto it = m.find(v);
    if (it == m.end())
        m.insert({ v, 1 });          // 第一次出现：插入，次数 1
    else
        ++it->second;                // 出现过：次数 +1
}

for (const auto& p : m)             // 注意 const auto&：只读遍历用常引用
    if (p.second > 1)
        cout << p.first << " 出现 " << p.second << " 次" << endl;
```

熟悉 `[]` 副作用后，循环体可以压成一行：

```cpp
for (int v : arr)
    ++m[v];                          // 不存在→插入并得 0，++得 1；存在→返回引用 ++
```

`m[v]` 三合一：查询、（不存在时）插入、返回值引用——副作用在这里正好是想要的行为。这就是上一篇那句"用对地方就是利器"的兑现现场。

两个细节。**遍历用 `const auto&` 而不是 `auto&`**：range-for 拿容器元素，普通引用意味着"可能改容器"，map 迭代指向的是 const 键的 pair，非 const 引用直接编译失败——第 13 篇的 const 守则又一次现形。**为什么选 unordered 而不是 map**：这道题只要快、不要有序，10 万次查询 × O(1) 与 O(log n) 的差距在大数据下非常可观；若题目要求"按数字大小输出重复情况"，才轮到红黑树系。

## 4. 实战二：海量数据去重

题目：同一批数据，把**去重后的数字**打印出来（重复的只输出一次）。

这次不需要次数，只要"见过没"——**键就够了，`unordered_set` 而不是 map**：

```cpp
unordered_set<int> s;
for (int v : arr)
    s.insert(v);                     // 单重集合：重复值自动不落库

for (const auto& k : s)
    cout << k << " ";                // 输出的就是去重后的集合
```

`insert` 的"存在即忽略"语义替我们完成了全部判断，代码量归零。整体复杂度 O(n)——每个元素一次常数时间的哈希插入，与数据总量线性相关，远优于朴素的双层循环比较（O(n²)）。

**set 还是 map 的选择判据**也在这两题里显形：只需要"出现过没有"→ set（只存键）；要附带属性（出现次数）→ map（键 + 值）。

## 5. 与红黑树族的选择表

两族接口一致，选择全看需求里有没有"顺序"：

| | unordered_*（哈希表） | set/map（红黑树） |
|---|---|---|
| 增删查 | 接近 O(1) | O(log₂n) |
| 遍历输出 | 乱序 | 按键升序 |
| 范围查询 | ✗（无顺序语义） | ✓ lower_bound/upper_bound |
| 典型场景 | 查重、去重、计数、缓存 | 排行榜、区间统计、有序遍历 |

一句话总结：**哈希表的主场是"海量数据 + 只关心存在性/计数"；一旦题目里出现"有序""前 K 大（按序输出）""区间"，切回红黑树族。**第 36 篇 TopK 用的是堆（priority_queue），第 37 篇的有序遍历靠中序——每种结构都有它无法被 O(1) 收买的独门能力。

## 小结

- 无序族 = 有序族类名加 `unordered_` 前缀：接口一致，底层链式哈希表，增删查接近 O(1)，遍历乱序、无范围查询
- insert 不给位置（哈希函数决定落桶）；map 键值对用 `make_pair` 或大括号打包成 pair；`[]` 的插入副作用原样继承
- 查重实战：`++m[v]` 一行顶三行——[] 的副作用在计数场景就是正确语义；遍历用 `const auto&`
- 去重实战：单重 set 的"存在即忽略" insert 免费完成去重，整体 O(n)
- set 还是 map：只要存在性→set；要附带属性→map
- 与红黑树族的选择：出现"有序/区间/按序输出"切红黑树，纯快取需求用哈希
