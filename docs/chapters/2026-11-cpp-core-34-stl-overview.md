# STL 六大组件：标准模板库的全景地图

![STL 六大组件全景：容器、适配器、迭代器、算法、函数对象、配置器的分工与协作](/assets/images/cpp-core/cpp-core-34-stl-overview.png)

STL（Standard Template Library，标准模板库）是 C++ 的 top3 重要模块。这三个词各有含义：**标准**——随编译器安装的官方库，Windows、Mac、Linux 都带着它，`#include` 即用；**模板**——容器和算法全是模板实现，想处理什么类型，拿什么类型实例化；**库**——一套经过千锤百炼的数据结构与算法。

有趣的是，你其实已经亲手造过半个 STL 了：第 20 篇的 vector、第 23 篇的迭代器、第 19 篇的 allocator、第 17~18 篇的模板技术。这篇把全景地图铺开——六大组件各是什么、一句话定位、复杂度几何——后面的文章按图索骥逐个攻占。

边界：本篇是地图不是细节；每个组件的完整机制在各自篇章展开，文末给出对应关系表。

## 1. 六大组件：一张地图

STL 由六个部分协作而成，先记住每个组件的**一句话定位**：

| 组件 | 一句话定位 | 代表 |
|---|---|---|
| **容器**（container） | 装数据的各种数据结构 | vector、deque、list、set、map |
| **容器适配器**（adapter） | 借别的容器改头换面的"接口类" | stack、queue、priority_queue |
| **迭代器**（iterator） | 统一遍历容器的胶水（第 23 篇手写过） | `vector<int>::iterator` |
| **泛型算法**（algorithm） | 服务所有容器的全局函数 | sort、find、reverse |
| **函数对象**（仿函数） | 行为像函数的对象，算法的策略参数 | less、greater |
| **空间配置器**（allocator） | 容器的内存管家（第 19 篇手写过） | `std::allocator<T>` |

协作关系第 30 篇已经演示过一次：算法（sort）拿着迭代器（begin/end）操作容器（vector），排序规则由函数对象提供（less），内存由配置器管理。**六件套各司其职，靠迭代器把"存"与"算"解耦**——这套架构正是 STL 的精髓。

## 2. 容器家族：三分天下

容器是最大的一块，按底层数据结构分三支：

**顺序容器**：元素排成一条线，底层是线性表。`vector`（向量，动态数组，前面手写过）、`deque`（双端队列，两端都能 O(1) 增删）、`list`（链表）。名字即结构。

**关联容器**：按"键-值"组织，底层是高级数据结构，分两族——

- **有序关联容器**：底层**红黑树**，元素按键排序，增删查 **O(log₂n)**。set / multiset（单重/多重集合）、map / multimap（单重/多重映射表）。"单重"键唯一，"多重"允许键重复。
- **无序关联容器**（C++11）：底层**链式哈希表**，不排序、只求快，增删查**接近 O(1)**。unordered_set / unordered_multiset / unordered_map / unordered_multimap。

选择口诀顺着复杂度走：**要快且不关心顺序 → unordered；要有序遍历/范围查找 → 红黑树系；只要尾部进出 → vector/deque；中间频繁插删 → list。**

**近容器**：长得像容器但没纳入标准容器编制的几个——`string`（字符容器，第 16 篇手写过四件套）、`array`（C++11 定长数组）、`forward_list`（C++11 单向链表）、`bitset`（位容器，位图法查重、哈夫曼编码都用得上）。

## 3. 复杂度速查表

选容器的本质是选复杂度。一张表带走：

| 操作 | vector | deque | list | 红黑树系 | 哈希系 |
|---|---|---|---|---|---|
| 随机访问 `[]` | **O(1)** | O(1) | O(n) | O(log n) | O(1) 均摊 |
| 末尾插删 | O(1) 均摊 | O(1) | O(1) | — | — |
| 中间插删 | O(n) | O(n) | **O(1)** | O(log n) | O(1) 均摊 |
| 查找 | O(n) | O(n) | O(n) | O(log n) | **O(1) 均摊** |

vector 的中间插删 O(n) 来自元素搬移（第 20 篇的扩容搬家是它的极端形态）；list 的 O(1) 插删是链表指针拨动的天赋，代价是永远无法随机访问（第 23 篇讲过它不提供 `[]` 的原因）。两头的甜头不能都占——**选容器就是选你愿意付出的代价**。

## 小结

- STL = 标准（随编译器安装、跨平台）+ 模板（类型实例化）+ 库（数据结构与算法）
- 六大组件各司其职：容器装数据、适配器换接口、迭代器当胶水、算法做计算、函数对象定策略、配置器管内存
- 容器三分：顺序容器（vector/deque/list）、关联容器（红黑树系有序 O(log n)、哈希系无序 O(1)）、近容器（string/array/forward_list/bitset）
- 复杂度速查：vector 随机 O(1) 中间插删 O(n)；list 插删 O(1) 无随机访问；哈希查快无序；红黑树有序 log——选容器就是选代价
- 手写过的轮子已覆盖半个 STL；剩下五篇补齐序列容器、适配器、两类关联容器、函数对象、泛型算法
