# const 修饰谁：同一个关键字，C 和 C++ 把它编译成两种东西

![C 与 C++ 对 const 的两种编译方式：C 按变量处理，C++ 编译期替换成初始值](/assets/images/cpp-core/cpp-core-05-const.png)

有一道笔试题我见过很多次。四行代码，先在纸上写答案，再上机验证：

```cpp
const int a = 20;
int* p = (int*)&a;
*p = 30;
printf("%d %d %d", a, *p, *&a);
```

一大半人会写 `20 30 30`，理由是"内存被改成 30 了，读哪儿都是 30"。上机跑一遍，MSVC 的输出是 `20 30 20`。三个表达式访问的是同一块内存，打印出来却是两个值。

这不是玄学，是 C 和 C++ 对同一个关键字采用了**两种完全不同的编译方式**。这篇文章把这件事讲透：`const` 到底修饰谁、C 为什么把它当变量、C++ 为什么把它替换成数字，以及什么时候"常量"会退化回"常变量"。

先划边界。本文只讨论 `const` 修饰**普通整型变量**的情况；`const` 与一、二级指针的结合是下一篇的主题，函数参数与返回值里的 `const` 也不在本文范围。文中输出以 32 位 MSVC 为准，其他编译器在末尾有说明。

## 1. 最初的理解：const 修饰的量不能作左值

例. 最朴素的认识来自赋值语句。

```cpp
int a = 10;
a = 20;             // 可以，a 作为左值被写入

const int b = 10;
b = 20;             // 编译错误
```

解. `b = 20` 这个写法里，`b` 出现在赋值号左边，叫**左值**（lvalue）——意思是"这块内存可以被写入"。`const` 加进去之后，编译器直接拒绝这个语句。

这就是每个人第一次学 `const` 时得到的答案：**`const` 修饰的量不能再作为左值，初始化之后不能通过它的名字修改。**

但注意这句话的措辞。"不能通过它的名字修改"不等于"这块内存改不了"。内存就摆在那儿，指针、汇编、调试器都能写它。`const` 是一条**语法层面的约束**，只管"你写 `b = 20` 我不让你过"，不管内存本身。

这个区别在后面会变成分数：笔试题考的正是"语法约束"和"内存状态"分开判断。

## 2. C 语言：const 修饰的是"常变量"

把上面的认识放进 `.c` 文件，逐条验证 C 语言的态度。

第一件事，`const` 变量不初始化会怎样？

```c
const int a;        /* C：编译通过，顶多一条"未使用变量"的警告 */
```

C 编译器放行了。因为在它眼里 `a` 就是个变量——只是不能作左值而已。变量不初始化本来就不算错误，读它才是未定义行为。

第二件事，能用它定义数组长度吗？

```c
const int n = 10;
int arr[n];         /* MSVC 报错：表达式必须含有常量值 */
```

报错。数组长度要求**常量表达式**（constant expression），而 C 语言认定 `n` 是变量——只是个"不能作左值的变量"，习惯上叫它**常变量**（constant variable）。变量不是常量，这一步 C 态度很明确。

第三件事最关键：那块内存到底能不能改？

```c
const int a = 20;
int* p = (int*)&a;
*p = 30;
printf("%d %d %d", a, *p, *&a);
```

编译运行，输出 `30 30 30`。

三个表达式，访问的都是 `a` 那块内存。`*p = 30` 把内存真改成了 30，之后不管你用名字 `a`、解引用 `*p`、还是先取地址再解引用 `*&a`，读到的都是内存里的 30。C 的世界里没有意外：**名字和内存是绑定的，改了内存，所有名字跟着变。**

顺带说一句，`(int*)&a` 这个强转在这里是必须的：`&a` 的类型是 `const int*`，直接赋给 `int*` 会被编译器拦下。C 语言里可以不写强转只吃一条警告，C++ 里必须写。强转本身不产生任何指令，只是告诉编译器"别管了"。

## 3. C++：const 是常量，编译期替换

把一模一样的代码搬进 `.cpp` 文件。三件事立刻变脸。

第一，不初始化直接报错：

```cpp
const int a;        // C++：错误，必须初始化
```

第二，可以定义数组了：

```cpp
const int n = 10;
int arr[n];         // C++：通过
```

第三，刚才那段"改内存"的代码，输出变成 `20 30 20`。

第一行打印 20？内存里明明是 30。要解释这三行，得看 C++ 编译器对 `const` 的处理方式：

> **C++ 中，所有出现 const 常量名字的地方，在编译阶段都被替换成它的初始值。**

`a` 不是"一个放在内存里的数"，更像一个**带名字的字面量**（类似 C 里 `#define N 10` 的加强版）。编译器在编译期扫描代码，见到 `a` 就抄一个 20 进去：

- `printf` 里的 `a` 被替换成 20——它根本没去读内存，打印的是编译期抄进去的字面量；
- `*p` 是真正的解引用，走内存，读到 30；
- `*&a` 取地址再解引用，绕了一圈等价于访问 `a` 本身，编译器折叠之后照样替换成 20。

内存里那 4 个字节**确实被改成 30 了**——打个断点看内存窗口就能确认。但 `printf` 压根没看那块内存，它打印的是编译期就定死的数字。这回开头那道题的答案齐了：`20 30 20`，三个值两个来源。

![同一块内存被改成 30 后：C 的名字读内存打印 30 30 30，C++ 的名字被替换打印 20 30 20](/assets/images/cpp-core/cpp-core-05-const-flow.gif)

还有一件事现在能解释了：C++ 为什么强制 `const` 必须初始化？因为要替换。初始值都没有，编译器见到名字拿什么抄？C 语言没有替换这回事，所以不初始化也无所谓。

> **边界：** 标准层面，通过强转修改 `const` 对象属于未定义行为。MSVC 在常量折叠下给出 `20 30 20`，GCC/Clang 开优化后行为类似；关掉优化的其他编译器可能读内存、打印 `20 30 30`。笔试按 MSVC 的行为答，工程里永远别写这种代码。

## 4. 退化：用变量初始化，常量退回常变量

C++ 的"编译期替换"有一个前提：**初始值在编译期可见**。破坏这个前提，常量就打回原形。

```cpp
int b = 20;             // b 是普通变量，运行时才有值
const int a = b;        // 用变量初始化 const
```

`a` 的初始值是 `b`，而 `b` 的值要到运行时才知道。编译期替换无从谈起，于是 `a` **退化成常变量**——和 C 语言里那个一模一样：

```cpp
int arr[a];             // 错误，a 又不是常量表达式了

int* p = (int*)&b_addr_of_a;
*p = 30;
printf("%d %d %d", a, *p, *&a);   // 30 30 30，和 C 的输出完全一致
```

替换没有了，名字和内存重新绑定。C++ 判断一条 `const` 是"常量"还是"常变量"，就看初始值：**初始值是立即数，是常量，参与替换；初始值是变量，是常变量，按普通变量编译。**

这也是笔试里的一条隐藏判据：看到 `const int a = b;` 就要意识到后面的数组定义、`case` 标签、模板实参全都用不了 `a`——这些位置都要常量表达式。

## 5. 两句话带走这道题

把 C 和 C++ 的分野压成一张对照表：

| | C | C++（初始值为立即数） |
|---|---|---|
| 身份 | 常变量 | 常量 |
| 不初始化 | 编译通过 | 报错 |
| 定义数组长度 | 不行 | 行 |
| 编译方式 | 按变量生成代码 | 名字出现处替换为初始值 |
| 改内存后打印名字 | 新值 | 初始值（没读内存） |

判断笔试题时记两句话。第一句：**内存改没改，是运行时的事**——通过指针写，内存一定变。第二句：**打印值是多少，是编译方式的事**——C++ 里名字可能根本不对应那次内存读取。两件事分开判断，这道题就不会再错。

## 小结

- `const` 修饰的量不能作左值，这是它在两种语言里唯一的共同点
- C 里它是常变量：可不初始化、不能定数组、按变量编译，改内存后所有访问看到新值
- C++ 里初始值为立即数时它是常量：必须初始化、能定数组，出现名字的地方编译期替换成初始值
- 替换解释了 `20 30 20`：名字被替换、解引用走内存、`*&a` 折叠后照样替换
- 用变量初始化的 const 退化为常变量，行为与 C 完全一致
- 判断笔试题：内存状态看运行时，打印值看编译方式，两件事分开
