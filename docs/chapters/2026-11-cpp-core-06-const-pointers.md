# const 与一、二级指针：两条公式判断所有对错

![const 与一、二级指针结合的全部情况：一级两种、二级三种，转换公式与泄露路径](/assets/images/cpp-core/cpp-core-06-const-pointers.png)

面试里有一道经典坑题。面试官先让你看三行代码：

```cpp
int a = 10;
const int* p = &a;
int* q = p;          // 这行能编译过吗？
```

你答"不能，`const int*` 不能转 `int*`"。面试官点点头，开始往坑里引："`p` 里放的是不是 `a` 的地址？`a` 是不是普通变量、随便可以改？那 `q` 拿到 `a` 的地址有什么错？"

很多人到这里就懵了：是啊，`a` 又不是常量，凭什么不让转？

这篇文章把 `const` 和一、二级指针结合的所有情况讲完，最后你会拿两条公式回答这道题——而且能说清"为什么跟 `a` 没关系"。

边界先划好。本文只讨论 `const` 修饰指针的表达式，`const` 与引用的结合是下一篇的内容；32 位系统下指针占 4 字节这个前提沿用上一篇。

## 1. 两条红线：常量仅有的两种错误

`const` 修饰的量（就叫它常量）在 C++ 里只有两条红线，后面所有讨论都从这两条推出来。

**第一条：常量不能作左值。** `a = 20` 直接被编译器拒绝，上一篇讲过。

**第二条：常量的地址不能泄露给普通指针或普通引用。**

```cpp
const int a = 20;
int* p = &a;         // 错误：const int* → int*
```

为什么拦这一步？因为普通指针解引用不受约束，`*p = 30` 合法。一旦放行，常量的内存就被间接改掉了——第一条红线被绕过。编译器把"泄露地址"这个入口堵死，常量才算真正常。

这两条红线是编译器检查 `const` 代码的全部依据。接下来所有"能转、不能转"的判断，都是在回答同一个问题：**这样转，会不会造成泄露？**

## 2. const 与一级指针：只有两种情况

`const` 和一级指针结合，写法看着很多，实质只有两种，判据是 **`const` 修饰的是哪个表达式**。

第一种，`const` 修饰 `*p`（指针的指向）：

```cpp
const int* p = &a;       // 或写作 int const* p，完全等价
*p = 30;                 // 错误：*p 被 const 修饰，不能作左值
p = &b;                  // 正确：p 本身没被修饰
```

`const` 离 `int` 最近，修饰的表达式是 `*p`。效果：指针可以随便换指向，但不许通过它改指向的那块内存。`int const* p` 和 `const int* p` 是同一种——`*` 不可能单独作类型，两种写法里 `const` 最近的类型都是 `int`，修饰的都是 `*p`。

第二种，`const` 修饰 `p`（指针本身）：

```cpp
int* const p = &a;       // const 离 p 近，修饰 p 本身
*p = 30;                 // 正确：*p 没被修饰
p = &b;                  // 错误：p 是常量，不能作左值
```

效果与第一种正好互补：指针钉死在一块内存上，但那块内存可以随便改。

两种叠加 `const int* const p`，指向和本身都锁死。判别口诀就一句：**看 `const` 右边离着什么**——右边是类型（`int`），它修饰指向；右边直接是 `p`，它修饰指针本身。

## 3. 两条转换公式

一级指针之间的类型转换，只需背两条：

> **`int*` → `const int*`：正确。**
> **`const int*` → `int*`：错误。**

道理还是那两条红线。`int*` 转 `const int*`，是把约束加强——原来能写的现在不能写了，编译器放心。反方向是把"承诺不写"的东西交给一个"随时能写"的指针，一旦转过去，`*q = 30` 就绕过了 `const`，这就是泄露。

普通变量那边也一样对称：`int* → const int*` 允许（普通变量的地址给 const 指针，没问题），`const int* → int*` 拒绝。

## 4. const 什么时候参与类型

这里藏着最容易踩的一个误区。看这个声明：

```cpp
int* const q = &p;       // q 的类型是什么？
```

答案不是 `int* const`，是 **`int*`**。可以用 `typeid(q).name()` 验证，打出来就是 `int *`。

规则是：

> **`const` 右边如果没有指针（没有 `*`），这个 `const` 不参与类型。**

`int* const q` 里，`const` 右边只有变量名 `q`，没有 `*`，所以它不参与类型——`q` 的类型就是 `int*`。那这个 `const` 干了什么？它只做一件事：宣布 `q` 是常量，不能作左值、地址不能泄露给更松的类型。类型系统看它，和看一个普通 `int*` 没有区别。

反过来，`const int* p` 里 `const` 右边有 `*`，它就参与类型——`p` 的类型真是 `const int*`，和 `int*` 是两种类型，转换才要按公式检查。

这条规则直接决定你分析第三行代码对错时，要不要把某个 `const` 算进类型里。算错一步，结论就反。

## 5. 拆掉那道面试坑题

现在回到开头的题目。逐行过一遍：

```cpp
int a = 10;              // a: int
const int* p = &a;       // int* → const int*，公式说正确
int* q = p;              // const int* → int*，公式说错误
```

第一行转换 `int*` → `const int*`，约束加强，正确。

第三行是 `const int*` → `int*`，公式直接判错。

面试官的引导是"`p` 里明明是普通变量 `a` 的地址"。注意编译器不看这个：**编译器看的是 `p` 的声明类型**。声明成 `const int*`，编译器就认定 `p` 里放的是"整形常量的地址"——至于运行时那块内存实际是不是常量，编译器不管。类型系统只认声明，不认运行时的事实。所以这题从头到尾和 `a` 没有关系：就算把 `a` 换成一个真正的 `const int`，结论一字不变。

把 `a` 是否可变搅进来，是这道题的全部迷惑性所在。答题时一句话顶回去："转换对错由静态类型决定，`const int*` 转 `int*` 就是泄露路径，编译器按声明拒绝。"

## 6. 推广到二级指针：三种情况，一个新规则

二级指针 `q` 能写的表达式有三个：`q`、`*q`、`**q`。`const` 依次修饰它们，就是三种情况：

```cpp
const int** q;       // 修饰 **q：最终指向的内存不许改
int* const* q;       // 修饰 *q：中间那层一级指针不许换
int** const q;       // 修饰 q：q 本身不许换
```

判别方法和一级完全相同：找 `const` 最近的类型，它修饰"从那个类型往左展开出来的表达式"。

但转换规则在这里变严了。一级的两条公式，到二级变成了：

> **`const` 与二级（及更多级）指针结合时，两边必须都有 `const`，少一边都错。**

```cpp
int a = 10;
int* p = &a;

const int** q = &p;      // 错误：int** → const int**，右边少了……不对，是左边引入 const 右边没有
int** const q2 = &p;     // 正确：const 右边没星，不参与类型，实为 int** → int**
```

第一行为什么错？一级那条"`int*` → `const int*` 正确"的直觉在这里失效。原因值得完整推一遍，它是全文最有价值的三段推理：

假设 `const int** q = &p;` 合法。那么 `*q` 和 `p` 是**同一块内存**（`q` 存的就是 `p` 的地址）。

`*q` 的类型是 `const int*`，按定义它可以接收常量地址：

```cpp
const int b = 20;
*q = &b;                 // 类型完全匹配，放行
```

`*q` 就是 `p`。这一句之后，普通指针 `p` 里躺着**常量 `b` 的地址**——第二条红线已经被穿透。接下来 `*p = 100` 修改常量，没人拦得住。

编译器在第一行就掐断这个链条，所以 `int**` → `const int**` 一律报错。一级指针没这个问题，是因为一级没有"中间层"可以借道。

修法有两种，思路都是堵泄露口：

```cpp
// 法一：把中间层也变成 const int*，让两边类型对齐
const int* p = &a;
const int** q = &p;      // 正确

// 法二：锁死 *q，让它收不了新地址
int* const* q = &p;      // 正确：*q 不能作左值，常量地址塞不进来
```

`int* const* q` 这一行里，`const` 修饰的表达式是 `*q`，相当于把"那层一级指针"按一级公式锁住——这就是授课老师说的"`const` 跟几级指针结合，把前面整体类型当一个大类型剥掉一层看"：剥掉一层，`int* const*` 里剩下的正是 `int* → const int*` 的一级情形，公式判定正确。

## 小结

- 常量只有两条红线：不能作左值；地址不能泄露给普通指针或引用
- `const` 与一级指针两种情况：修饰指向（`const int*`）则指向不可改、指针可换；修饰本身（`int* const`）则指针不可换、指向可改
- 一级转换两条公式：`int*` → `const int*` 对，反方向错
- `const` 右边没有 `*` 就不参与类型：`int* const q` 的类型是 `int*`，`const` 只负责宣布"q 是常量"
- 面试坑题与 `a` 无关：编译器只看声明类型，`const int*` 转 `int*` 就是泄露路径
- 二级指针三种情况；多级转换两边必须有 `const`，错误根源是 `*q = &b` 可以借中间层把常量地址塞进普通指针
