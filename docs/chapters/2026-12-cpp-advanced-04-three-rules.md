# 三条对象优化规则：11 次调用怎么压到 4 次

![三条规则递减：按引用传参(11→9)、返回临时对象(9→7)、初始化接收(7→4)](/assets/images/cpp-advanced/cpp-advanced-04-three-rules.png)

上一篇的 getString 案例里，四五行代码背后跑了 11 次函数调用。移动语义（02、03 篇）解决的是"类内部怎么写"；这一篇的三条规则更轻——**不改类定义，只改调用方写法**，就能把 11 次压到 4 次。

三条规则每条都对应一笔明确的节省，叠起来是完整的优化链。它们也是笔试"给四件套打印、写调用顺序"这类题的判题标尺——按正常分析走，每碰到规则触发点就优化一步。

边界：规则描述以"返回值是对象的函数"为场景；编译器优化（临时对象拷贝构造新对象不产生，第 01 篇）是规则生效的前提，规则本身是写法约定。

## 1. 规则一：对象传参，按引用不按值

> **函数参数传递过程中，对象优先按引用传递，不要按值传递。**

按值传递的代价清单（第 01 篇拆过）：实参拷贝构造形参一次，函数结束析构形参一次——**两次函数调用凭空多出**。按引用传递底层就是传地址（第 07 篇：引用是更安全的指针），形参不诞生新对象，这两次直接消失。

```cpp
Test getObject(Test t)          // ✗ 按值：+拷贝构造 +析构
Test getObject(const Test& t)   // ✓ 按引用：零新对象
```

11 → 9。省两下看着不多，乘以调用频率就是可观的账——高频调用的接口（每帧调用的渲染函数、循环体里的处理函数）里，这两次是纯税。加 `const` 还顺手拿到第 13 篇守则：普通对象、常对象都能调。

## 2. 规则二：返回对象，优先返回临时对象

> **当函数返回对象时，优先返回一个临时对象，而不要返回一个定义过的对象。**

两种返回写法的差距藏在"tmp 的生死"里：

```cpp
// 写法 A：先定义再返回
Test getObject(const Test& t)
{
    Test tmp(t.getData());      // 构造 tmp
    return tmp;                 // 拷贝构造 main 栈帧临时对象
}                               // 析构 tmp ← 定义过的对象必须析构

// 写法 B：直接返回临时对象
Test getObject(const Test& t)
{
    return Test(t.getData());   // return 处直接构造
}
```

写法 A 里 `tmp` 是有名对象，出函数必析构；`return tmp` 时"用**已存在的对象**拷贝构造新对象"，main 栈帧临时对象照常产生——构造 tmp、拷贝构造临时对象、析构 tmp，三步走完。

写法 B 里 return 的是**临时对象**，触发第 01 篇那条全平台优化——"用临时对象拷贝构造新对象，临时对象不产生"。main 栈帧上那个"接收返回值的临时对象"与 return 的临时对象**合二为一**：直接在 main 栈帧按参数构造最终对象。函数内零对象诞生、零析构。

9 → 7，省掉 tmp 的构造与析构。写法指引也顺出来了：**把构造函数需要的参数先算好，return 处直接 `return Test(参数)`，别先定义对象再改它成员再返回**。

## 3. 规则三：接收返回值，按初始化不按赋值

> **接收返回值是对象的函数调用时，优先按初始化的方式接收，不要先定义对象再以赋值的方式接收。**

```cpp
Test t2(5);
t2 = getObject(t1);        // 写法 C：赋值接收

Test t2 = getObject(t1);   // 写法 D：初始化接收
```

写法 C 里 `t2` 已存在，函数返回的对象必须**先生成**（赋值需要实物，第 01 篇），赋完即析构——临时对象的构造 + 析构两笔账在。

写法 D 里 `t2` 正在定义，链条变成"**用临时对象拷贝构造 t2**"——优化再次触发：临时对象不产生，`getObject` 的返回值**直接构造进 t2 的内存**。实现机制也值得一提：调用 `getObject` 时，编译器把 t2 的地址压进栈帧，函数内部"直接构造最终对象"时用的正是这个地址——从构造那一刻起，对象就住在 t2 的家里，没有中转。

7 → 4。最后剩四次：构造 t1、构造 t2、析构 t2、析构 t1——两个真实对象的一生，一次多余的调用都没有。

## 4. 三条规则的合龙

11 → 9 → 7 → 4 的每一步都对应一条规则，合起来看它的逻辑结构：

| 规则 | 省掉的调用 | 作用位置 |
|---|---|---|
| ① 按引用传参 | 形参拷贝构造 + 析构 | 函数接口层 |
| ② 返回临时对象 | tmp 构造 + 析构（临时对象合并） | 函数返回层 |
| ③ 初始化接收 | 接收用临时对象构造 + 析构（对象直构进 t2） | 调用接收层 |

三层各自独立、效果叠加：接口不造中间对象，返回不造中转对象，接收不造中转对象——**整条链上除了两个真实对象（t1、t2），没有任何中间产物**。配合第 02、03 篇的移动语义（万一中间产物因编译器或写法原因没被合并，移动构造把深拷贝变指针接力），对象优化的完整拼图就齐了。

笔试题的应答姿势也由此定型：拿到"写打印顺序"的题，先按正常对象语义逐步分析（每步调什么函数），**每碰到"用临时对象拷贝构造新对象"就触发优化合并**——两套思维（正常分析 + 优化触发）叠加，打印序列不会错。

## 小结

- 规则一：对象传参按引用（`const T&`）——省形参拷贝构造与析构；11 → 9
- 规则二：返回对象优先 `return Test(参数)` 直接返回临时对象——"用临时对象拷贝构造新对象"的优化让临时对象与接收对象合一；9 → 7
- 规则三：接收按 `Test t2 = getObject(t1);` 初始化写法——返回值直接构造进 t2 内存（t2 地址压栈传入）；7 → 4
- 三层独立叠加：接口、返回、接收全链无中间对象；最终只剩真实对象的构造与析构
- 与移动语义的关系：规则消灭中间产物，移动语义兜底未合并场景的深拷贝——双保险
- 笔试姿势：正常分析逐步走 + 优化触发点合并，打印序列必对

C++ 写得慢不是语言的锅，是不懂对象背后账本的锅。三条规则 + 移动语义，就是这本账的核销单。
