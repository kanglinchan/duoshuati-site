# 指向类成员的指针：多一个类作用域，多一个 .*

![指向类成员的指针四象限：普通/静态 × 变量/方法，指针类型与解引用语法对照](/assets/images/cpp-core/cpp-core-15-member-pointers.png)

写 `int* p = &t.ma;` 想拿个指针指成员变量，编译器报错里冒出一个没见过的类型：`int Test::*`。再往后读泛型代码，又撞上 `(obj.*pfunc)()` 这种星号满天飞的调用。这些都是同一套东西——**指向类成员的指针**。

它和普通指针的差别就两条：定义时多一个**类作用域**（`Test::`），使用时多一个专用符号（`.*` 或 `->*`）。这篇把"普通/静态 × 变量/方法"四个象限一次列全，以后在绑定器、`function` 那些高级场合见到它们时能对上号。

边界：本文是基础篇——这组指针的真正主场在泛型编程里（用成员指针推导返回值与形参类型），那里用到时你只需要"认识"；`.*` 的运算符重载细节也不涉及。

## 1. 为什么普通指针指不了成员变量

例. 先看直觉写法为什么错：

```cpp
class Test
{
public:
    int ma;
    void func() { }
};

Test t;
int* p = &t.ma;          // 错误：无法从 "int Test::*" 转换到 "int*"
```

解. 报错里的类型名就是答案。`ma` 不是全局的 `int`，是 **Test 类作用域里的 int**——编译器给它的类型是 `int Test::*`，跟裸的 `int*` 是两种类型，转换被拒绝。

背后的语义障碍更值得想一遍：**脱离对象谈论普通成员，没有意义**。`Test` 是"人"，`ma` 是"年龄"——"指向年龄的指针"指向谁的性格年龄？普通成员变量挂在对象身上，谈它必须连着对象谈。指针类型里的 `Test::` 就是在把这个前提钉死：这是一根"指向 Test 类成员"的指针，光有它还不行，用的时候必须补上对象。

## 2. 正确姿势：定义、解引用、两个专用符号

定义时加类作用域：

```cpp
int Test::* p = &Test::ma;      // 注意：&Test::ma，不是 &t.ma
```

注意取的是**类的成员**（`&Test::ma`），不是某个对象的成员——这根指针描述的是"Test 里的那个 int"这个位置，跟任何具体对象无关。可以把它理解为"成员在对象内的相对位置"而非绝对地址，对象在解引用那一刻才补进来。

解引用需要对象，C++ 为此准备了两对专用符号：对象用 `.*`，对象指针用 `->*`：

```cpp
Test t1;                        // 栈上对象
t1.*p = 20;                     // 通过对象解引用：等价于 t1.ma = 20

Test* pt = new Test();          // 堆上对象
pt->*p = 30;                    // 通过对象指针解引用
delete pt;
```

`t1.*p` 读作"t1 里的 p 所指的那个成员"。普通指针解引用一步到位（`*p`），成员指针解引用要多喂一个对象——这正是"成员离不开对象"在语法上的体现。

> **边界：** 顺带一条工程规范：堆对象的开辟释放，C++ 代码里统一 `new`/`delete` 配对，不要和 `malloc`/`free` 混搭（对象必须走析构，第 11 篇讲过 `free` 会跳过它）。混用不见得立刻报错，但读代码的人会分不清这是 C 还是 C++。

## 3. 静态成员变量：普通指针就够了

`static` 成员变量是另一种情况。它不依赖对象（第 13 篇的结论：类级别的全局变量），所以普通指针直接可用：

```cpp
class Test
{
public:
    static int mb;              // 类内声明
};
int Test::mb = 10;              // 类外定义，别忘了（第 13 篇的坑）

int* p2 = &Test::mb;            // 普通指针，没有 Test:: 前缀
*p2 = 40;                       // 解引用也不需要对象
```

定义不用 `int Test::*`，解引用不用 `.*`——静态成员变量跟全局变量只差一个类作用域外壳，指针层面完全退化为普通指针。

## 4. 指向成员方法的指针

成员方法同理，而且语法更繁一点。普通函数指针指不了成员方法：

```cpp
void (*pf)() = &Test::func;     // 错误：普通函数指针（cdecl）≠ 成员函数指针
```

报错说明两者是不同类型——成员方法指针的类型里也带类作用域：

```cpp
void (Test::*pf)() = &Test::func;    // 指向"返回 void、无参"的 Test 成员方法

(t1.*pf)();                          // 通过对象调用
(pt->*pf)();                         // 通过对象指针调用
```

调用必须通过对象，原因还是那个 `this`：普通成员方法编译后多一个 `this` 形参（第 10 篇），不管直接调还是间接调，都得有对象地址可传。`(t1.*pf)()` 里的括号不能省——`.*` 的优先级低于函数调用，裸写 `t1.*pf()` 会被解析成 `t1.*(pf())`，直接编译错误。

静态成员方法则再次退回普通情况：没有 `this`、不依赖对象（第 13 篇），用**普通函数指针**接它即可，调用也不带对象。

## 5. 四象限总结

把两维交叉，一张表收拢：

| | 普通成员 | 静态成员 |
|---|---|---|
| **变量** | `int Test::*p = &Test::ma;` 解引用 `t.*p` / `pt->*p` | `int* p = &Test::mb;` 普通指针 |
| **方法** | `void (Test::*pf)() = &Test::func;` 调用 `(t.*pf)()` | `void (*pf)() = &Test::sfunc;` 普通函数指针 |

规律压成两句话：

- **普通的成员**（变量、方法）指针：类型带 `Test::`，使用带 `.*` / `->*`，永远连着对象——因为普通成员的语义离不开对象（变量挂对象身上，方法有 `this`）；
- **静态的成员**指针：完全退化为普通指针——静态成员本来就是"住在类作用域里的全局成员"，第 13 篇说过它不依赖对象。

看不懂第三方库里 `.*`、`->*` 的代码时，回到这张表定位它属于哪个象限，语法自然读通。

## 小结

- 普通成员变量的指针类型是 `int Test::*`，与 `int*` 是两种类型；取址取 `&Test::ma`（类成员），不是 `&t.ma`
- 成员指针描述的是"类内位置"，对象在解引用时才补上——所以必须用 `t.*p` / `pt->*p` 连着对象用
- 静态成员变量不依赖对象：普通指针、普通解引用；类外定义那一句不能忘
- 普通成员方法的指针 `void (Test::*)()`，调用 `(t.*pf)()`，括号不能省；根源是 `this` 形参需要对象
- 静态成员方法用普通函数指针；四个象限的统一规律：普通成员连对象，静态成员是"类作用域里的全局成员"
- 这组指针在绑定器、`function` 等泛型场合是主角，届时用于推导成员方法的返回值与形参
