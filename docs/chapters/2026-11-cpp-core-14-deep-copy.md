# 深拷贝与浅拷贝：同一块堆内存的两次析构

![浅拷贝让两个对象的指针指向同一块堆内存，二次析构崩溃；深拷贝各自持有资源](/assets/images/cpp-core/cpp-core-14-deep-copy.png)

一个什么都没写的语句 `CSeqStack s2(s1);`——构造正常，运行正常，程序结束前轰然崩溃，崩在析构函数里。你没写析构逻辑错误，没越界，唯一的问题是：你没有写**拷贝构造函数**。

对象拷贝是 C++ 里事故率最高的一类问题，因为编译器会默默替你生成拷贝代码，而那份代码在做错事。这篇把浅拷贝的崩溃过程逐帧拆开，给出"什么时候浅拷贝会出事"的判据，再把拷贝构造与赋值重载的写法一次配齐。

边界：`operator=` 的完整运算符重载体系在第 25 篇展开，这里只把赋值当特例讲清；标准库里 `string`、`vector` 的内部用的正是这套机制。

## 1. 默认拷贝构造：一份看不见的内存拷贝

先看两个写法，它们完全等价：

```cpp
CSeqStack s1(10);
CSeqStack s2(s1);        // 写法一
CSeqStack s2 = s1;       // 写法二，与写法一无差
```

两者都是"**用已存在的对象构造新对象**"——这是初始化，不是赋值（第 5 节细说区别）。对象生成必调构造函数，这里调用的叫**拷贝构造函数**。

你没写过它，为什么能编译？编译器的补全规则（第 11 篇讲过一半）：你不提供任何构造函数，它生成空的默认构造和默认析构；你不提供**拷贝**构造函数，它生成**默认拷贝构造**——默认版本做的事是：把源对象的成员变量逐字节抄给新对象，一份朴素的内存拷贝。

对上一节的顺序栈，这份"抄写"抄了什么？三个成员变量：`top = -1`、`size = 10`，以及关键的——**指针 `pstack` 的值**。`s1.pstack` 里存着堆上那块数组的地址，抄给 `s2.pstack` 后，两个指针存的是同一个地址。

## 2. 崩溃逐帧回放

把内存图画出来（画图分析是这类题的标准解法）：

```text
栈区                                堆区
s1 { pstack ──┐
      top=-1  │──────→  [ int × 10 ]（s1 构造时 new 出来的数组）
      size=10 │
s2 { pstack ──┘   ←浅拷贝抄来的同一个地址
      top=-1
      size=10 }
```

程序结束时按逆序析构（第 11 篇）：先析构 `s2`——`delete[] pstack` 把堆上数组释放，`s2.pstack` 置空。这一步没崩，`s1` 的三个成员变量还好好的。然后析构 `s1`——它的 `pstack` 还指着那块已经被释放的内存，再 `delete[]` 一次：**同一块资源释放两次**，运行时堆管理器检测到损坏，崩溃。

浅拷贝的完整罪状就一条：**拷贝了指针的值，没拷贝指针指向的资源**，两个对象的指针从此指向同一块堆内存，析构时必然撞车。

## 3. 判据：对象有没有占用外部资源

浅拷贝不一定出错。商品类那三个成员变量（`char[20]`、`double`、`int`）做默认拷贝构造，一切正常——数组虽然是数组，但它长在对象体内，不指向外部。

判据一句话：

> **对象持有"外部资源"（成员指针指向对象之外的堆内存），默认的浅拷贝才会出问题。**

看一个类的第一眼就该扫它的成员变量：有指针成员、且构造时 `new` 了内存，这个类的默认拷贝构造**必然**是错的，必须自己写深拷贝。这个判断要在写类的时候就做，而不是等崩溃后再查。

## 4. 深拷贝：让每个对象持有自己的资源

深拷贝的思路：不只抄指针的值，**给新对象单独开辟一份外部资源**，再把内容逐个抄过去：

```cpp
CSeqStack(const CSeqStack& src)     // 自定义拷贝构造函数
    : top(src.top), size(src.size)
{
    pstack = new int[src.size];     // 自己的堆内存
    for (int i = 0; i <= src.top; ++i)   // 注意 <=：top 从 -1 起算
        pstack[i] = src.pstack[i];
}
```

格式有两条硬规定。名字与类名相同（它毕竟是构造函数）；参数必须是**本类类型的引用** `const CSeqStack&`——不能是值传递。原因想一层就通：值传递形参本身要用实参构造，调用的还是拷贝构造，于是"构造自己先要构造自己"，无限递归，编译器直接禁止。引用没有这次拷贝，链条断开。

这样写完后，`s1`、`s2` 的指针各指各的数组，析构时各自释放自己的资源，互不干扰。崩溃消失。

## 5. 赋值不是初始化：operator= 的三步

还有一处会触发同样的事故，而且更隐蔽：

```cpp
CSeqStack s2(10);
s2 = s1;                 // 这是赋值，不是初始化
```

等号两边都是**已存在的对象**——这不是初始化（初始化要创建新对象），而是**赋值操作**，调用的是**赋值函数** `operator=`。C++ 语法规定 `s2 = s1` 的真实身份是 `s2.operator=(s1)`：`s2` 调用自己的成员函数，`s1` 当实参传入；等号不是合法函数名，所以前面加关键字 `operator`。你没写它，编译器同样默认生成一个——同样是无脑内存拷贝，同样的浅拷贝。

而且赋值版的浅拷贝比拷贝构造**多赔一笔**：`s1.pstack` 的地址抄给 `s2.pstack` 的瞬间，`s2` 原来指向的那块堆内存的地址被覆盖丢失——没人能再释放它，泄漏。接着才是熟悉的双重释放。一次赋值，赔两笔。

自定义赋值函数，三步走：

```cpp
CSeqStack& operator=(const CSeqStack& src)
{
    if (this == &src)            // ① 防自赋值：s = s 时直接返回
        return *this;
    delete[] pstack;             // ② 释放自己原有的外部资源
    top = src.top;
    size = src.size;
    pstack = new int[size];      // ③ 按 src 的尺寸重新开辟
    for (int i = 0; i <= top; ++i)
        pstack[i] = src.pstack[i];
    return *this;
}
```

第①步不能省：`s = s` 时若先执行 `delete[]`，把自己的资源删了再从自己身上拷贝——源数据已经没了，非法访问。第②步是赋值与拷贝构造的唯一本质差异：**拷贝构造的对象是新的，没有旧资源要还；赋值的两边都已存在，得先归还自己手里的**。第③步与拷贝构造完全相同。

> **边界：** 返回 `CSeqStack&`（返回 `*this`）是为了支持 `a = b = c` 连续赋值，返回值类型的讲究在运算符重载篇展开；"拷贝并交换"等现代写法也留到那里。

## 6. 顺带揭晓：扩容为什么不用 memcpy

第 11 篇埋的问题现在能答了。顺序栈扩容时把旧数组内容搬到新数组，为什么坚持用 `for` 循环而不用 `memcpy`、`realloc`？——因为 **`memcpy` 和 `realloc` 做的正是浅拷贝**：纯内存搬运，指针成员的值原样照抄。

数组里存的是 `int` 时没问题，`int` 不占用自身之外的资源。可一旦存的是带指针成员的对象，`memcpy` 之后每个对象的指针都指向原来那批资源——把第 2 节的事故在数组里复制了 N 份。OOP 编程里数据搬移一律用 `for` 循环逐个赋值（会正确调用每个元素的拷贝构造/赋值），只有**明确**元素不占外部资源时才敢用内存函数。

## 小结

- 用已存在对象构造新对象是初始化，调拷贝构造；等号两边都已存在是赋值，调 `operator=`——两个不同的函数
- 默认拷贝构造 = 逐成员内存拷贝（浅拷贝）；指针成员只抄值，两个对象共享同一块堆内存
- 崩溃机制：后析构的那个对已释放内存二次 `delete`
- 判据：对象持有外部资源（指针指向堆），浅拷贝必错；纯值成员浅拷贝无碍——看类要扫成员变量
- 深拷贝：拷贝构造参数必须是 `const T&`（值传递会无限递归），给新对象单独开辟资源再逐元素拷
- `operator=` 三步：防自赋值 → 释放旧资源 → 深拷贝；第②步是它与拷贝构造的唯一本质差异
- `memcpy`/`realloc` 就是浅拷贝，元素可能是对象时一律用 `for`
