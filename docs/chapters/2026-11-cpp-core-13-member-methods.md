# 三种成员方法：全在 this 指针上做文章

![普通方法的 this 是 CGoods*、常成员方法的 this 是 const CGoods*、静态方法没有 this](/assets/images/cpp-core/cpp-core-13-member-methods.png)

面试问"普通成员方法和静态成员方法的区别"，九成答案是"一个用对象调，一个用类名调"。对，但这是**现象**。追问一句"为什么静态方法能用类名调？"就卡住了。

这篇文章用一条线把类里所有成员方法串起来：第 10 篇讲过编译器给成员方法塞了隐含形参 `this`——那么普通方法、常成员方法、静态方法的全部区别，就是 **`this` 的三种形态**：普通指针、const 指针、压根没有。读懂这条线，"常对象为什么调不了普通方法"这类连环报错也就一次看懂。

边界：本文只讲成员方法的类型层面；虚函数带来的动态绑定属于多态篇；`const` 与指针的转换公式直接沿用第 06 篇，不再推导。

## 1. 普通成员方法：有 this 的都归这类

先给基准线。普通成员方法（此前所有 `show`、`init` 都是）有三条特征：

1. **属于类的作用域**——它不是全局函数，名字在类里；
2. **必须依赖对象调用**——`good1.show()` 合法，裸写 `show()` 非法；
3. **可以任意访问私有成员**——自己的方法访问自己的私有成员，天经地义。

第 2 条的原因第 10 篇拆过：编译器给每个成员方法的参数表开头加了 `CGoods* this`，调用时把对象地址传进来。没有对象，`this` 就没有实参来源，调用无法成立。这三条是"成员方法"的默认形态，下面两种变体都在它基础上改。

## 2. 静态成员变量：类级别的全局变量

变体之一要先从变量说起。需求：统计当前一共定义了多少个商品对象。用普通成员变量 `count` 行不行？不行——普通成员变量每个对象一份，`good1.count` 只能数 `good1` 自己，四个对象四个互不相干的 `count`。

用全局变量可以，但 OOP 里满屏全局变量是名字污染的温床。C++ 给出的答案是**静态成员变量**：

```cpp
class CGoods
{
    static int count;               // 类内：仅仅是声明
public:
    CGoods() { count++; }           // 新对象诞生，构造函数里 ++（顺便回扣：构造一定会被调用）
};

int CGoods::count = 0;              // 类外：必须定义并初始化
```

类内的 `static int count;` 只是声明，**类外定义**那一句不能省，漏掉就是链接期的"无法解析的外部符号"（第 03 篇的规则：声明不产生符号）。

静态成员变量的身份要说准：它**不属于任何对象，属于类**。说白了就是"一个落在类作用域里的全局变量"——四类事实支撑这个说法：

- 四个对象共享同一份，谁 `++` 都是同一个变量；
- 它住在数据段（初值为零的落在 BSS 段），和栈上对象的内存不在一处；
- `sizeof(CGoods)` 不把它算进去——对象大小只数普通成员变量；
- 访问它不需要对象，`CGoods::count` 直接可用。

## 3. 静态成员方法：没有 this

统计出来了，怎么打印？写个普通方法再用 `good4.getCount()` 调？功能正确，逻辑别扭——这是**所有对象共享的信息**，凭什么由某个具体对象代言？想用 `CGoods::getCount()` 类名直接调，编译器拒绝：普通方法有 `this` 形参，类名调用没有对象地址可传。

于是第三种形态登场——**静态成员方法**：

```cpp
static int getCount() { return count; }
```

调用用类名作用域：`CGoods::getCount()`。它与普通方法的三条差异，逐条对应：

1. 仍属于类作用域（没变）；
2. **不需要对象**，`CGoods::getCount()` 直接调（变）；
3. 仍可访问私有成员，但**只能访问不依赖对象的成员**——静态成员变量、静态成员方法（变）。

第 3 条是硬约束：静态方法没有 `this`，方法体里写 `m_price` 编译器不知道往哪个对象上找——普通成员变量挂在对象上，必须经 `this` 访问。所以"本质区别"的标准答案有了：

> 普通成员方法编译后会多一个 `CGoods* this` 形参；静态成员方法没有 `this`。一个依赖对象、一个不依赖，一切表象差异都从这里流出。

## 4. 常对象与常成员方法：this 变成 const 指针

第三种形态由一个新需求引出。镇店之宝，非卖品，对象的信息只许看不许改——那就是**常对象**：

```cpp
const CGoods good5("镇店之宝", 100, 1);
good5.show();        // 编译错误
```

常对象调普通方法为什么报错？用第 06 篇的公式一步看穿。`good5` 是 `const CGoods`，取地址后实参类型是 **`const CGoods*`**；而普通方法 `show` 的 `this` 形参类型是 **`CGoods*`**。`const CGoods*` → `CGoods*` 正是那条红线：把常量的地址泄露给普通指针，编译器拒绝。

修法顺着公式推：形参得改成 `const CGoods*` 才接得住。`this` 的类型是编译器定的，我们没法手改——但 C++ 留了开关：**成员方法的参数表后加 `const`**：

```cpp
void show() const            // 常成员方法
{
    cout << m_name << m_price;   // 只读，合法
}
```

后缀 `const` 的效果就一件事：编译器生成这个方法的 `this` 时用 **`const CGoods*`** 类型——`this` 指向的对象被当成常量，方法体里对任何普通成员变量的写操作都被禁止（读不受限）。

两个连锁推论，都由 `this` 的类型决定：

**推论一：`show()` 与 `show() const` 构成重载。**两个方法的 `this` 形参类型分别是 `CGoods*` 和 `const CGoods*`——第 06 篇说过，`const` 右边有指针就参与类型，两种形参类型不同，重载成立。常对象调 `const` 版，普通对象调普通版，编译器按实参（对象是否 const）选择。

**推论二：常成员方法里不能调普通方法。**常方法手里的 `this` 是 `const CGoods*`，把它传给普通方法的 `CGoods*` 形参——又是那条泄露红线，报错。常方法里只能调其他常方法（或静态方法）。

由此得出一条实践守则：**只读的成员方法一律实现成常成员方法**。`const` 版本普通对象也能调（`CGoods*` → `const CGoods*` 是约束加强方向，合法），常对象也能调——两种调用者通吃；反过来只写普通版，常对象一来就是一串看不懂的报错。OOP 代码里形参大量带 `const`，常对象随处可见，这条守则是预防针。

## 小结

- 普通成员方法：类作用域、依赖对象、可访问私有；根因是隐含形参 `CGoods* this`
- 静态成员变量：类内声明、类外定义并初始化；属于类不属于对象，住数据段，不占对象内存，所有对象共享
- 静态成员方法：没有 `this`，类名直接调用；只能访问静态成员——这是它与普通方法的本质区别
- 常对象只能调常成员方法：实参 `const CGoods*` 传给普通方法的 `CGoods*` 形参，正是第 06 篇的泄露红线
- 方法后缀 `const` = 把 `this` 声明成 `const CGoods*`：指向的内容只读；它与普通版本构成重载
- 实践守则：只读方法一律写 `const` 版本，普通对象、常对象通吃；类级别共享信息用 `static`

方法的地基齐了。下一篇处理对象之间最出名的一类事故：把一个对象赋给另一个对象、用对象初始化另一个对象时，指针成员被两个对象共享——深拷贝与浅拷贝。
