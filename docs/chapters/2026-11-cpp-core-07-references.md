# 引用：披着别名外衣的指针

![引用与指针的底层对照：同一套 lea/mov 指令；const 引用与右值引用都经由临时量](/assets/images/cpp-core/cpp-core-07-references.png)

"引用和指针有什么区别？"这是 C++ 面试的必考题，也是一道最容易答砸的题。答"引用是变量的别名，指针存地址"——面试官心里已经扣分了：这是语法书第一页的答案，不是理解的答案。

这篇文章把引用从汇编层面拆开。你会看到：定义一个引用和定义一个指针，生成的指令一模一样；所谓"别名"只是语法层的伪装。看清这一点之后，`const` 引用为什么能绑定 `20` 这种右值、C++11 的右值引用到底解决什么问题，全都是水到渠成的推论。

边界先说清：本文用 32 位 x86 的汇编对照（引用变量和指针一样占 4 字节）；右值引用只讲到这里为止，它在移动语义里的威力，留到面向对象篇再说。

## 1. 从 swap 看引用为什么存在

例. 每个人都写过的交换函数，按值传递版：

```cpp
void swap(int a, int b)
{
    int tmp = a; a = b; b = tmp;
}

int x = 1, y = 2;
swap(x, y);          // x、y 纹丝不动
```

解. 失效的原因上一篇刚讲过：实参到形参是**按值传递**，`swap` 改的是自己栈帧里的两份拷贝，函数一返回拷贝就作废了。

第一代修法用指针：`void swap(int* x, int* y)`，调用处写 `swap(&x, &y)`。能用了，代价是取地址符满天飞，函数体里全是 `*x`、`*y`。

第二代修法用引用：

```cpp
void swap(int& x, int& y)
{
    int tmp = x; x = y; y = tmp;
}

swap(x, y);          // 直接传变量名，函数体内当普通变量用
```

调用干净了，函数体也干净了。但先别急着感动——传进去的到底是值还是地址？答案藏在汇编里，下一节看。

## 2. 底层指令：引用就是指针

在调试器里对着两条定义看反汇编。左边定义指针，右边定义引用：

```cpp
int a = 10;
int* p = &a;         // lea eax, [a]      mov [p], eax
int& b = a;          // lea eax, [a]      mov [b], eax
```

两条 `lea`，两条 `mov`，一字不差。`lea` 把 `a` 的地址算出来放进 `eax`，`mov` 把这 4 字节地址存进 `p` 或 `b` 各自的内存。**引用变量有自己的 4 字节内存，里面存的就是被引用者的地址**——和指针的存储结构完全相同。

再通过它们改内存：

```cpp
*p = 20;             // mov eax,[p]  mov [eax], 14h
b = 30;              // mov eax,[b]  mov [eax], 1Eh
```

也是同一套：先从 `p`/`b` 的内存里取出地址，再往那个地址处写值。区别只在语法层：通过指针写要手写 `*p`，通过引用写直接 `b = 30`——编译器**自动补了解引用**。

所以"引用和指针的区别"的深层答案是：**指令层面不存在引用，一切引用底层都由指针完成；区别全部发生在语法层。**引用把"取地址"和"解引用"两步手工劳动交给了编译器，同时用"必须初始化"的纪律消灭了指针最大的风险源——野指针。这就是"引用是一种更安全的指针"的准确含义。

## 3. 引用的三条纪律

纪律一：**引用必须初始化**。指针可以 `int* p;` 悬着，引用不行——它诞生时就必须绑定一块内存，之后终身不改指向（语法上连"重新绑定"这个操作都不存在）。

纪律二：**初始化的值必须能取地址**。因为定义引用的指令第一步就是 `lea` 取右边对象的地址，右边若是个立即数，这条指令生成不出来：

```cpp
int& b = 20;         // 错误：20 没有内存，取不了地址
```

纪律三：**引用只有一级**。指针可以 `int**`、`int***` 一路套下去，引用没有"引用的引用"——`int&&` 在 C++11 里是右值引用，是另一个概念，不是二级引用（第六节细说）。

前两条纪律的根源是同一个：引用底层就是指针，所以右边必须有地址可存；它又不像指针那样留了"不初始化"的口子，所以天生不会悬空。

## 4. 数组引用：sizeof 暴露的别名身份

看一组对照，32 位系统：

```cpp
int arr[5] = {0};
int* p = arr;

sizeof(arr)          // 20：整个数组 5 × 4 字节
sizeof(p)            // 4：指针本身的大小
```

给数组配一个引用该怎么写？用上一篇讲 `const` 时的笨办法：先写指针再变形。指向数组的指针是数组指针 `int (*p)[5] = &arr;`，然后"右边的取地址符覆盖左边的星号"——`(*p)` 里的 `*` 换成 `&`：

```cpp
int (&q)[5] = arr;

sizeof(q)            // 20
```

`sizeof(q)` 是 20 不是 4。这就是引用和指针在语义层的真实差别：**引用是别名，使用引用就是在使用被引用物本身**——`q` 出现的地方编译器都自动解引用，`sizeof(q)` 等价于 `sizeof(arr)`。指针则是一个独立对象，`sizeof` 只量它自己那 4 字节。

顺带这条"指针变形法"值得记住：任何写不出来的复杂引用，先写出指向它的指针，再把初始化表达式上的 `&` 与声明里的 `*` 互相覆盖，就得到正确写法。

## 5. 左值与右值：为什么 `int& b = 20` 不行

**左值**（lvalue）：有内存、有名字，可以出现在赋值号左边。`a` 是左值。

**右值**（rvalue）：没内存、没名字，只能出现在赋值号右边。字面量 `20` 是右值——它没有内存，通常直接躺在寄存器里；函数返回的临时对象也是右值。

现在纪律二可以换个角度重述：左值引用只能绑定左值，因为定义引用要取地址，而右值无地址可取。`int& b = 20;` 被拒，不是语法故意刁难，是指令生成不了。

## 6. const 引用与右值引用：临时量登场

那 `20` 这种右值就没法引用了吗？可以，`const` 引用开绿灯：

```cpp
const int& d = 20;           // 正确
```

矛盾回来了：`20` 没有地址，`d` 底层存什么？看汇编，编译器做了三步：先在栈上**产生一个临时量**（临时变量），把 20 存进去；再 `lea` 取这个临时量的地址；最后把地址存进 `d` 的底层指针。`d` 引用的从来不是 `20` 本身，是那个装着 20 的临时量。

C++11 的右值引用 `&&` 走的是完全相同的路：

```cpp
int&& e = 20;                // 正确：同样是 产生临时量 → 取地址 → 存入底层指针
```

把两段汇编摆在一起看，逐条指令都相同。区别只有一个，且在语法层：

- `const int& d`：`d` 被 `const` 锁住，不能通过它改临时量；
- `int&& e`：没锁，**可以通过 `e` 修改那个临时量**。

右值引用的三条使用规则由此展开：

1. 右值引用专门引用右值——它需要产生临时量，左值自带内存，没有生成临时量的必要，所以 `int&& e = a;`（`a` 是左值变量）是错误的；
2. **右值引用变量本身是左值**——`e` 有内存、有名字，完全符合左值的定义；想再引用 `e`，得用左值引用；
3. 不能用右值引用去绑一个左值。

第二条规则现在听着像文字游戏，等到面向对象篇讲移动语义时它会变成关键：函数体内对右值引用再传递时，它已经"落地成左值"，想保持右值身份需要 `std::move`。这里先记住结论。

> **边界：** `const T&` 与 `T&&` 都能延长临时量生命周期，但重载决议时它们是两种不同的参数类型——这个差别在运算符重载与移动构造里会反复用到，本文不展开。

## 7. 笔试里的快速判据：把引用还原成指针

上一篇的判断法在这里同样适用。看到可疑的引用表达式，把 `&` 还原成 `*`、右边补上取地址，对错立刻显形；引用本身不参与类型（`typeid` 打不出来引用标记），考虑类型时把它当被引用物的指针看。

比如 `int* &q = p;`（引用一个指针变量）：还原成 `int* *q = &p;`，二级指针存一级指针的地址，成立。而 `const int* &q = &a;` 之类写法，还原后用第 06 篇的两条公式检查类型转换即可，不再赘述。

## 小结

- 定义引用与定义指针的汇编一字不差：都是取地址、存入 4 字节底层内存；引用赋值是编译器自动补的解引用
- "更安全的指针"的准确含义：必须初始化 + 初始值必须能取地址，野指针的两个来源全被堵死
- 引用只有一级；`&&` 是右值引用，不是二级引用
- 引用是别名：`sizeof` 按被引用物算；复杂引用先用指针写出来再变形
- 左值有内存有名字；右值没有。左值引用绑不了右值，因为取地址指令生成不了
- `const` 引用与右值引用都经由"临时量"绑定右值，指令相同；唯一区别是能否通过引用修改临时量
- 右值引用变量本身是左值；右值引用不能绑左值
