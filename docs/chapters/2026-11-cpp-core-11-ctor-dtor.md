# 构造函数与析构函数：把对象的生灭交给编译器

![栈上对象出作用域自动析构、全局对象程序结束才析构、堆对象必须 delete；delete = 调析构 + free](/assets/images/cpp-core/cpp-core-11-ctor-dtor.png)

上一篇的商品类留了个尾巴：`init` 和 `release` 两个方法要靠人手调。这篇开头把它换成顺序栈，问题更尖锐——栈类的构造要在堆上开辟数组，析构要释放它。忘了 `init`，一 `push` 就崩；忘了 `release`，堆内存悄悄漏掉。这两种错误没有任何编译器会提醒你，因为它们只是"没被调用的普通函数"。

人会忘，编译器不会。构造函数与析构函数的全部意义就在这里：**把"对象诞生时的初始化"和"对象消亡前的清理"从人工调用改成编译器自动插入**。这篇讲清它们的规则、三种内存区域上对象的生灭顺序，以及"对象"这个词在 C++ 里的准确含义。

边界：构造函数的初始化列表是下一篇的主题；`new`/`delete` 的底层实现（函数调用版）在第 21 篇展开，这里只讲它们与构造析构的关系。

## 1. init/release 模式的两种死法

例. 一个可扩容的顺序栈，属性三个：`pstack`（指向堆上数组）、`top`（栈顶下标）、`size`（容量）。手工初始化版本：

```cpp
class CSeqStack
{
    int* pstack;      // 指向堆上的数组——外部资源
    int top;
    int size;
public:
    void init(int sz = 10)
    {
        pstack = new int[sz];
        top = -1;
        size = sz;
    }
    void release()
    {
        delete[] pstack;
        pstack = nullptr;
    }
};
```

解. 对象本身 12 字节，但它指向对象外部的堆内存——这叫**外部资源**。手工模式有两种死法：

**忘了 `init`**：`pstack` 是野指针，第一次 `push` 就是往随机地址写内存，程序崩溃。

**忘了 `release`**：程序一切正常，数组那块堆内存永远没人还，泄漏。它更隐蔽，因为不崩溃，只在长跑的服务里慢性失血。

"是人都会忘"，所以这两件事不该托付给人。编译器知道对象何时诞生、何时消亡——让它代劳。

## 2. 构造函数：定义对象时自动执行

把 `init` 改名成**与类名完全相同的函数**，再去掉返回值，它就成了构造函数：

```cpp
CSeqStack(int sz = 10)
{
    pstack = new int[sz];
    top = -1;
    size = sz;
}
```

规则三条：名字与类名相同；没有返回值（连 `void` 都不写）；可以带参数，因此**可以重载**——第 09 篇的重载规则原样适用。

定义对象时编译器做两件事，缺一不可：

1. **开辟内存**：栈上挪出 12 字节，三个成员变量就位，但值是随机的、不合法的；
2. **调用构造函数**：按实参匹配一个重载版本（第 08 篇的匹配规则），把成员变量刷成合法状态。

给参数带上默认值（第 08 篇）还能一函数两用：`CSeqStack s;` 用默认 10，`CSeqStack s(50);` 用 50——两个重载版本合成一个。

## 3. 析构函数：出作用域自动执行

析构函数是 `类名` 前加波浪号：`~CSeqStack()`。规则与构造互补：没有参数、没有返回值，因此参数列表永远相同，**只能有一个，不能重载**。

栈上对象在函数 `return` 处自动析构，不用任何人调用：

```cpp
void demo()
{
    CSeqStack s1;
    CSeqStack s2(50);
}                    // ← 这里自动执行：先 ~s2，再 ~s1
```

析构顺序与构造**相反**：先构造的后析构。原因第 01 篇已经给过——栈的进出顺序。对象按声明顺序入栈（压帧），出作用域按逆序出栈（拆帧），构造析构就像入栈出栈。

## 4. "对象"是个逻辑概念

这里有一层容易被忽略的时间线。定义 `CSeqStack s;` 时：

- 第 1 步内存开辟完成——三个成员变量**存在**了，但值不合法；
- 第 2 步构造函数执行完——成员变量合法，我们说"**对象产生了**"。

析构函数执行后，我们说"对象不存在了"——但那 12 字节栈内存还在，要等函数返回、栈帧作废才真正回收。

这条时间线解释一个危险操作：手动调用析构函数在语法上是允许的（`s.~CSeqStack();` 编译通过），调用时对象内存还在所以不报错。但析构已经把 `pstack` 指向的堆数组 `delete` 了，之后再 `s.push(5)` 就是往已释放的堆内存写入——非法访问。析构之后的对象不该再使用，哪怕它的内存看起来还在。

## 5. 三块内存上的对象生灭

不同区域的"自动"程度不同，一张表说清：

| 区域 | 构造时机 | 析构时机 | 谁负责 delete |
|---|---|---|---|
| 栈 | 执行到定义处 | 出作用域（return 处），自动 | 不需要 |
| 全局（数据段） | `main` 之前 | `main` 结束后，自动 | 不需要 |
| 堆 | `new` 时 | **只有 `delete` 时** | 你 |

堆上对象没有"出作用域"的概念，它的析构只被 `delete` 触发。一个演示程序能看得明明白白：栈上三个对象、全局一个对象、堆上 `new` 一个对象，运行输出 **4 次构造、3 次析构**——缺的那次正是堆对象，没人 `delete ps`，它的析构函数永远不会执行，外部资源也永远不会释放。

所以 `delete` 必须拆成两步看：

```cpp
delete ps;
// 等价于：
ps->~CSeqStack();     // 第一步：调用对象的析构函数（释放外部资源）
free(ps);             // 第二步：释放对象本身的内存
```

**delete = 析构 + free**。这也是它与 `free` 的本质区别（第 21 篇会从实现角度重讲）：`free` 只做第二步，对象的析构函数根本不会执行，堆上的数组就漏了。给对象用 `free`，是 C 程序员转 C++ 最经典的泄漏方式。

全局对象在数据段上，`main` 之前构造、`main` 结束后析构——所以全局对象构造得最早，析构得最晚，和栈上对象"先构造后析构"是同一条逆序原则跨了整个程序生命周期。

## 小结

- 构造函数：与类名相同、无返回值、可重载；定义对象 = 开辟内存 + 调构造，两步缺一不可
- 析构函数：`~类名`、无参数无返回值、只能有一个；栈上对象出作用域自动析构
- 构造与析构逆序：先构造的后析构，栈进栈出的老规则
- "对象"是逻辑概念：内存就位但值不合法时还不算对象；构造完才产生，析构完就消亡——哪怕内存还在
- 三块内存：栈对象出作用域自动析构；全局对象 `main` 后析构；堆对象只有 `delete` 才析构，4 构造 3 析构漏的就是它
- `delete` = 调析构 + `free`；对象用 `free` 必泄漏外部资源

构造函数解决了"谁来初始化"。但有一类成员——`const` 成员、引用成员、没有默认构造的成员——根本不能在函数体里赋值，必须"出生时就绑定"。下一篇：构造函数的初始化列表。
