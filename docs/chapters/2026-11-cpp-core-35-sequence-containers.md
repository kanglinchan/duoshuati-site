# vector、deque、list：顺序容器三兄弟

![deque 的二维数组结构与扩容策略；vector/deque/list 三容器对比四要点](/assets/images/cpp-core/cpp-core-35-sequence-containers.png)

vector 已经在手写篇吃透了（第 20 篇），但顺序容器是三兄弟。这篇补齐另外两位：**deque**（双端队列）和 **list**（链表），然后把面试最爱问的两组对比一次说清——vector vs deque、vector vs list。

考法先说明白：容器面试走两条线，**纵向**考深度（底层什么结构、怎么扩容），**横向**考对比（各维度谁优谁劣、什么场景选谁）。只会 `push_back` 是及格线，懂底层才是区分度所在。

边界：deque 的内部实现各编译器版本有差异，本文以常见实现（map + 固定长第二维数组）为准；list 的迭代器失效规则沿用第 24 篇。

## 1. vector 的两个补充点

手写篇讲过底层与扩容，补两个使用细节。其一，**默认构造的 vector 一字节空间都没开**——`vector<int> v;` 的三根指针（第 20 篇的 first/last/end）全是空，第一次 `push_back` 才从 0 → 1 → 2 → 4 → 8 这样二倍扩张。每次扩容的代价是全套搬家：老对象在新内存逐个拷贝构造、老对象逐个析构、老内存释放。

其二，**reserve 与 resize 的区别**——笔试高频：`reserve(n)` 只把容量开到 n（`end_` 后移），**不产生任何元素**，`size()` 仍是 0；`resize(n)` 真的构造 n 个元素，`size()` 变 n。已知规模时先 `reserve` 一把，扩容搬家的开销就省了。这两句的区别本质就是 `end_` 与 `end_` 各动各的指针。

## 2. deque：一个二维数组的智慧

vector 只会从尾部便宜地生长，头部插入 O(n)。deque 的名字"双端队列"就是承诺：**两端插入删除都是 O(1)**。承诺的底气来自底层结构——**动态开辟的二维数组**：

```text
map（第一维，初始长度 2）
  ├→ [第二维数组 0：4096/sizeof(T) 个元素]
  └→ [第二维数组 1：同上]
```

第一维是根指针数组（初始只有 2 格）；每个第二维是一段**固定长度**的数组（常见实现按一页内存算，int 就是 1024 个元素）。两个游标 `first`、`last` 标记数据的起止——它们初始落在第一段的**正中间**，而不是开头：两头各留一半空位，从队头插、从队尾插都先吃空位，谁也不必先搬家。

扩容分两级。某一端空位用完，就在该端方向**再 new 一个第二维**挂上去——只动新增那段，已有元素一格不动。第一维 2 格挂满了，第一维**二倍扩容**（2 → 4 → 8……），老的第二维指针搬到新第一维的**正中间**（从下标 oldsize/2 开始放）——还是那个思路：上下留对称的空行，头尾两边将来都有地方继续挂新段。

这套结构的回报在接口上：deque 比 vector **多出一组 `push_front` / `pop_front`**，都是 O(1)。vector 不提供这两个接口不是忘了——数组头插要挪动全部元素，O(n) 的接口提供出来只会误导人。

## 3. list：双向循环链表

list 的底层是**带头节点的双向循环链表**：每个节点带 `pre`、`next` 两个地址域；尾节点的 next 指回头节点，头节点的 pre 指向尾节点。"循环"的回报是 `push_back` 不用从头遍历找尾巴——`head->pre` 一步直达尾节点。

插删是链表的天赋：插入删除一个节点只改前后两处的地址域，**不挪动任何其他元素，耗时与节点总数无关**——纯 O(1)。代价也来自同一处：节点在内存里散落各处，访问第 i 个元素只能从头挨个 `next`，查找 O(n)，**随机访问不存在**——list 干脆不提供 `[]`（第 23 篇埋过的伏笔）。

顺带把插删的"O(1)"说严谨：**找到位置之后**的插删是 O(1)，定位过程往往要先搜索一遍（O(n)）。所以"list 插删快"的完整表述是：已知位置的插删快；若位置未知，搜索的开销常常反超 vector。

## 4. 两组经典对比

**vector vs deque**（四个维度）：

1. **底层数据结构**：一维动态数组 vs 二维数组（map + 固定长段）。
2. **头部插删**：vector 没有 `push_front`（要挪全部元素，O(n)）；deque O(1)。两端都频繁插删 → 选 deque。
3. **内存使用效率**：vector 要求**一整块**连续内存——数据量大时，找这么大一块连续空间本身就难；deque 的每个第二维**独立 new**，只要有合适大小的空闲内存块就能放下，**分段连续**，内存利用率更高。面经原题"deque 底层内存是否连续？"的答案就在这里：**每段内部连续，段与段之间不连续**。
4. **中间插删**：都是 O(n)（都要挪元素），但 **vector 实际更快**——完全连续的内存挪动就是一个循环扫过去，指令少；deque 跨段挪动要经一维索引换算段内位置，指令多。复杂度相同不代表耗时相同。

**vector vs list**（本质是数组 vs 链表）：

- 随机访问：vector `[]` O(1)；list 无 `[]`，定位 O(n)。
- 已知位置插删：vector O(n) 挪动；list O(1) 指针操作。
- 查找：都 O(n) 顺序扫。

选型口诀一行：**随机访问多 → vector；已知位置的插删多 → list；两端插删多 → deque；都不确定 → 默认 vector**（连续内存对缓存友好，综合性能最稳）。面试答对比题时按"底层结构 → 各位置插删复杂度 → 内存效率 → 选型场景"四步走，比背结论体面得多。

## 小结

- deque = map + 固定长第二维数组：first/last 初始在段中间（两头留空位）；段满朝该方向加新段；第一维二倍扩容，老段放中间——一切设计服务于"双端 O(1)"
- deque 比 vector 多 `push_front`/`pop_front`；vector 头插 O(n) 所以不提供这组接口
- deque 内存**分段连续**：段内连续、段间独立 new——不需要一整块连续内存，利用率更高；但跨段挪动指令多，中间插删实际比 vector 慢
- list = 带头节点双向循环链表：`head->pre` 直达尾部；已知位置插删 O(1) 与节点数无关；无随机访问，定位 O(n)
- reserve 开容量不造元素，resize 造元素——本质是 end_ 与 last 各动各的
- 选型：随机访问多→vector；已知位置插删多→list；两端插删多→deque；默认 vector
