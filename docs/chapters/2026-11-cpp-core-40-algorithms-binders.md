# 泛型算法与绑定器：把"手撕代码"变成"一行调用"

![泛型算法两特点（收迭代器、收函数对象）+ find_if 与绑定器 + for_each 与 lambda](/assets/images/cpp-core/cpp-core-40-algorithms-binders.png)

泛型算法是 STL 六大组件的收官之篇，也是回报率最高的一块：标准库提供**七八十个**现成算法（sort、find、binary_search、for_each、reverse、unique……），每个新版本还在扩充。用熟之后，笔试限时手撕代码的时间能省一半——同样一道题，别人在写循环，你在写一行调用。

泛型算法的结构其实已在前面各篇露过面：`sort(v.begin(), v.end(), greater<int>())` 这一行同时用了迭代器（第 23 篇）、函数对象（第 39 篇）和容器。这篇把它们合龙，重点讲两个"按条件处理"的进阶玩法：**find_if 配绑定器**、**for_each 配 lambda**。

边界：绑定器（bind1st/bind2nd）的底层实现、lambda 的闭包原理属于中级课程，本篇只讲用法；算法清单参考《C++ Primer》附录的字母序罗列，用到时查表即可。

## 1. 泛型算法的两条特点，就是两个模板参数

泛型算法是全局函数，为什么能服务所有容器？两条特点各对应一个设计决定：

**特点一：参数接收的都是迭代器（区间）。**算法要通用，就得有一种统一方式遍历所有容器——只有迭代器做到了（第 23 篇：差异封装在各容器的 `++` 里）。所以算法签名几乎全是 `[first, last)` 区间：`sort(v.begin(), v.end())`。容器提供遍历能力，算法消费遍历能力，两边解耦。

**特点二：参数还能接收函数对象（策略）。**算法的行为不该写死：sort 默认 `less` 升序，传 `greater` 立刻降序。比较方式、过滤条件、处理动作全部参数化——策略换、骨架不动（第 39 篇的结论在算法层的重演）。

两条合起来就是泛型算法的全部：**模板实现 + 迭代器区间 + 函数对象策略**。

## 2. 常用算法速查

先备一个小抄，都是最常用的：

| 算法 | 作用 | 复杂度 |
|---|---|---|
| sort | 排序（快排，默认升序） | O(n log n) |
| binary_search | **有序**区间二分查找，返回 bool | O(log n) |
| find | 线性查找，返回迭代器（找不到返回 end） | O(n) |
| find_if | 按条件（一元谓词）线性查找 | O(n) |
| for_each | 对每个元素执行一元操作 | O(n) |
| reverse / unique | 逆置 / 相邻重复去重 | O(n) |
| random_shuffle | 打乱 | O(n) |
| max_element / min_element | 区间最大 / 最小元素的迭代器 | O(n) |

一个易错点先排掉：**binary_search 只对有序区间有效**（它就是二分的前提），乱序区间先 sort 再查；要拿"元素位置"用 find/find_if（返回迭代器），binary_search 只回答"存不存在"（返回 bool）。

## 3. find_if 与绑定器：一元谓词的来源

场景：vector 已按 `greater` 降序排好，要把 48 **按序插入**——也就是找到**第一个小于 48 的元素**的位置。

用 `find_if`（按条件查找）本来顺手，但它要求第三个参数是**一元谓词**：每次只从容器取一个元素、返回 bool 的函数对象。而我们手头的 `less`、`greater` 全是**二元**的（比较需要两个操作数）。48 是固定的，容器元素是流动的——怎么把"两个操作数的比较"改造成"一个操作数的判断"？

STL 的答案是**绑定器**（binder）：把二元函数对象的**一个形参绑死成固定值**，剩下那个形参接容器元素——二元就变成了一元：

```cpp
// 需求：找第一个小于 48 的元素
auto it = find_if(v.begin(), v.end(),
                  bind1st(greater<int>(), 48));      // 方案 A
auto it = find_if(v.begin(), v.end(),
                  bind2nd(less<int>(), 48));         // 方案 B，效果相同
```

推导过程比记结论重要。`greater(a, b)` 是 `a > b`；要表达"容器元素 < 48"，有两种装配方式：

- 方案 A：把 **a 绑成 48** → `48 > 元素`——等价于元素小于 48 → 用 `bind1st`（绑第一参）；
- 方案 B：把 **b 绑成 48** → `元素 < 48`——直接就是字面需求 → 用 `bind2nd`（绑第二参）。

找到后 `v.insert(it, 48)` 完成按序插入；找不到（48 比所有元素都小）时 find_if 返回 end，insert 到 end 恰好是尾部——逻辑天然闭合。

绑定器 + 二元函数对象 = 一元函数对象，这个公式在 lambda 出现前是 STL 的标准玩法。但要诚实地说：**这行代码不解释原理的话可读性很差**——`bind1st(greater<int>(), 48)` 到底绑的是谁、比的方向是什么，得在脑子里转一遍推导。这正是 C++11 引入 lambda 的动机。

## 4. for_each 与 lambda：一行读出意图的场景

另一类高频需求：对每个元素做点事——比如"打印所有偶数"。`for_each` 的第三个参数同样要一元谓词（不需要返回值），老写法是为它专门定义一个函数对象类，新写法是 **lambda 表达式**：

```cpp
// 老写法：为一个 for_each 专门定义一个类……
class PrintEven
{
public:
    void operator()(int val) { if (val % 2 == 0) cout << val << " "; }
};
for_each(v.begin(), v.end(), PrintEven());

// C++11 lambda：一行
for_each(v.begin(), v.end(), [](int val) {
    if (val % 2 == 0) cout << val << " ";
});
```

lambda 的结构对着函数对象读一遍就懂：`[]` 是**捕获列表**（把外部变量"抓"进函数体，此处为空）；`(int val)` 是形参——对应 `operator()` 的参数表；`{ ... }` 是函数体；需要返回值时写 `-> bool` 这类尾置返回类型。**写 lambda 就是在写函数对象**，只是编译器替你生成那个类。

lambda 在算法场景的杀手级优势不是"少打字"，而是**局部性**：函数对象类要定义在调用点外面，用一次却占一个类名；lambda 就地书写、用完即弃——每个算法调用点都有它自己的、一眼能读懂的策略，代码里不会再长出一堆"只有 operator() 的微型类"。

## 5. 选择路径

把这一篇的决策路径收拢：

- **有序区间查存在性** → binary_search；要位置 → find / find_if
- **条件能用现成二元对象 + 一个固定值表达** → find_if + 绑定器（bind1st/bind2nd）
- **条件稍复杂或追求可读** → find_if / for_each + lambda（日常首选）
- **完全自定义流程** → 迭代器自己遍历——永远是兜底方案，可读性最高、性能可控

绑定器在 C++11 后的实用价值基本被 lambda 取代，但它背后的"**把二元谓词装配成一元谓词**"思想仍在（`std::bind`/`std::function` 是它的现代后继，中级课程详谈）。面试中能讲清 bind1st/bind2nd 的装配推导，比会用 lambda 更能体现对函数对象体系的理解。

## 小结

- 泛型算法两特点：参数收迭代器区间（通用遍历的解）、收函数对象（策略参数化的解）——模板 + 迭代器 + 函数对象三者合龙
- 常用算法小抄：sort（快排）、binary_search（只报存在性、只对有序区间）、find/find_if（返回迭代器或 end）、for_each、reverse/unique
- 绑定器：把二元函数对象的一个形参绑成固定值，得到一元谓词；bind1st 绑第一参、bind2nd 绑第二参——装配方向由"固定值放比较符哪一边"推导
- lambda = 编译器帮你生成的函数对象：[] 捕获、() 形参、{} 函数体；就地书写、局部性完胜外置类
- 决策路径：binary_search 查存在、find_if+lambda 查位置、迭代器兜底；绑定器是 lambda 出现前的历史方案，思想仍在 std::bind 中延续
