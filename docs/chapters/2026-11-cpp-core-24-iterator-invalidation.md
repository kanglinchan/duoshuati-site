# 迭代器失效：erase 之后再 ++ 会发生什么

![迭代器失效三场景与底层原理：容器维护迭代器登记链表，修改时 verify 置空，用返回值更新](/assets/images/cpp-core/cpp-core-24-iterator-invalidation.png)

一段再普通不过的业务代码：删掉 vector 里所有的偶数。写完一跑——只删第一个时岁月静好，把 `break` 一去掉，程序当场崩溃，返回码非零。

这就是**迭代器失效**（iterator invalidation），容器使用的事故率榜首，也是面经必考题。它有一套清晰得近乎机械的规则：哪些迭代器会失效、怎么避免、以及容器底层凭什么"知道"一个迭代器失效了。这篇把三层全部讲透——规则层保你写对代码，原理层让你在崩溃时知道去哪看。

边界：以 vector 为准展开（失效规则最严、也最能暴露机制）；`list` 的 `erase` 只失效被删除的那个迭代器，关联容器相关的差异在第 37、38 篇补充。

## 1. 事故现场

例. 复现崩溃：

```cpp
vector<int> vec;
for (int i = 0; i < 20; ++i)
    vec.push_back(rand() % 100);

// 删掉所有偶数
auto it = vec.begin();
while (it != vec.end())
{
    if (*it % 2 == 0)
        vec.erase(it);      // 删除 it 指向的元素
    ++it;                   // ← 第一次 erase 之后，这行是灾难
}
```

解. `erase(it)` 和 `insert(it, val)` 是 vector 的两个"指定位置"接口——`push_back` 只管末尾，`erase` 删迭代器指向的元素，`insert` 在迭代器指向的位置插入。**第一次 `erase(it)` 后，`it` 本身已经失效**；紧接着的 `++it` 是对一个失效迭代器做运算符重载调用，非法操作，进程意外终止。

为什么删一个会牵连迭代器本身？回想 vector 的底层（第 20 篇）：连续数组。删掉中间一个元素，它后面的所有元素都要**前移一格**填坑。而 vector 的迭代器本质是一根指向数组某格的指针——元素挪了，"指向元素 i 的迭代器"在移动之后指的已经是别的元素，甚至越过了 `last`。对 vector 来说：**删除点（含）到容器末尾的所有迭代器全部失效**。

## 2. 三种失效场景，一张表

| 操作 | 谁失效 | 谁幸存 |
|---|---|---|
| `erase(p)` | `p` 及其之后（到末尾）全部 | `p` 之前的迭代器 |
| `insert(p)`（不扩容） | `p` 及其之后全部（元素后移） | `p` 之前 |
| `insert` 引起**扩容** | **全部迭代器**，无一幸免 | 无 |

前两行是同一句话：**插入/删除点及之后的迭代器失效，之前的安然无恙**——前面的元素没挪过。第三行更彻底：扩容意味着搬新家（第 20 篇的 `expand`），底层内存整个换了地方，旧内存上所有指针（迭代器）全部作废，管你指向哪。

这套规则对 deque、list、关联容器同样成立（它们都有 `insert`/`erase`），只是失效范围各容器略有不同——记 vector 的规则，遇到其他容器再查它的特例。

## 3. 解法：用返回值更新，再配合逻辑

`erase` 和 `insert` 的函数签名里藏着解药——**它们都返回一个迭代器**，指向完成操作后**当前位置**的新迭代器：

```cpp
it = vec.erase(it);        // it 指向"被删元素的下一个"
it = vec.insert(it, val);  // it 指向新插入的元素
```

更新了迭代器只解决"有效"，还得解决"正确"。两个经典逻辑配合：

**删除后不前进。**删掉一个元素后，后面的元素已经前移到 `it` 当前位置。此时 `++it` 会跳过这个刚挪过来的元素——它还没被检查过。所以 erase 之后停在原地，只有没删时才 `++`：

```cpp
while (it != vec.end())
{
    if (*it % 2 == 0)
        it = vec.erase(it);     // 更新 + 不前进
    else
        ++it;                   // 没删才前进
}
```

**插入后跳两格。**需求"在每个偶数前面插一个比它小 1 的数"：在偶数位置插入后，偶数被挤到 `it` 的下一个位置。`++it` 一次正好落在那个**已经判断过**的偶数上——再插、再挤，循环永不结束。所以要 `++it` 两次：一次跨过新插入的奇数，一次跨过已判断的偶数。

失效问题的完整答案因此是两句话：**位置失效用返回值更新，逻辑错位用步进配合。**背模板不如记住这两条推导。

## 4. 底层原理：迭代器都是登记在册的

最有意思的一层：容器凭什么知道"这个迭代器失效了"？把 VS 的 vector 源码抠掉包装，核心设计其实很短：

**迭代器多记了一笔账。**我们第 23 篇实现的迭代器只有一个成员（元素指针），库版迭代器还有第二个成员——**指向它所属容器对象的指针** `_pVec`。每次通过 `begin()`/`insert()` 等构造迭代器时，这个"户口"就登记在迭代器身上。

**容器维护一条迭代器登记链表。**容器内部有一条带哨兵头节点的链表，每诞生一个迭代器，就把它的地址**头插**进这条链——容器随时知道"我的迭代器都发给谁了、各自指向哪一格"。

**修改操作先查户口。**`erase`/`insert`/`push_back` 在动手前调用 `verify(失效起点, last)`：遍历登记链表，凡是记录的元素地址落在失效区间内的迭代器，把它身上的 `_pVec` **置空**——这就是"失效"的物理含义，一个空指针而已——然后把它从链表摘除。扩容时的 `verify(first, last)` 查全表，所以全军覆没。

**失效暴露在使用时。**迭代器的 `++`、`*`、`!=` 里都有检查：`_pVec` 为空，抛异常；`!=` 还检查两边迭代器的 `_pVec` 是否同一个容器——**不同容器的迭代器比较没有意义**，编译器的检查报的正是 `iterator incompatible`（迭代器不兼容）。

所以"迭代器失效"不是什么玄学状态，是**容器主动把你手里的迭代器标记成空**。也解释了两个日常现象：为什么不同容器的迭代器不能互比、为什么失效后继续用会抛异常而不是悄悄出错——检查点就写在运算符重载里。

## 5. 亲手写 insert/erase：挪动的单位是对象

在自己的 vector 上补这两个接口，会发现挪动不能 `memcpy`——第 14、18 篇的老结论，这里是最直接的用武之地：

```cpp
iterator erase(iterator it)
{
    _allocator.verify(it.cur(), last);          // 失效区间检查
    T* p = it.cur();
    for (; p != last - 1; ++p)
    {
        _allocator.destroy(p);                  // 先析构当前位置
        _allocator.construct(p, *(p + 1));      // 用后一个元素构造过来
    }
    _allocator.destroy(last - 1);               // 最后一个元素单独析构
    last--;                                     // 有效区间缩一格，内存不动
    return iterator(p, this);                   // 返回当前位置的新迭代器
}
```

erase 是"前移"：**先 destroy 再 construct**（后元素的对象搬进当前位置，资源随之搬家）；insert 反过来是"后移"：从 `last` 往回**先 construct 再 destroy**（先在下一格造副本再析构原对象）。两个方向的顺序不能反——对象的外部资源只允许在"已有副本"之后才析构。循环边界 `p != last - 1` 也是差一陷阱：最后一个元素没有"下一个"可拷，循环外单独析构。

这也回过头解释了失效规则为什么长那样：erase 之后 `[p, last)` 区间的对象全是新造的副本，旧位置上的迭代器自然全部作废——**失效规则不是规定出来的，是对象搬家的必然结果**。

## 小结

- 三种失效场景：`erase(p)` 与不扩容的 `insert(p)` 使 `p` 及之后全部失效；**扩容使全部失效**；之前的迭代器安然无恙
- 解法两件套：用 `erase/insert` 的**返回值**更新迭代器（位置有效），配合步进逻辑（erase 后不 `++`，insert 后按需求 `++` 两次）
- 底层原理：迭代器身上记着所属容器的指针；容器用登记链表记录所有发出的迭代器，修改时 `verify` 把失效区间内的迭代器 `_pVec` 置空；使用时的检查点在 `++`/`*`/`!=` 里，报 `iterator incompatible`
- 不同容器的迭代器不可比较——检查点在 `!=` 里
- 手写 `erase`/`insert`：挪动的单位是对象，erase 先析构后构造、insert 先构造后析构；失效规则是对象搬家的必然结果
