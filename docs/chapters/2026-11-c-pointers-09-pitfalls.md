# 陷阱与惯用写法速查（完结篇）

前八课把指针的原理和用法都讲透了。这最后一课换个形式——不再按知识体系推进，而是把 C 指针实践中最容易踩的坑、最好用的写法，整理成一份**可以随手翻的清单**。

写 C 的时候遇到不确定的地方，回来查这一课。

### 1. 库函数选型：优先用带范围检查的版本

C 的老牌字符串函数都不检查缓冲区长度，是缓冲区溢出的温床。能用安全版本就用安全版本：

```c
/* 危险：不检查长度，str 太长就溢出 dest */
strcpy(dest, str);
sprintf(buf, "%d-%s", n, name);

/* 推荐：明确告诉它缓冲区多大 */
snprintf(buf, sizeof(buf), "%d-%s", n, name);   /* C99，超长会截断 */
strcpy_s(dest, sizeof(dest), str);              /* C11 Annex K，超长直接报错 */
```

特别要澄清一个流传很广的误解：`strncpy` **不是** `strcpy` 的安全版。它超长时**不会补 `'\0'`**，产出的不是合法字符串，后患更大。真要用 `strncpy`，记得手动补结尾：

```c
strncpy(dest, src, sizeof(dest) - 1);
dest[sizeof(dest) - 1] = '\0';   /* 手动补终止符 */
```

### 2. `printf` / `scanf` 的格式符陷阱

`printf` 和 `scanf` 的格式符不一致，是个万年坑。根子在第 6 章讲的"可变参数会发生默认类型提升"：

| 场景 | float | double | char | short |
|---|---|---|---|---|
| `printf` | `%f` | `%f` | `%c` 或 `%d` | `%d` |
| `scanf` | `%f` | **`%lf`** | `%c` | `%hd` |

记两个要点就够：

- **`printf` 里 float 和 double 都用 `%f`**。因为 float 传进可变参数时会被自动提升成 double，`%f` 对应的就是 double。
- **`scanf` 里 double 必须用 `%lf`**。因为 scanf 传的是指针，指针不发生提升，必须精确匹配目标类型。用 `%f` 往 double 里读会写错内存。

还有一个迷惑性极强的：

```c
printf("%f", 1.5);       /* ✓ 对 */
printf("%d", 1.5);       /* ✗ 类型不匹配，行为未定义 */
printf("%d", 1.5f);      /* ✗ 同上，f 后缀没用，还是会提升成 double */
```

### 3. 整数提升：比 int 小的类型先变成 int

看一段代码，猜猜打印什么：

```c
unsigned char c = 200;
printf("%d\n", c + c);    /* 400 还是 144？ */
```

答案是 400。因为 `unsigned char` 参与运算前，会先被提升成 `int`——这叫**整数提升（integer promotion）**。两个 200 的 int 相加得 400，不会按 unsigned char 的 255 回绕。

```c
c = c + c;                /* 但赋回 unsigned char 时，400 被截断成 144 */
printf("%d\n", c);        /* 144 */
```

规则一句话：**凡是比 int 小的整数类型（char、short），一进表达式就先提升成 int，算完再说。** 赋回去的时候再按目标类型截断。

这也是为什么 `getchar()` 的返回值是 `int` 而不是 `char`——它要能装下所有字符**外加**一个 EOF（通常是 -1），char 装不下。

### 4. 结构体的惯用写法

写结构体，社区有套约定俗成的习惯，照着写可读性最好。

**typedef + 结构体标签**，一气呵成：

```c
typedef struct Point {
    double x, y;
} Point;

/* 之后直接用 Point，不用每次写 struct Point */
Point p = {1.0, 2.0};
```

**自引用结构体**（链表、树的节点），成员里只能用结构体标签，不能用 typedef 别名：

```c
typedef struct Node_tag {
    int value;
    struct Node_tag *next;   /* 此时 typedef 还没生效，只能用标签 */
} Node;
```

**两个结构体互相引用**，先各自声明标签，再定义：

```c
typedef struct Man_tag Man;
typedef struct Woman_tag Woman;

struct Man_tag   { Woman *wife;    };
struct Woman_tag { Man   *husband; };
```

注意：互相引用只能用**指针**，不能直接嵌套实体——`struct Man { Woman wife; }` 需要 Woman 的完整定义，而 Woman 里又装着 Man，无限套娃，编译器算不出大小。指针大小是固定的（8 字节），所以指针随便互相指。

### 5. 初始化的现代写法（C99+）

C99 给初始化加了两个超实用的特性，能显著减少 bug。

**指定初始化器**——不用按成员顺序，直接点名：

```c
typedef struct { int year, month, day; } Date;

/* 老写法：顺序不能错，漏了还得数逗号 */
Date d1 = {2026, 11, 13};

/* C99：点名初始化，清晰、不怕顺序 */
Date d2 = { .year = 2026, .month = 11, .day = 13 };
Date d3 = { .year = 2026 };              /* 只初始化 year，其余自动为 0 */
```

数组也能指定下标：

```c
int a[10] = { [3] = 100, [7] = 50 };   /* 只给第 4、8 个赋值，其余为 0 */
```

**复合字面量**——不用先声明临时变量，直接造一个结构体/数组的值：

```c
/* 老写法：得先造个临时变量 */
Point tmp = {1.0, 2.0};
draw(&tmp);

/* C99：直接在调用处写字面量 */
draw(&(Point){1.0, 2.0});
draw_all(&(Point[]){ {0,0}, {1,1}, {2,2} });   /* 数组也行 */
```

这两个特性让 C 的初始化体验接近 JS 的对象字面量，写起来顺手很多。

### 6. 关于指针的九条军规

把全书最重要的话收拢成九条，算是这门课的毕业赠言：

1. **指针 = 地址 + 类型信息。** 类型决定 `p+1` 走多远、`*p` 读几个字节。
2. **表达式中数组自动转成指针**，`a[i]` 就是 `*(a+i)`；但 `sizeof`、`&`、字符串初始化是例外。
3. **声明和表达式是两套语法。** 声明里的 `*` 和 `[]` 不是运算符，用第 5 课的阅读法拆解。
4. **C 只有值传递。** 想让函数写回调用方的变量，就把地址传进去（`scanf` 的 `&` 就是这个道理）。
5. **内存生命周期只有三种**：静态（全程）、自动（栈，函数返回即失效）、动态（malloc 到 free）。永远不要返回局部变量的地址。
6. **malloc/free 成对出现**；free 后立刻置 NULL；内存问题交给 Valgrind 抓。
7. **字符串字面量在只读区。** `char s[] = "..."` 可写，`char *s = "..."` 指向只读区不能改。
8. **新代码用下标写，能读懂指针运算就行**；别为了炫技写 `*++p`。
9. **调不通就把地址打出来看**（`%p`）。写代码时想着"指针是类型"，调 bug 时回到"指针就是地址"——两个视角切换自如，指针就彻底通了。

### 小结

这门课从"指针是什么"一路讲到"怎么用指针搭数据结构"。回头看，其实 C 指针的所有困难都可以归结到两点：**声明语法反直觉**（第 5 课解决），以及**数组与指针的暧昧关系**（第 6 课解决）。把这两点拿下，剩下的 malloc/free、链表、函数指针，都只是应用而已。

JS 开发者学 C 指针还有个额外收获：你会突然看懂很多 JS 的"为什么"——为什么对象是引用、为什么 `const` 锁不住内容、为什么原型链能共享方法。C 把这些机制裸露出来，看懂了它，再看高级语言就都是"哦，原来是这么实现的"。
