# 继承的基本意义：继承到底继承了什么

![继承访问权限矩阵：三种继承方式 × 三种基类成员访问限定，在派生类与外部的实际权限](/assets/images/cpp-core/cpp-core-26-inheritance.png)

从这篇开始进入 C++ 面向对象的重头戏：继承与多态。第一个问题听起来最简单，也最容易被答浅——**继承到底继承了什么？**

答"继承了基类的成员"只对一半。派生类确实把基类的成员变量、成员方法全部搬进了自己的内存布局，但搬进来之后**能不能碰**是另一回事——继承方式（public/protected/private）与成员在基类里的访问限定交叉出一张九宫格，几乎所有继承的笔试题都在这张表里出。

边界：本篇只讲继承的语义与访问权限；派生类怎么初始化基类部分（构造顺序）是下一篇；重载/隐藏/覆盖三兄弟是第三篇。

## 1. 继承的第一目的：代码复用

场景最直白：类 A 已经有三个属性（人：姓名、年龄、性别），类 B 想要这三个再加自己的——选择之一是把三个属性在 B 里再抄一遍。选择之二是：

```cpp
class A
{
public:
    int ma;
protected:
    int mb;
private:
    int mc;
};

class B : public A      // B 从 A 继承而来；A 派生了 B
{
public:
    int md;
};
```

语法就一句话：`class B : 继承方式 A`。`B` 叫**派生类**（子类），`A` 叫**基类**（父类）；规范的说法是"A 派生了 B，B 从 A 继承而来"。

继承之后 B 的内存布局分两段：**前半是完整的 A（基类部分），后半是 B 自己新增的成员**。32 位下 `sizeof(A)` 是 12（三个 int），`sizeof(B)` 是 16——基类部分 12 加自己 4。基类的部分"整个"躺在派生类对象里，连 `mc` 这种基类私有的也占着内存——**继承了，只是未必可见**，这一点马上见分晓。

还有个容易疑惑的现象：派生类里再写一个 `ma` 会怎样？编译器不报重定义——**派生类自己作用域里的 `ma` 与从 A 作用域继承来的 `ma` 互不冲突**。可以理解成派生类继承了成员的同时还附带继承了基类的作用域，两套名字各归各的域（这层关系在"隐藏"那篇会再次出场）。

## 2. 组合还是继承：part of 与 kind of

什么时候该用继承？先认识另一种类间关系——**组合**（composition）：一个类的成员变量是另一个类的对象。第 12 篇的 `CGoods` 持有 `CDate m_date`，就是组合。

两者的判据是一句话：

> **组合是 part of（一部分的关系），继承是 kind of（一种的关系）。**

日期是商品信息的一部分 → 商品与日期是组合。学生是人的一种 → 学生与人该设计成继承：人里的姓名年龄性别被学生复用，学生再加学号、班级。

选错关系的代码不会立刻报错，但语义全歪：把"学生是人的一种"写成组合（人作为学生的成员），"学生有一个'人'"的模型会荒腔走板；反之把"日期是商品的一部分"写成继承，商品"是一种日期"更是笑话。建模的第一道判断题永远先问：**是一部分，还是一种？**

## 3. 九宫格：继承方式的完整权限表

派生类把基类成员搬进来之后，访问限定受两个因素交叉决定：**继承方式**（public/protected/private，也有三种）× **成员在基类里的访问限定**（public/protected/private）。逐格实验后得到完整矩阵：

| 基类成员 ↓ · 继承方式 → | public 继承 | protected 继承 | private 继承 |
|---|---|---|---|
| **public** | 派生类内 ✓ / 外部 ✓ | 派生类内 ✓ / 外部 ✗ | 派生类内 ✓ / 外部 ✗ |
| **protected** | 派生类内 ✓ / 外部 ✗ | 派生类内 ✓ / 外部 ✗ | 派生类内 ✓ / 外部 ✗ |
| **private** | **不可见** | **不可见** | **不可见** |

读这张表抓三条规律就够了：

**规律一：成员在派生类中的权限 = min(基类权限, 继承方式)。**public 继承下所有权限原样保留；protected/private 继承把 public、protected 成员"压"到继承方式的级别（基类 public 成员经 protected 继承后在派生类里就是 protected）。

**规律二：外部永远只能访问 public。**对象在外部只能碰 public 成员——只要成员在派生类里不是 public，外面一律碰不到。

**规律三：基类的 private 成员在派生类里是"不可见"，不是"私有"。**这是最容易答错的一格。私有 ≠ 不可见：如果继承后在派生类里算"私有"，那派生类自己的方法就该能访问自己的私有成员——可实验是访问不了（编译器报无法访问 private 成员）。准确的表述是：**基类私有成员被派生类继承（占内存、是对象的一部分），但派生类看不见它**，任何继承方式下都一样。private 的封装在继承面前依然成立——只有基类自己（和友元）能碰。

一个追问顺带解决：多级继承时权限怎么算？**只看直接基类**。C 从 B 继承（private 方式），B 从 A 继承（private 方式），`ma` 在 C 里的权限是什么？答：看 `ma` 在 B 里是什么——private 继承把它压成了 private，于是在 C 里不可见。别隔着 B 直连 A，权限逐级传递，不跳跃。

## 4. protected 的存在意义

九宫格看完，一个问题浮出来：protected 和 private 在单个类里看起来一模一样（外部都碰不到），那 protected 为什么要存在？

答案就在继承结构里：

- **private**：基类的成员**谁都不给**——派生类、外部都不许碰；
- **protected**：基类的成员**给家里人、不给外人**——派生类可以访问，外部不行。

所以设计基类时问一句"派生类需不需要访问这个成员"：需要且不想给外人 → protected；派生类也不需要 → private。没有继承体系时 protected 与 private 效果相同，它的价值专属于继承场景——"基类为派生类预留的、对外封死的接口"。

## 5. 默认继承方式：class 与 struct 的分叉

继承方式不写会怎样？跟成员默认访问限定同一条规则分叉：

- `class B : A` → 默认 **private 继承**；
- `struct B : A` → 默认 **public 继承**。

class 默认 private（成员默认 private，第 10 篇）、struct 默认 public，两处默认值保持一致。也正因为 private 继承会把权限全压暗，**显式写出继承方式**是好习惯——看到 `class B : A` 时多想一秒"这八成是笔误漏了 public"。

> **边界：** private 继承在工程里的语义是"按实现继承"（复用实现但不是一种的关系），比组合更强的耦合，实践中很少用；本系列的继承示例全部默认 public 继承。

## 小结

- 继承的本质之一是代码复用：`class B : public A`，B 的内存布局 = 完整的 A + B 的新增部分，基类私有成员也占内存
- 类间关系二选一：part of 用组合（成员对象），kind of 用继承——学生是人的一种，日期是商品的一部分
- 九宫格规律三条：派生类内权限 = min(基类权限, 继承方式)；外部永远只能访问 public；基类 private 成员被继承但**不可见**（不是"私有"）
- 多级继承只看直接基类，权限逐级传递
- protected 的存在意义专属继承：给派生类访问、对外封死；private 则连派生类也不给
- 默认继承方式跟 class/struct 走（private/public），显式写出是好习惯

继承把基类的成员搬进了派生类，也带来新问题：基类部分的成员由**谁**初始化？派生类的构造函数能直接给基类私有成员赋值吗？下一篇：派生类的构造过程。
