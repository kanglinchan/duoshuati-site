# 重载、隐藏、覆盖：同名函数的三种关系

![继承结构同名成员：重载（同作用域不同签名）、隐藏（派生类同名遮蔽基类）、覆盖（虚函数，下一篇）；上下转换规则](/assets/images/cpp-core/cpp-core-28-overload-hide-override.png)

基类有 `show()`，派生类也有 `show()`——这两个函数是什么关系？答"重载"的人数最多，**答案是错的**。重载、隐藏、覆盖三个词描述的全是"名字扯上关系"的函数，区分标准只有两条：**它们在不在同一个作用域**、**参数列表一不一样**。

这篇把三者的判定规则定死，并顺手讲清继承结构的"上下转换"——基类指针指向派生类对象为什么合法、反过来为什么危险。后者是下一篇虚函数与多态的地基。

边界：覆盖（override）需要虚函数参与，本篇只把"隐藏"讲透，覆盖留到下一篇与虚函数一起收；文中"上转/下转"的说法与图里基类在上、派生类在下的画法对应。

## 1. 重载：必须同作用域

第 09 篇给重载下的定义里有一条被普遍忽视的前提：**一组函数必须处在同一作用域**。现在它要发威了。

```cpp
class Base
{
public:
    void show() { cout << "Base::show()"; }
    void show(int a) { cout << "Base::show(int)"; }
};

class Derived : public Base
{
public:
    void show() { cout << "Derived::show()"; }   // 派生类自己的
};

Derived d;
d.show();        // Derived::show() —— 没毛病
d.show(10);      // 编译错误！
```

`d.show(10)` 报的错很迷惑：编译器拿着 int 实参去匹配，找到的却是 `Derived::show()`——一个不带参的版本，报"函数不接受 1 个参数"。**基类里明明有个 `show(int)`，为什么不匹配它？**

因为 `Base::show(int)` 和 `Derived::show()` **不在同一个作用域**，它们连重载关系都谈不上。名字查找从最近的作用域（Derived）开始，找到 `show` 这个名字就停——第 09 篇的"局部声明遮蔽全局整组重载"在这里原样重演，只是换成了类作用域之间。

所以重载的完整判定：**同一作用域 + 函数名相同 + 参数列表不同**。基类的一组函数之间、派生类的一组函数之间可以谈重载；跨基类和派生类的两个函数，永远不构成重载。

## 2. 隐藏：派生类的同名成员遮蔽基类

那 `Derived::show()` 和 `Base::show()`、`Base::show(int)` 是什么关系？——**隐藏**（hiding）。

> 继承结构中，派生类的同名成员（不管是变量还是方法，不管参数列表是否相同）把基类的同名成员**全部**遮蔽。

注意"全部"：派生类只要有一个 `show()`，基类的 `show()` **和** `show(int)` 就一起被遮住——不是按签名逐个遮，是**按名字整锅端**。这就是 `d.show(10)` 找不到 `Base::show(int)` 的完整解释：名字查找在派生类作用域命中 `show` 后停止，基类作用域根本没被搜到。

强制访问被隐藏的基类成员，办法是显式指定作用域：

```cpp
d.Base::show(10);        // 指定 Base 作用域，调用基类的 show(int)
```

对成员变量同理：派生类定义同名 `ma` 后，`d.ma` 是派生类自己的，`d.Base::ma` 才是基类那份（两份都实实在在占内存，第 26 篇说过同名不冲突的原因正是作用域不同）。

到这里三分有二：**同作用域、参数不同 → 重载；跨作用域、名字相同 → 隐藏。**第三分（覆盖）需要虚函数，下一篇揭盅；现在只需记住覆盖是"派生类虚函数与基类虚函数同名同参"的一种特殊隐藏，先混个脸熟。

## 3. 上下转换：四个方向，两个合法

继承结构的内存图（第 26 篇）：派生类对象 = 基类部分 + 派生类新增部分，基类在上、派生类在下。术语"上转/下转"由此而来——上转 = 派生转基类，下转 = 基类转派生。四个转换方向逐一判定：

**① 派生类对象 → 基类对象：合法（上转）。**基类对象只需要基类部分那么大的数据，派生类把基类部分"切"给它即可。`Base b = d;` 完全正常——注意这是**切片**：派生类特有的部分被丢弃，b 里只有基类部分。

**② 基类对象 → 派生类对象：非法（下转）。**派生类对象需要"基类部分 + 自己的部分"，基类对象只够填前半截，后半截填什么？编译器不会替你编数据，直接禁止。

**③ 基类指针/引用 → 指向派生类对象：合法，且极其重要。**

```cpp
Base* pb = &d;           // 基类指针指向派生类对象
pb->show();              // 调用的是……Base::show()
```

指向本身合法（派生类对象里完整地躺着一份基类部分，`pb` 指着它是真实准确的）。但**指针的类型决定指针的能力**：`pb` 的类型是 `Base*`，解引用时编译器按 Base 的布局解读内存，只能访问基类部分的成员——派生类特有的成员从 `pb` 的视角根本不存在。所以 `pb->show()` 调的是 `Base::show()`，哪怕 `pb` 实际指着 Derived 对象。

"静态类型决定可见范围"——这句话就是下一篇多态的引信：`pb->show()` 按静态类型调了 Base 版，可它指向的明明是 Derived，"按实际类型调用"正是虚函数要做的事。

**④ 派生类指针 → 指向基类对象：非法，且危险。**

```cpp
Derived* pd = &b;        // 编译错误
```

派生类指针解引用时按 Derived 布局解读内存，访问范围大于基类对象实际拥有的内存——后半截是别人的内存，碰了就是非法访问。编译器直接拦下。硬要强转过去语法上能编过，但那是在骗编译器：内存上根本没有派生类对象，`pd->show()` 调派生类版本时若访问了派生类成员，就是实打实的越界。

四个方向收敛成一条规则：

> **继承结构的类型转换，默认只支持从下到上（派生 → 基类）；从上到下一律拒绝。**

指针、引用、对象三者同判。为什么基类指针指向派生类对象值得单独立一条③？因为 `Base* pb = new Derived;` 是多态的标准姿势——工厂返回基类指针、容器装各种派生对象，全靠这条转换撑着。③的"缺陷"（只能访问基类部分）正是下一篇虚函数要解决的最后一环。

## 4. 强转逃生门，与它的代价

第④条用 C 风格强转能骗过编译器：

```cpp
Base b;
Derived* pd = (Derived*)&b;   // 强转，编译通过
pd->show();                   // 访问 Derived 特有成员 → 非法内存访问
```

`pd->show()` 本身可能不崩（若 show 只打印），但只要它碰了派生类特有的成员变量，读到的就是不属于这块内存的数据。第 33 篇讲 `dynamic_cast` 时会给这种下转一个安全的通道（带运行时检查，失败返回空），这里先立个规矩：**下转必须有运行时依据**，裸强转下转是未定义行为的入场券。

## 小结

- 重载三条件齐全才算：**同作用域** + 名字相同 + 参数不同——基类与派生类的函数跨作用域，永远不构成重载
- 隐藏：派生类同名成员把基类同名成员**按名字整锅端**（与签名无关）；名字查找在派生类作用域命中即停；`d.Base::show(10)` 显式指定作用域可绕开
- 三分表：同作用域不同签名 = 重载；跨作用域同名 = 隐藏；跨作用域同名同参的虚函数 = 覆盖（下一篇）
- 上下转换四象限：派生对象→基类对象（切片，合法）；基类指针/引用→指派生对象（合法但只能访问基类部分，静态类型决定能力）；反向两种一律拒绝
- 继承转换默认只支持下到上；上转是多态的标准姿势，"只能访问基类部分"的局限正是虚函数要补的最后一环
- 裸强转下转骗得过编译器骗不过内存：没有运行时依据的下转是未定义行为

`pb->show()` 调了 Base 的版本，可 `pb` 明明指向 Derived——这个"违和感"就是下一篇的全部剧情。给 show 加一个 `virtual`，世界从此不同。
