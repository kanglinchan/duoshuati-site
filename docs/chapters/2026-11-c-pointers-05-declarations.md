# 读懂 C 声明：一套方法拆解任何类型

前面几课我们一直在回避一个问题：C 的声明写法太反人类了。

```c
int *a[10];        /* 这是啥？ */
int (*a)[10];      /* 这又是啥？就差一对括号 */
char (*(*x[3])())[5];  /* 救命 */
```

很多人学 C 卡在指针上，其实卡在**声明根本读不懂**。不知道 `int *a[10]` 是什么，自然不知道该怎么用它。这一课我们就来解决这个根本问题——给你一套**机械的阅读方法**，任何 C 声明都能在五秒内拆解出来。

学会了这一套，指针就只剩"用"的问题，没有"读"的障碍了。

### 1. 病根：C 的声明不能从左往右读

先看 C 声明为什么难读。对比一下：

```c
int a[10];      /* C */
```

```pascal
a : array[0..9] of integer;   /* Pascal：顺着读就行 */
```

Pascal 的读法符合直觉：a 是数组，元素是 integer，一路顺下来。

C 不一样。C 的声明里，类型修饰符（`*`、`[]`、`()`）**围绕在变量名四周**，优先级还不一样。从左往右读 `int *a[10]`，你会以为 `*` 先修饰 int——错了，`[]` 的优先级比 `*` 高，先结合的是 `a[10]`。

这就是为什么读不懂。**不是指针难，是 C 的声明语法反直觉。** 连 C 之父 Dennis Ritchie 自己都承认这个设计广受批评。

好消息是：虽然反直觉，但有**固定的规律**。掌握了规律，再复杂的声明也能机械拆解。

### 2. 核心心法：从变量名出发，向右向左交替读

读 C 声明，记住一个起点、一套顺序：

**起点：先找到变量名（标识符）。** 不管声明多长，先找到那个真正的变量名，从它开始往外扩。

**顺序：从变量名出发，按这个优先级向外读：**

1. **先看右边**：碰到 `[]` 读"是数组"、碰到 `()` 读"是函数"
2. **再看左边**：碰到 `*` 读"是指向…的指针"
3. **括号优先**：括号里的先读，读完再出括号继续"右—左"交替
4. **最后读类型**：`int`、`char` 这些放在最后收尾

用英语想更顺，因为 C 就是按英语语序设计的：`of` 对应数组、`returning` 对应函数、`pointer to` 对应指针。

来，马上实战。读 `int *a[10];`：

```text
a            ← 找到变量名
a[10]        ← 右边有 [10]：a 是数组，10 个元素
*a[10]       ← 左边有 *：数组里装的是指针
int *a[10]   ← 最左边 int：指针指向 int
```

合起来：**a 是一个数组（10 个元素），每个元素是"指向 int 的指针"。**

再读 `int (*a)[10];`——只多了一对括号，但意思全变：

```text
a            ← 变量名
(*a)         ← 括号优先：a 是指针
(*a)[10]     ← 出括号看右边：指向数组
int (*a)[10] ← 数组里装 int
```

合起来：**a 是一个指针，指向"10 个 int 组成的数组"。**

看出括号的威力了吗？`int *a[10]` 是"指针的数组"，`int (*a)[10]` 是"数组的指针"——一对括号，天壤之别。

### 3. 三类声明套公式

C 的声明千变万化，但拆解时只有三种"零件"：

| 零件 | 读作 | 例子 |
|---|---|---|
| `*p` | p 是指向 T 的指针 | `int *p` → p 是指向 int 的指针 |
| `a[N]` | a 是数组，N 个 T | `char a[8]` → a 是 8 个 char 的数组 |
| `f(…)` | f 是函数，返回 T | `int f(int)` → f 是函数，返回 int |

任何复杂声明，都是这三种零件的组合。**`[]` 和 `()` 的优先级高于 `*`**——这就是一切的根源。想改变结合顺序，就加括号。

再来一个，把三种零件都用上：

```c
void (*signal(int sig, void (*func)(int)))(int);
```

别慌，机械拆解：

```text
signal                ← 变量名（其实是函数名）
signal(int sig, …)    ← 右边 ()：signal 是函数，参数是 (int sig, …)
  里面的参数：void (*func)(int)
    func → (*func) 指针 → (int) 函数 → void 返回
    = func 是"指向【接收 int、返回 void 的函数】的指针"
*signal(...)          ← 出括号看左边 *：signal 的返回值是指针
(*signal(...))(int)   ← 右边 ()：指针指向一个接收 int 的函数
void                  ← 返回 void
```

合起来：**signal 是一个函数，参数是 (int, 函数指针)，返回值也是一个"函数指针"——指向接收 int、返回 void 的函数。**

遇到这种声明，工程上的正确做法不是硬读，而是用 `typedef` 拆开（马上讲到）。但**能读懂**是前提。

### 4. typedef：给类型起个短名字

`signal` 那种声明每次写一遍谁都受不了。C 给了个逃生通道：**typedef 可以给类型起别名。**

```c
typedef void (*sighandler_t)(int);   /* 给"函数指针"类型起个名 */
sighandler_t signal(int sig, sighandler_t func);  /* 瞬间清爽 */
```

`typedef` 的读法和普通声明一模一样——把别名当成"变量名"来读声明即可。`typedef void (*sighandler_t)(int)` 读作：sighandler_t 是"指向接收 int、返回 void 的函数"的指针类型。定义好之后，`sighandler_t` 就能像 `int` 一样当类型用了。

工程建议：**凡是类型超过一层嵌套（指针的指针、数组的指针、函数指针），就用 typedef 拆开。** 可读性是程序员之间最基本的善意。

### 5. const：它修饰的是"紧跟在后面的那个东西"

`const` 也经常和指针搅在一起：

```c
const char *p;    /* p 指向的内容不能改 */
char *const p;    /* p 本身不能改（不能指向别处） */
```

怎么记？**读声明时，const 读作"只读的（read-only）"，它修饰紧跟其后的那个部分。**

- `const char *p`：从右往左读——p 是指针，指向 char，char 是只读的。**指向的内容只读**，p 本身可以改指向。
- `char *const p`：p 是**只读的**指针，指向 char。**p 本身只读**（不能再指向别人），指向的内容可以改。

再想深一层：`const char *p` 里，内容只读只是"通过 p 不能改"——如果还有另一个非 const 指针也指向同一个字符串，从那边照样能改。const 锁的是"访问路径"，不是数据本身。

### 6. 函数指针：声明语法的巅峰

把上面的东西合起来，就能读懂 C 声明的"终极 boss"了。函数指针我们在第 3 课已经用过，现在看懂它的声明：

```c
void (*func_p)(double);
```

拆解：func_p → `*func_p` 是指针 → `(*func_p)(double)` 指向一个接收 double 的函数 → `void` 返回 void。**func_p 是"指向【接收 double、返回 void 的函数】的指针"。**

用起来很简单——函数名本身就是地址，赋值、调用一气呵成：

```c
void greet(double x) { printf("hi %.1f\n", x); }

void (*func_p)(double) = greet;   /* 函数名赋给函数指针 */
func_p(1.0);                      /* 通过指针调用，等价于 greet(1.0) */
```

注意 `= greet` 这里没写 `&`，也不用写——和数组一样，**函数名在表达式里自动转成指向自己的指针**。这是 C 里数组与函数设计上的一处对称。

### 小结

- C 声明不能从左往右读，要从**变量名**出发
- 阅读顺序：右（`[]`/`()`）→ 左（`*`）→ 括号优先 → 最后收尾基本类型
- `[]`、`()` 优先级高于 `*`，想改顺序就加括号
- `int *a[10]` 是指针的数组；`int (*a)[10]` 是数组的指针
- 复杂类型用 `typedef` 拆开
- const 修饰紧跟其后的部分：`const char *p` 锁内容，`char *const p` 锁指针
- 函数名本身就是地址，可直接赋给函数指针
